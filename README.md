# HWP Easy

목표는 **에이전트가 한글 설치 없이 HWP를 읽고 편집하며, 클라우드에서도 HWP로 저장하는 것**입니다. 저장소 이름은 `hwp-easy`입니다. 방향과 지원 범위는 [제품 요구사항](docs/PRD.md)을 읽고 검토하며 조정합니다.

새 제품은 부여받은 파일 접근 권한 안에서의 HWP 편집과 기본 미리보기에 집중합니다. HWPX·PDF·DOCX 변환과 내보내기는 제품 범위에 포함하지 않습니다. 아래에 설명한 현재 COM 프로토타입의 내보내기 기능은 새 제품의 개발 계획과 구분합니다.

첫 구현은 `@rhwp/core`의 WASM 엔진을 재사용하는 **한글 없는 HWP 5.x 처리 경로와 로컬 MCP**입니다. 기존 Windows COM 프로토타입은 별도 경로로 보존하며 새 엔진이 실패했을 때 자동으로 실행하지 않습니다. 공개 클라우드 서비스나 일반 사용자용 연결까지 완성된 상태는 아닙니다.

> 현재는 개발·검증 단계입니다. 내려받을 설치 파일, 일반 사용자용 화면, 운영 HWP 편집용 원클릭 Codex 연결과 공개 플러그인은 아직 제공하지 않습니다. 비공개 합성 시험용 플러그인은 별도입니다.

## rhwp와 HWP Easy의 역할

rhwp는 아이디어만 참고한 프로젝트가 아니라 **실제로 사용하는 외부 HWP 엔진**입니다. 현재 `@rhwp/core` 0.8.6을 고정해 사용하며, rhwp의 웹 편집 화면 전체를 가져오는 방식은 아닙니다.

- **rhwp core:** HWP 문서 모델 읽기·텍스트 편집·HWP 바이트 쓰기·SVG 생성.
- **HWP Easy 검증 계층:** 문단·표 셀 대상 지정, 버전·기존 값 확인, 긴 문서 이어 읽기, 편집 후 재열기와 독립 레코드 보존 검사.
- **HWP Easy 연결·저장 계층:** 에이전트용 MCP, 권한 안의 로컬 저장·백업·복구, 개발용 원격 사용자 범위와 D1/R2 버전 저장.

따라서 HWP 엔진을 처음부터 만든 제품은 아닙니다. 기존 엔진 위에서 에이전트가 읽고 수정하고 실패 원인을 확인할 수 있는 작업 흐름을 만드는 프로젝트입니다. 외부 엔진의 고정 버전·라이선스와 아직 검증하지 못한 범위는 [라이선스 고지](THIRD_PARTY_NOTICES.md)에 구분합니다.

## 무엇을 할 수 있나요?

- 본문 문단과 지원하는 표 셀을 구분해 읽고 검색합니다. 긴 문서는 같은 버전을 끝까지 이어 읽을 수 있습니다. 읽기·요약 요청에서는 저장하지 않습니다.
- 문서 버전과 대상 식별자, 기존 값을 확인해 지정 문단·셀의 텍스트를 바꿉니다. 반복 문구 전체를 무조건 치환하지 않습니다.
- 편집 결과를 다시 읽어 검사한 뒤 **현재 HWP에 저장**합니다. 직전 버전은 복구용으로 보관합니다. 다른 이름으로 저장은 요청한 경우에만 사용하며, 별도 기존 파일의 교체에는 기대 버전이 필요합니다.
- HWP에서 직접 생성한 SVG 미리보기를 제공합니다. PDF·DOCX를 중간 파일이나 결과물로 만들지 않습니다. 미리보기는 정확한 배치나 제출 적합성을 인증하지 않습니다.
- 지원하지 않는 내부 레코드와 내용을 알리고, 안전하게 보존할 수 없는 문서의 편집을 거부합니다.

개인정보 없는 합성 바이너리 HWP 20종으로 읽기·저장·재열기와 SVG 생성을, 별도 10개 편집 사례로 본문·셀·균일 스타일 보존을 검사했습니다. 실제 문서 처리와 stdio MCP 흐름을 Windows와 화면 없는 Linux에서 시험했습니다. **임의의 지원서나 복잡한 양식 전체의 호환성·서식 보존을 입증한 결과는 아닙니다.** 자세한 범위와 재현 방법은 [새 엔진 개발자 안내](docs/native-engine.md)에 있습니다.

## 현재 필요한 환경

새 경로는 Node.js 22 이상과 Python 3.11 이상, 고정 버전의 WASM 런타임을 사용하는 개발용 구성입니다. **한글·COM·Wine·GUI는 필요하지 않습니다.** 필요한 구성요소를 간편하게 설치·연결하는 배포 패키지는 아직 없습니다. 설치 명령은 개발자 안내에만 두며 일반 사용자에게 요구할 정상 사용 흐름으로 제시하지 않습니다.

첫 지원 범위는 보안·선택 기능 플래그가 없는 비암호화 HWP 5.x의 본문과 최상위 표입니다. 한 대상 안에 섞인 글자 스타일, 이름 있는 필드, 중첩 표, 머리말·꼬리말과 이미지 편집은 지원 완료를 주장하지 않습니다. 미지원 요소가 있으면 전체 내용 조회 완료로 표시하지 않으며 편집을 제한합니다.

원격 MCP에는 확인된 단일 구역의 쪽 번호 위치 제어(`pgnp`)를 수정하지 않고 보존하는 좁은 예외를 추가했습니다. 제어의 문단은 읽기 전용이며 다른 지원 문단·셀만 편집합니다. 제어와 연결 데이터가 바뀌거나 사라지면 저장을 거부합니다. 이는 쪽 번호 자체의 편집·전체 내용 이해·정확한 배치 인증이 아니며, 로컬 stdio MCP의 미지원 요소 차단은 그대로 유지합니다. [보존 전용 편집 계약](docs/remote-documents.md#쪽-번호-보존-전용-편집)

허용 폴더는 여러 곳으로 구성할 수 있지만, 경로 검사와 시간 제한이 운영체제 샌드박스나 클라우드 사용자 격리를 뜻하지는 않습니다. 지금은 신뢰할 수 있는 테스트 문서만 사용하세요. 조회한 내용이 연결된 AI 앱으로 전달될 수 있으므로 민감한 문서는 해당 앱의 데이터 처리 조건도 확인해야 합니다.

## 만들고 있는 간편 사용 방식

간편 연결은 **Sites 기반 원격 MCP와 플러그인**으로 검증하고 있습니다. 소유자 전용 Sites에서 합성 HWP의 엔진 실행·보존·D1/R2 저장을 확인했고, 설치된 시험용 플러그인을 Codex Desktop에서 실제 호출했습니다. 인증한 사용자별 개발용 문서 도구·전송 경로도 구현했습니다. [실행 시험의 범위와 결과](probes/sites-runtime/README.md)를 참고하세요. 실제 파일 입력·회수, 운영 격리·보관·삭제와 다른 클라이언트 연결은 아직 남아 있습니다. 이 시험용 플러그인은 일반 사용자용 HWP 편집 서비스가 아닙니다.

일반 사용자는 연결을 설치·인증하고 HWP를 선택해 읽기나 수정을 요청하는 흐름을 목표로 합니다. 원격에 업로드한 파일을 저장해도 PC의 원본이 자동으로 갱신되는 것은 아닙니다. PC 파일 직접 저장에는 별도로 승인된 로컬 연결이 필요합니다.

클라우드 지원 목표에는 **새 Codex Cloud 작업에서의 입력·조회·수정·저장·HWP 결과 회수**도 포함합니다. Linux와 Sites의 엔진 실행은 확인했지만 실제 Codex Cloud의 파일 왕복·플러그인 연결은 아직 미검증입니다. Node와 browser ESM은 공통 문서 코드를 사용합니다. 원격 문서 도구와 D1/R2 저장·HWP 전송 경로도 구현했습니다. 사용자의 요청으로 소유자 전용 비공개 배포에서 파일 가져오기를 열고, Codex Desktop의 합성 HWP 업로드·읽기·수정·저장과 재시도를 확인했습니다. 개인 양식·다중 사용자·운영 개인정보 보호 검증이 끝난 공개 서비스는 아닙니다. [파일 전달 계약](docs/remote-documents.md)과 [클라우드 지원 기준](docs/codex-cloud.md)을 참고하세요.

기존 EXE·GUI 중심의 [Windows 배포안](docs/distribution-plan.md)은 이전 COM 방향의 참고 자료입니다. 새 제품에서 이를 우선 구현하지 않습니다. MCP나 개인 스킬을 자동 등록하지 않으며 기존 클라이언트 설정도 변경하지 않습니다.

## 이전 COM 프로토타입

`one-hwp`와 `one-hwp-mcp`는 설치된 Windows 한글과 이미 등록된 파일 접근 보안 모듈을 사용하는 기존 경로입니다. 새 출력 전용 저장 및 선택 내보내기 기능을 그대로 보존합니다. 이는 새 제품의 기본 경로나 지원 범위가 아닙니다. 실행법과 당시 검증 결과는 [이전 프로토타입 개발자 안내](docs/development.md)에 있습니다.
