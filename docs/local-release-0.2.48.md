## 원인과 수정

기존 렌더 보정은 `pageBreak:2`에서 상위 셀의 문단이 하나면 정렬 높이 계산을 건너뛰었다. 접두부와 중첩 표를 사본에서 분리한 뒤에는 원래 가운데/아래 정렬을 직접 복원해야 하지만, 이 경우 남는 높이가 위 여백에 반영되지 않았다.

한 문단 호스트도 검증된 원래 셀 높이·내부 여백·접두부/자식 표 흐름으로 정렬을 계산한다. 높이가 달라진 편집본도 현재 바이트에서 다시 계산한다. 대표 3줄·여유 높이 사례의 중첩 표 원점은 위 정렬 178.5px, 가운데 225.1px, 아래 271.7px이며 실제 한글 경계와 대조했다. 깊이 2/3·빈/한글 접두부·C1 줄바꿈을 함께 검사한다.

사본의 위 여백만 보정하며 원본 셀 정렬·여백·부동 상태·문단/글자 정의와 대상 경로를 보존한다. SVG·내장 BMP·진단은 같은 뷰를 사용한다. `render_nested_tables`의 `ancestor_alignment_shift_hwpunit`는 사본 보정량이며 HWP에 저장하지 않는다. 기존 두 깊이 3 회귀의 잘못 고정된 위쪽 원점 기대값도 실제 정렬과 원본 식별 검사로 수정했다.

## CI 검사 분산

0.2.47의 Windows 복잡 개체 작업은 21분 28초/22분이었다. 처음에는 일반 배치 Node/Python 1쌍을 부동 작업으로 옮겼으나, `be65eb8`의 Windows 실행에서 혼합/다단·독립 판독까지 20분 8초를 사용해 마지막 일반 배치가 22분 상한에 도달했다. 테스트 assertion 실패와 시간 초과를 구분한다. `f17c908`의 더 이른 실행은 글자 서식 보호 보완 때문에 6개 통과 후 중단했다.

최종 배치는 일반 배치 1쌍을 여유 있는 장문 작업으로 옮긴다. 이번 장문 작업 실측은 Windows 12분 45초/18분, Linux 11분 26초/18분이었다. 새 B4 11건은 격리 패키지 작업에 유지한다. 기존 모든 명령·전체 18개 작업·각 작업 예산·제품 5초 한도를 유지하며 제품 소스와 검증 ZIP은 바꾸지 않는다.

설정 커밋 `60326c7`의 [수동 `placement-balance`](https://github.com/spark142857142857/hwp-easy/actions/runs/40439972583)는 옮긴 일반 배치의 **2개 OS 실행**만 선택하며 둘 다 통과했다. 제품 소스·실행기/ZIP은 `be65eb8`과 동일하며 장문/검색의 이전 두 OS 통과와 옮긴 일반 배치 통과를 구분한다. `all`은 장문/검색을 그대로 실행하고, 전체는 **18개**, `render-view`는 장문/일반 배치도 포함한 **8개 OS 실행**이다. 이미 통과한 전체 작업을 반복하지 않는다. 격리 패키지 작업의 Claude Code·Cursor 이름은 실제 앱 설치·인증·모델 호출과 구분한 공통 엔진 QA다.

## 지원 조건과 남은 작업

B4는 기존 정규화 중첩 렌더 범위의 원래 격자·표/셀·단일 크기 가로 문단·접두부 흐름을 증명할 수 있는 경우를 보정한다. 새 네이티브 대조 표본은 한 구역·한 쪽, 깊이 2/3의 위/가운데/아래 정렬과 빈/한글 접두부, 명시 LF·영문 긴 단어/단어 경계·한글 줄바꿈이다. 원래 정렬과 부동 상태를 바꿔 문제를 숨기지 않는다.

- **B4:** 위 지원 범위의 수정·저장/복구·실제 배치 검증 완료.
- **F3-C2:** 원본 글꼴과 공용 빈 문서 글 폭 측정의 연결, 추가 글꼴·혼합 크기·자간·일상 구두점/한영 혼합 문장·추가 조형/복수 문단은 미완료.
- **F3-C3:** 행 내부 쪽 이어짐과 일반적인 쪽 계산 차이는 미완료.
- **F3-B2·D:** 빈 필드 안내·추가 다단/개체 프로필·꼬리말/후속 본문 간격과 추가 진단은 미완료.
- **R1·D1:** 새 Codex 설치/새 채팅은 미실행, Claude Code·Cursor 갱신은 계속 보류.

모든 HWP의 글꼴·조형·기준선·인쇄 배치 일치를 인증한 것으로 처리하지 않는다. `layout_verified:false`, `diagnostics_complete:false`를 유지한다. 추가 외국어/이모지 조형은 계속 D3 최후순위다.
