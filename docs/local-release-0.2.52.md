# 0.2.52 코드 리뷰·자기소개서 양식 검증

[프로젝트 상태](project-status.md) · [남은 작업](remaining-work.md) · [F4 지원 범위](f4-support-0.2.51.md)

검증일: **2026년 10월 27일**. 0.2.51의 필드 식별·내부 글상자·렌더 경로·같은 파일 저장/복구를 검토하고, 합성 자기소개서 양식으로 실제 편집 흐름을 확인했다. 0.2.52는 로컬 검증 후보이며 **설치된 Codex는 0.2.51을 유지**한다. 모든 HWP 구조의 구현 완료나 인쇄 배치 일치를 뜻하지 않는다.

## 자기소개서 시나리오

테스트가 직접 만드는 HWP는 가상 기업의 지원서다. 제목·인적사항 4칸·문항/답변 4개·가로 병합 셀·꼬리말·표 뒤 본문을 포함한다. 동일한 입력 안내가 네 곳에 있어도 각 구조 대상 ID로 선택한다. 실존 인물의 이력이나 개인 문서를 사용하지 않는다.

| 상태 | 편집 내용 | 실제 한글 / 미리보기 |
| --- | --- | --- |
| 빈 양식 | 10행·4열 격자, 병합 후 16셀 | 1쪽 / 1쪽 |
| 작성본 | 가상 인적사항과 답변 437·371·424·375자 입력 | 2쪽 / 2쪽 |
| 장문 | 세 번째 답변을 서로 다른 번호가 있는 80줄로 교체, 표 높이 자동 동기화 | 4쪽 / 4쪽 |
| 재수정 | 원래 답변으로 줄이고 명시적으로 높이 내용 맞춤 | 2쪽 / 2쪽 |
| 작성본 복구 | 중간 백업으로 정확히 복구 | 2쪽 / 2쪽 |
| 원본 복구 | 최초 빈 양식으로 정확히 복구 | 1쪽 / 1쪽 |

계획 단계의 무저장, 같은 파일 저장, 오래된 SHA 거부, 실패한 묶음의 무저장, 변경 없는 요청의 이력 미생성, 중간·최초 원본의 정확한 복구를 확인했다. 독립 OLE 판독으로 글·서식 범위·셀 좌표/병합/너비/여백/테두리와 비대상 스트림을 검사했다. 실제 한글은 읽기 전용으로 열어 **6개 상태 파일·12쪽**, 본문/셀의 모든 글, 장문 **80줄의 실제 쪽 소속**, 복구 화면의 픽셀 일치를 대조했다. 모든 쪽의 꼬리말 영역도 빈 양식과 픽셀이 같았다.

`GetTextFile('TEXT')`는 꼬리말을 본문 텍스트로 반환하지 않으므로, 꼬리말은 원시 바이트·화면·픽셀로 확인했다. 본문 텍스트 추출만으로 꼬리말까지 읽었다고 간주하지 않는다. 최종 BMP도 직접 육안 확인했다.

## 재현과 검증

```powershell
node --test tests/test_local_application_review.mjs
node scripts/check-local-application.mjs outputs/application-source
node scripts/package_local_plugin.mjs
node scripts/check-local-application-package.mjs outputs/application-package
# 아래 두 검사는 개발자용: Windows 한글/pywin32, 이후 Pillow 환경에서 실행한다.
.venv/Scripts/python.exe -X utf8 scripts/check-local-application-native.py outputs/application-source
python scripts/check-local-application-images.py outputs/application-source
```

각 출력 폴더는 새 경로여야 한다. 일반 실행에는 Python이나 한글 설치가 필요하지 않다. 분리 패키지 검사는 임시 폴더의 번들만 실행하며 개발 저장소의 모듈을 실행기에 로드하지 않는다. 양식 생성과 검증 기대값 준비만 테스트 소스를 사용한다.

분리 번들에서 자소서 시나리오와 중복 ID 거부·회전 글 누락 경고/복구를 확인했다. 여섯 상태의 HWP는 소스 실행 결과와 바이트가 같아 위 네이티브 대조가 동일한 패키지 출력에도 적용된다. F4의 기존 24개 시나리오도 번들 저장/복구·모든 SVG/썸네일 일치·독립 OLE 판독을 통과했다.

후보 ZIP은 25개 허용 파일, **5,673,584바이트**다. SHA-256은 `09e7beb07ece7ec9092aac1f377f77098dfa41ca482407f09faa589aaeced81d`, 실행기는 `3807b287d4727e50fd4e312dce491f82d2290b34a4f9ea8101ee8d8edeccbbca`다. 기존 0.2.51 ZIP의 SHA-256과 설치된 25개 파일은 모두 그대로였다. 엔진/WASM 버전도 바꾸지 않았다.

## 배포와 심사

기존 원격 제출본은 10월 27일 수신한 결과에서 **명칭 또는 설명의 제휴·상표 관련 표현을 사유로 반려**됐다. 이메일은 문제의 특정 단어를 지목하지 않았다. `HWP`라는 문자열 자체가 원인이라고 단정하지 않는다. 로컬 0.2.52의 제출·승인 여부와 구분한다.

독립 브랜드 후보를 결정한 뒤 플러그인 표시 이름·slug·명시 호출 예시·아이콘·설치/업데이트 경로·저장소·정책 링크를 함께 정리해야 한다. 이번에는 후보만 검토했으며 저장소와 플러그인 이름을 변경하거나 다시 제출하지 않았다. [공식 가이드라인](https://developers.openai.com/plugins/plugin-guidelines)은 독자적인 목적, 정확한 이름/설명, 지식재산 사용 권한과 제휴 오인 방지를 요구한다. 이름 변경만으로 승인되는 것은 아니다.
