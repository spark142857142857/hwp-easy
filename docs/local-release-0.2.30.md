2026년 10월 18일. **소스·분리 검증 패키지**의 기록이다. Codex 실제 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다.

## 중첩 셀의 기준 위치 보완

0.2.29에서 거부했던 중첩 셀 사각형의 지원 프로필을 추가했다. 같은 셀에서 부동 상태로 재배치하며 글자처럼 취급·크기·앵커 설정·감싸기·내용·서식·셀/표 치수를 바꾸지 않는다. 변경하는 문서 데이터는 선택 개체의 두 오프셋과 매핑한 줄 배치 캐시다.

문제는 오프셋 기준의 차이였다. 현재 엔진의 [셀 도형 배치](https://github.com/edwardkim/rhwp/blob/v0.8.6/src/renderer/layout/table_cell_content.rs#L680)는 셀 내부 원점에 오프셋을 더한다. 검증한 한글 프로필에서는 같은 원시 값이 **단과 본문 호스트 문단**을 기준으로 배치되었다. 중첩 표의 앞선 글 폭·바깥 여백과 셀 안 여백도 함께 대조해야 했다. 참조 필드는 [한컴 HWP 5.0 표 69·70](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)을 확인하고 실제 합성 파일의 원시 값·한글 페이지 이미지·컨트롤 속성으로 대조했다. 이 결과를 임의 HWP 전체의 배치 법칙으로 확장하지 않는다.

공통 Node/WASM 엔진과 원시 저장 경로는 유지한다. 재배치는 다음 정보를 사용한다.

- 유일하게 확인한 조상 표/셀 경로와 저장된 첫 행의 최소 기하
- 표 바깥 여백, 실제 적용하는 셀 안 여백, 한 줄 평문 접두부의 측정 폭과 허용 오차
- 단·본문 문단의 기준점과 대상 셀 글의 높이 추정
- 선택 개체를 메모리에서 제외한 배치, 재배치 후 조상 프레임/경계 대조

이 정보를 바탕으로 보수적인 셀 내부 공간을 찾고 HWP 기준으로 오프셋을 계산한다. 접두부가 빈 경우·한글·영문, 바깥/안쪽 오른쪽 셀, 여백 변경, 깊이 3과 기본 여유 간격의 작은 상자를 실제 한글에서 검사했다.

## 지원 범위와 남은 제한

**깊이 2·3**, 첫 행·위 정렬·병합 없는 조상 셀, 첫 문단의 단순 중첩 인라인 표를 지원한다. 본문 호스트는 빈 일반 정렬 문단·한 단이며, 중첩 표 앞에는 한 줄 평문만 둘 수 있다. 대상 셀에는 평문과 선택 사각형이 있고, 내부 메트릭·회전·배율이 없으며 내용 추정이 상자에 들어가야 한다. 충분한 셀 공간이 없으면 저장하지 않는다.

후속 행/문단·가운데/아래 정렬·병합·추가 표/부동 개체·줄이 나뉜 접두부·필드/컨트롤·모호한 경로와 추가 깊이는 거부한다. 셀·구역 간 이동, 임의 그림/그룹의 셀 배치와 자동 크기 맞춤·쪽 분할은 별도 작업이다.

현재 WASM의 SVG·썸네일·컨트롤 위치는 중첩 원점을 여전히 다르게 표시할 수 있다. 이를 숨기지 않고 `NESTED_FLOATING_RENDER_ORIGIN_DISAGREEMENT`, `engine_checked:false`, `raw_hierarchy_checked:true`, `coordinate_basis:"hwp_column_and_root_paragraph_reference"`를 반환한다. `layout_verified:false`, `native_layout_verified:false`는 유지한다. **문서의 실제 저장 위치 보완과 엔진 표시 좌표의 완전 일치는 별개**이며 후자는 F3에 남긴다.

지원 프로필의 위험 진단도 같은 투영 좌표를 사용한다. 단 기준 오프셋을 셀 내부 폭에 더하던 과도한 넘침 판정을 바로잡고, 셀 내부의 좌/우/위/아래 경계·글 영역 위험을 구분한다. 글꼴·접두부·높이는 추정이므로 `font_estimate`와 불확실성을 표시한다. `reject_new_risk`는 새 위험을 저장 전에 거부한다. 원시 폭 자체가 셀 폭을 넘는 기하 검사는 유지한다. 이전 작은 셀/불확실 프로필의 진단도 회귀 검사했다.
