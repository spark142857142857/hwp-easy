# 첫 양식 지원 범위 검사

이 문서는 합성 사례, 공개 빈 양식과 개인 시험 파일의 검사를 구분한다. 아래에 명시한 개별 저장 성공을 일반 양식 호환성 인증으로 확대하지 않는다. 개인 시험 원본은 읽기 전용으로 유지하고 업로드하지 않는다. 10월 11일 사용자가 요청한 새 로컬 직접 편집의 복사본 시험은 [로컬 편집 검사](local-file-editing.md#사용자-제공-문서의-로컬-복사본-검사)에 별도로 기록하며, 원본의 구조 조회 보고서를 편집·저장 성공으로 집계하지 않는다.

2026년 10월 5일 사용자 결정으로 소유자용 비공개 MVP를 먼저 제공한다. 아래 대표 합성 양식의 실제 연결 검사는 그 제한된 MVP의 근거이며, 개인 양식과 정확한 조판의 지원 인증은 별도다.

## 구조 조회와 편집 후보의 구분

로컬 Python 경로와 원격 배포 엔진의 계약은 다르다. `tests/local_corpus.py`의 읽기 성공만으로 원격 편집을 허용하지 않는다. 원격 엔진의 동일 코드를 로컬에서 실행하는 `probes/sites-runtime/scripts/local-profile.mjs`로 추가 분류한다. 이 검사에서도 원격 연결은 사용하지 않는다.

| 결과 | 해석 |
| --- | --- |
| `complete_profile` | 지원 본문·최상위 표 셀 범위의 끝까지 조회됐고 미지원 요소가 발견되지 않았다. 페이지 배치 검증은 아니다. |
| `partial_profile` | 지원 블록 조회는 끝났지만 미지원 요소가 있다. 페이지 번호를 불투명 바이트로 보존하는 경우에도 전체 의미 조회로 표시하지 않는다. |
| `replacement_candidates` | 현재 대상별 제한을 통과한 기존 비어 있지 않은 문단·셀 문단이다. 실제 변경 내용의 생성·보존 검사는 아직 수행하지 않았다. |
| `empty_fill_candidates` | 검증된 기존 빈 셀 문단의 입력 후보다. 빈 본문 문단 생성이나 새 셀 추가 지원을 뜻하지 않는다. |
| `clear_candidates` | 기존 셀 문단을 비울 수 있는 후보다. `replacement_candidates`와 중복되므로 더해 별도 대상 수로 계산하지 않는다. |
| `read_only_blocks` | 텍스트 레코드, 글자 서식, 제어 문단 또는 문서 전체의 편집 계약 때문에 편집 후보가 아닌 블록이다. |

숨은 글자 서식 참조와 텍스트 레코드 배치 제한은 [대상별 제한](remote-documents.md#조회-단계의-대상별-편집-제한)을 그대로 따른다. 원격 엔진은 확인 가능한 단일 스타일 텍스트와 검증된 혼합 글자 서식의 제한된 치환을 지원한다. 혼합 서식은 한 서식 구간 안에서 글자 수와 각 글자의 UTF-16 길이를 유지하는 경우에 한정하며 기존 서식을 보존한다. 일반 혼합 스타일 편집, 미지원 머리말·중첩 구조를 허용한 것은 아니다. 로컬 Python 경로의 혼합 서식 차단은 유지한다. 후보라도 저장 전 실제 직렬화와 독립 보존 검사를 통과해야 한다.

## 읽기 전용 검사 실행

아래는 개발자용 명령이다. 저장소의 최상위 `testdocs/*.hwp`만 읽고 HWPX와 하위 폴더는 검사하지 않는다.

```powershell
python -B tests/local_corpus.py --report outputs/local-corpus.json
node --max-old-space-size=256 probes/sites-runtime/scripts/local-profile.mjs
```

두 번째 검사는 배포 엔진과 같은 4 MiB 입력 한도를 적용한다. 이어 읽기를 끝까지 진행한 뒤 구조·후보·제한별 수만 기록한다. 편집·무저장 직렬화·렌더링·HWP 내보내기를 호출하지 않으며 검사 전후 원본 해시 일치를 확인한다. 파일명·본문·대상 ID·해시·upstream 오류 문구는 출력하지 않는다. 결과는 Git에서 제외되는 `outputs/hosted-local-profile-<UTC 시각>.json`에 새로 저장한다.

심볼릭 링크·하드링크와 한도 초과 파일은 거부한다. 적대적인 파일시스템 교체에 대한 OS sandbox는 아니며, 실패한 문서의 원본 불변 여부를 확인하지 못했으면 성공으로 집계하지 않는다. 검사할 문서가 없거나 검사가 실패하면 종료 코드 2다. 부분 조회는 실패와 구분해 보고한다.

## 우선 검증 후보와 남은 완료 조건

첫 후보는 머리말·중첩 구조 없이 기존 최상위 표 셀의 단일 스타일 텍스트를 바꾸거나 검증된 빈 셀을 채우는 양식으로 좁힌다. 지원 상품 범위를 확정한 결정은 아니다. 본문 위주의 문서와 페이지 번호가 있는 복잡한 표는 별도 후보로 남긴다.

실제 개인 양식과 분리한 45셀·46셀 문단 합성 사례로 반복 문구 대상 선택, 길이가 다른 답변, 빈 칸 채우기·비우기, 생성 전 검사와 재열기 및 비대상 보존을 확인한다. 별도 합성 페이지 번호 사례는 일부 조회 상태를 유지하면서 번호 보존과 셀 편집을 검사한다. 검사 코드: [local-profile.test.mjs](../probes/sites-runtime/tests/local-profile.test.mjs).

2026년 10월 5일의 대표 합성 원본·셀 수정 결과는 별도 Python/olefile 컨테이너·레코드 보존 검사와 52블록의 내용 비교도 통과했다. 같은 WASM의 재열기와 독립 컨테이너 검사를 구분하며, 독립 HWP 프로그램의 조판 검증으로 집계하지 않는다. 비교용 합성 HWP 두 파일은 로컬 `outputs/`에만 보관하고 개인 문서와 섞지 않는다.

2026년 10월 9일에는 그 고정 합성 원본과 수정본을 한글 2020에서 저장 없이 직접 열고 두 페이지 전체를 비교했다. 둘 다 2쪽을 유지했으며 표의 크기·위치, 변경하지 않은 보이는 문구와 지정한 답변 치환을 확인했다. 열기 후 원본과 수정본 바이트가 고정 생성 절차의 결과와 정확히 일치했다. 실제 브라우저에서 다운로드한 같은 45셀 계열의 저장본도 전체 해시 일치·52블록 재열기와 한글 열기를 확인했다. 이 비교는 해당 합성 사례에 한정하며 실제 개인 양식, 글꼴 전반, 인쇄 결과와 임의 문서의 정확한 조판을 인증하지 않는다.

같은 날 운영 브라우저에서 별도 혼합 서식·병합 셀 합성 HWP를 업로드해 제한된 치환 후보 1곳, 읽기 전용 3곳과 1쪽 기본 미리보기 로딩을 확인했다. 다운로드 바이트는 업로드 원본과 일치했고 엔진 재열기도 통과했다. 이 새 시험 문서는 업로드·화면·회수 검사만 했으며 수정 저장을 추가로 실행하지 않았다. 10월 7일의 실제 혼합 서식 수정/복구 검증과 구분한다.

같은 대표 합성 원본을 실제 Codex 연결로 가져와 6번의 이어 읽기로 52블록 끝까지 조회했다. 반복 문구 중 좌표로 선택한 셀 수정, 기존 빈 셀 채우기와 마지막 셀 비우기의 3개 작업을 한 번에 계획·저장했다. 52블록 비교에서 그 세 곳만 바뀌었고, 회수한 HWP의 전체 해시도 일치했다. 별도 Python/olefile 검사에서 WASM 조회를 사용하지 않고 본문 UTF-16을 직접 해석해 원본·결과의 모든 52문단과 비대상 레코드를 비교했다. 원본 해시·본문으로 새 버전을 복구하고 최초·편집·복구의 3개 버전을 보존했다. 실제 로그인 브라우저에서 편집본의 두 기본 미리보기 페이지도 로드됐다.

## 공개 빈 양식의 실제 연결 검사

2026년 10월 9일 [인제대학교 사회복지학과의 2018년 공개 게시물](https://cms.inje.ac.kr/welfare/community/reference.do?articleNo=9957&mode=view)에 첨부된 `자기소개서 양식.hwp` 한 파일을 별도로 내려받아 검사했다. 실제 빈 양식이며 합성 fixture가 아니다. 개인 시험 파일은 사용하지 않았고, 공개 원본에 개인정보 없는 검증 문구만 넣었다. 공개 첨부 원본과 회수본은 Git에서 제외되는 로컬 `outputs/public-form-check-20261009/`에 보관한다.

| 검사 | 실제 결과와 범위 |
| --- | --- |
| 원본과 전체 읽기 | 16,384바이트, 최상위 표 17개·본문/셀 문단 187개. 두 번의 버전 고정 이어 읽기로 끝까지 조회하고 새 로컬 엔진 조회와 비교했다. 미지원 문서 구조는 발견되지 않았다. |
| 편집 후보 | 기존 비어 있지 않은 셀 60곳과 빈 셀 채우기 102곳, 읽기 전용 25블록. 후보 수는 실제 저장 성공 수가 아니다. |
| 선택·계획·저장 | ‘나의 강점’의 기존 빈 셀 문단 한 곳에 짧은 검증 문구를 넣었다. 실제 연결의 저장 전 직렬화·내용·raw 보존 검사를 통과하고 같은 원격 문서에 저장했다. 나머지 186블록의 내용은 같았다. |
| 회수·정확한 재시도 | 실제 embedded 회수본 14,336바이트가 독립 로컬 재현과 바이트 전체 일치했다. 같은 편집 요청을 그대로 재시도했을 때 같은 버전을 반환하고 추가 버전을 만들지 않았다. |
| 독립 내용·레코드 검사 | 별도 Python/olefile 검사에서 엔진을 호출하지 않고 원본/회수본의 9개 CFB 스트림과 187개 raw UTF-16 문단을 비교했다. 요청한 빈 셀의 텍스트 레코드 삽입과 비대상 보존을 확인했다. 재생성하는 미리보기·줄 조판 정보와 텍스트에 따른 파생 카운트는 이 바이트 보존 판정에서 구분했다. |
| 복구 | 현재 버전 조건으로 원본을 같은 문서의 새 버전으로 복구했다. 복구본은 최초 원본 16,384바이트와 전체 일치했고 전체 읽기도 같았다. 최초·편집·복구의 3개 버전과 복구된 현재 버전을 확인했다. |
| 외부 HWP 프로그램 | 원본과 실제 회수한 편집본을 한글 2020에서 저장 없이 열었다. 둘 다 3쪽이며 선택 칸의 문구와 화면에서 보이는 주변 표 경계·크기·위치를 비교했다. 원본과 회수본의 바이트는 열기 후에도 그대로였다. |

시각 비교는 이 짧은 빈 셀 입력과 화면에서 확인한 영역에 한정한다. 화면 오른쪽 아래 일부는 다른 앱 표시가 가렸으며, 추가 단일 페이지 확대 비교는 창 자동화의 `failed to activate captured window` 오류와 새 창 선택 후 한 번의 재시도 실패로 미완료다. 이 도구 오류를 HWP 열기·저장 실패로 집계하지 않는다. 전체 픽셀 일치, 모든 글꼴·줄바꿈·인쇄 결과, 긴 답변과 다른 양식은 인증하지 않는다. 호출의 `layout_verified=false`도 유지한다. 이번 실제 연결 검사는 Codex Desktop에서 수행했으며 Codex Cloud의 일반 양식 검증으로 확대하지 않는다.

초기 로컬 검사 스크립트는 첫 128블록 응답만으로 완료를 요구해 실패했다. 변경하지 않은 이어 읽기 커서를 끝까지 따라가도록 검사 스크립트를 고쳐 187블록을 확인했다. 제품의 문서 거부나 내용 누락이 아니며 제품 코드는 바꾸지 않았다. 전체 상세와 비교 화면은 로컬 `outputs/public-form-check-20261009/verification-summary.json`에 연결한다.

## 같은 공개 양식의 긴 입력과 거부 검사

같은 공개 원본을 원격에 다시 저장하지 않고 후속 로컬 엔진에서 검사했다. 짧은 문구, 500·1,000·4,096·20,000자 입력, 결합 문자·ZWJ 이모지와 서로 다른 두 셀의 한 번에 수정 등 7개 성공 사례에서 요청 문구 전체와 비대상 내용·서식을 확인했다. 별도 Python/olefile 검사는 엔진을 호출하지 않고 각 결과의 9개 CFB 스트림과 187개 raw UTF-16 문단을 비교했다. 단일 셀 또는 요청한 두 셀 이외의 레코드를 보존했고 공개 원본 바이트도 유지했다.

탭·줄바꿈·잘못된 서로게이트·NUL, 한 대상의 100,001 코드 포인트와 문서 합산 400,000 UTF-16 단위 초과를 포함한 6개 사례는 저장 전 예상한 코드로 거부됐다. 합산 한도 사례는 두 셀을 함께 요청했으며 일부만 편집하지 않았다. 로컬 메모리에서 생성·재열기·원시 보존 검사까지 수행한 결과로, 운영 CPU·메모리나 실제 원격 저장 성공으로 확대하지 않는다.

기본 미리보기 엔진의 페이지 수는 원본 3쪽에서 500·1,000자 입력 때 4쪽, 4,096자 때 5쪽, 20,000자 때 13쪽으로 늘었다. 이 결과를 바탕으로 후속 소스의 계획·저장 응답에 [페이지 수 안내](remote-documents.md#계획저장의-페이지-수-안내)를 추가했다. 기존 입력·재열기 검사에서 얻은 수를 비교하므로 엔진 열기나 렌더링을 추가하지 않는다. 글꼴·줄바꿈·페이지 제한은 계속 미검증이며, 요청 문구를 자동으로 줄이거나 나누지 않는다. 이 후속 기능은 아직 운영 버전 46에 배포하지 않았다.

새 페이지 수 검사 3개, 기존 직접 편집 검사와 실제 로컬 compiled Worker의 계획·저장·정확 재시도 안내 유지가 통과했다. 전체 후속 검사는 Worker Node 460개, 공통 엔진 34개, Python 271개 중 11개 건너뛰기와 compiled Worker 회귀를 통과했다. Python 첫 실행은 현재 체크아웃의 import 경로가 없어 실패했고, 실행 프로세스의 `PYTHONPATH=src`를 지정한 재실행 결과를 집계했다. 긴 입력 결과의 외부 HWP 프로그램 시각 비교와 실제 서버 검증은 미완료다. 상세 측정·독립 비교는 로컬 `outputs/improvement-loop-20261009/`에 보관한다.

## 추가 공개 빈 양식의 운영 버전 47 검사

2026년 10월 9일 위의 공개 빈 양식 두 개를 소유자 전용 운영 버전 47의 실제 Codex Desktop native 연결로 가져왔다. 이전에 보관한 공개 원본의 SHA-256을 확인했고 개인 시험 파일은 접근하거나 전송하지 않았다. 재인증 없이 호출이 성공했으며 인증 자동 갱신의 해결을 뜻하지 않는다.

인천대 양식은 31,744바이트·44블록 전체 읽기 후 **신청사유의 첫 공백 문단과 기타의 빈 셀 문단**에만 개인정보 없는 합성 문구를 한 요청으로 넣었다. 제목·질문·서약·서명 칸은 바꾸지 않았다. 무저장 계획, 같은 문서 저장, 정확한 재시도, 전체 재조회, embedded 회수와 원본 버전 복구가 통과했다. 나머지 42문단과 비대상 서식은 같았고 최초·수정·복구의 세 버전을 유지했다. 기본 엔진의 페이지 수 안내는 원본/결과 각 1쪽이며 최종 조판 인증은 아니다.

실제 회수한 30,720바이트 수정본은 독립 로컬 재현과 바이트 전체가 같았고, 복구본은 31,744바이트 공개 원본과 같았다. 두 회수 파일을 새 엔진으로 열어 44블록 전체 모델을 확인했다. 별도 Python/olefile는 WASM 없이 9개 CFB 스트림·44개 raw UTF-16 문단의 요청한 두 곳과 나머지 42곳, 비대상 레코드·DocInfo 글꼴/서식 정의·원본 복구를 비교했다. 파생 미리보기·줄 배치·일부 DocInfo 통계 값은 바이트 보존 비교에서 구분했다. 실제 로그인 브라우저의 수정/복구 버전 표시, 1쪽 기본 미리보기 이미지 로드, 수정본 다운로드 해시와 문서 이름 변경 뒤 버전 불변도 확인했다.

상명대 양식은 45,568바이트를 원본 해시 그대로 저장한 뒤 지원 블록 31개를 반환했다. 이어 읽기 위치의 종료와 문서 전체 내용의 완료를 구분해 `complete: true`, `content_complete: false`, `all_content_supported: false`를 확인했다. 그림/도형 및 내부 목록의 미지원 표시, 모든 31블록의 읽기 전용과 편집 후보 0을 확인했다. 무저장 계획은 `UNSUPPORTED_EDIT_PROFILE`로 거부됐고 현재 버전·한 버전 이력·해시는 유지됐다. 편집은 실행하지 않았다. 브라우저에서도 편집 후보 0·읽기 전용 31곳과 제한 이유를 확인했다.

이 검증에서 미지원 문서의 부분 조회 안내가 보기 화면에 바로 드러나지 않는 점을 확인했다. 후속 소스는 이미 열린 스냅샷의 한 글자 응답에 포함된 **전체 문서 지원 여부**로 고정 한국어 안내를 에이전트 전달 영역 앞에 표시한다. 한 조각의 `content_complete: false`만으로 경고하지 않으며 새 엔진 열기·전체 본문 회수를 추가하지 않는다. 안내는 미지원 이유의 원문을 표시하지 않고 권한·버전 검사와 다운로드를 유지한다. 이 소스의 운영 반영 결과는 [MVP 상태](mvp-status.md)에 별도로 기록한다.

실행 기록과 공개 입출력, 독립 검사 및 화면은 ignored `outputs/public-native-v47-20261009/`에 둔다. 회수 시 첫 embedded 요청에 chunk 전용 `expected_sha256`을 넣어 인자 오류가 발생했고, 해당 인자를 제외한 명시적 embedded 회수로 보완했다. 저장·인증 오류로 집계하지 않는다. 외부 HWP 프로그램 시각 비교는 현재 제공된 화면 제어 도구가 native 앱을 지원하지 않아 미완료다. 임의 양식·전체 글꼴·인쇄·Codex Cloud의 일반 문서 검증으로 확대하지 않는다.

## 공개 양식의 편집 후보 사전 검사

같은 인제대·인천대 원본에서 일반 단일 서식의 편집 후보 162곳·39곳을 각각 한 번씩 로컬 사전 검사했다. 한글·영문·한자·가나·기호·이모지·결합 문자로 시작하는 고정 합성 문구를 순서대로 사용했다. 인제대 147곳과 인천대 39곳, 합계 **186곳이 메모리 내 생성·재열기·raw 보존 검사에 통과**했고, 인제대의 나머지 **15곳은 `BODY_REPAIR_ALLOCATION_UNSUPPORTED`로 거부**됐다. 모든 공개 원본 바이트는 유지했다.

당시 거부한 15곳만 별도로 같은 입력의 안전한 숫자 진단을 확인했다. 모두 보완 후 압축된 본문 데이터의 할당 단위 수가 감소하는 사례였다. 이후 10월 9일 한 mini-sector 꼬리 반환을 보완해 같은 15곳의 로컬 수정·재열기와 별도 Python 검사를 통과했다. 각 9스트림·187 raw 문단 중 요청한 한 문단만 변경되고 다른 186문단과 비대상 레코드·글꼴/서식 정의는 유지됐다. 인제·인천대의 기존 201개 후보를 같은 문구로 다시 사전 검사한 결과는 162/39 모두 통과했다. 이는 의미에 맞는 입력 칸 201개나 실제 서버 저장 201건이 아니다. 디스크 공간 부족·인증 오류로 바꾸어 설명하지 않으며 [제한된 할당 보완과 남은 거부](remote-documents.md#할당-조건-실패의-에이전트-피드백)를 구분한다. 압축 패딩이나 임의의 글자 추가로 우회하지 않았다. 운영·외부 한글 검사 여부는 최신 MVP 상태를 따른다.

이 201회는 저장하지 않는 로컬 사전 검사다. 실제 원격 저장·운영 CPU·독립 HWP 시각 비교와 각 후보의 별도 Python 비교 성공으로 집계하지 않는다. 후보에는 제목·질문 문구도 포함하므로 실제 양식을 채울 때 고쳐야 할 칸이라는 뜻도 아니다. 대상의 의미는 사용자의 요청과 전체 기존 문구·반환 좌표로 확인해야 한다. 상세 결과는 ignored `outputs/improvement-loop-20261009/public-candidate-sweep.json`과 `public-allocation-diagnostics.json`에 둔다.

실제 개인 파일의 후보 수를 실제 편집 성공 수로 집계하지 않는다. 공개 빈 양식 한 곳의 성공 이후에도 일반 지원 양식의 확정에는 별도로 허용된 실사용 문서 시험과 독립 HWP 프로그램 비교가 더 필요하다. 글꼴, 줄바꿈, 페이지 제한과 정확한 조판은 현재 인증하지 않는다. 소유자용 비공개 MVP와 남은 확장은 [MVP 진행 상태](mvp-status.md)를 따른다.

## 운영 버전 49의 할당 보완과 외부 한글 비교

2026년 10월 9일 제한된 mini-sector 꼬리 반환을 운영 버전 **49**에 반영했다. 일반 sector 감소·할당 종류 전환·여러 본문 chain의 동시 감소는 계속 거부한다. 기존 공개 원본 15곳의 로컬 수정·재열기·독립 Python 비교와 인제대/인천대 201개 후보의 사전 검사를 통과했다. 실제 서버 저장 검사는 이 중 의미가 확인된 **전공 아래 빈 입력 칸 한 곳**만 실행했다. 후보 총수를 서버 저장 수나 실제 입력 칸 수로 확대하지 않는다.

실제 Codex Desktop 연결에서 공개 원본 16,384바이트를 직접 가져오고 187블록을 끝까지 읽었다. 반환한 좌표·대상 ID·빈 기존 값을 사용해 `English synthetic check`를 계획하고 같은 문서에 저장했다. 계획은 mini-sector 반환 1을 보고했으며 버전·revision을 바꾸지 않았다. 실제 저장본은 14,336바이트이고 요청한 한 문단만 바뀌었다. 정확한 재시도는 같은 버전을 반환했다. 나머지 186문단과 모델 서식은 같았고, 실제 회수 바이트는 9스트림·187 raw 문단의 독립 Python 비교를 통과한 로컬 결과와 전체 일치했다. 원본 복구·브라우저 다운로드도 원본과 전체 바이트가 같았고 최초·수정·복구 3개 버전을 유지했다.

운영 환경 revision **8**에는 직전에 관측된 OpenAI 첨부 전달 origin 하나를 검증해 추가했다. 정확한 HTTPS origin·공개 DNS·인증서 검증과 허용/거부 경계를 확인했으며 wildcard·임의 리다이렉트·비공개 주소를 허용하지 않았다. 이후 실제 직접 가져오기가 성공했으나 응답에 전송 호스트가 노출되지 않아 그 호출이 특정 새 호스트를 썼다고 단정하지 않는다. 다른 전달 origin에서 거부되면 기존 브라우저 업로드 대안을 사용한다. 접근 사용자는 계속 소유자 한 계정이다.

설치된 **한글 2020의 100% 배율**에서 공개 원본과 실제 서버 회수본을 읽기 전용으로 비교했다. 아래의 페이지 수는 Hancom 상태 표시줄에서 확인한 값이다. 문서는 저장하지 않았으며 비교 후 네 원본이 각각 기록된 실제 복구본과 바이트 전체가 같았다.

자기소개서의 간격 차이를 원시 바이트로 추가 조사했다. 원본/실제 회수본의 두 셀 헤더가 전체 같았고 공통 LIST_HEADER 속성은 각각 `0x00200000`였다. [엔진 작성자의 형식 조사](https://github.com/edwardkim/rhwp/blob/main/mydocs/tech/hwp_spec_errata.md#3-list_header-속성-비트-위치)에 따르면 이는 세로 가운데 정렬이다. 빨간 안내 문구·제목·바깥 문단의 원시 줄 배치도 같았다. 바뀐 답변의 줄 수와 뒤쪽 문단의 위치는 분량에 따라 증가했다. **가운데 정렬된 내용이 길어지며 재배치되는 동작과 부합한다는 추론**이며, 정렬 손실·확정된 엔진 결함으로 분류하지 않는다. 원래 시각 간격을 고정하기 위해 셀 정렬이나 원본 line geometry를 임의로 덮어쓰지 않았다. raw 검사의 일반 line geometry 제외와 모든 글꼴·인쇄·임의 양식의 픽셀 일치 미검증 경계는 유지한다.

실제 로그인 브라우저의 이전/현재 표시·3개 이력, 선택한 이전 버전을 고정하는 읽기 전용 직접 복사 요청, 수정/복구본 보호된 다운로드·해시와 문서 이름 검색도 확인했다. 이름 변경과 조회 뒤 현재 버전·revision·이력은 같았다. 이번 브라우저 세션의 가상 클립보드가 빈 값을 반환한 것은 OS 복사 실패의 증거로 집계하지 않는다. 실제 OS 복사·Hancom 붙여넣기는 앞선 버전 46의 별도 기록으로 유지한다.

상세 ID·요청 시간·숫자 Worker 로그·입출력 해시·독립 비교·화면은 ignored `outputs/mvp-finish-20261009/`와 `docs/local/2026-10-09/mvp-finish.json`에 보관한다. 개인 파일·토큰·쿠키·인증 코드·메일 전송은 포함하지 않았다. 인증 자동 갱신과 새 Codex Cloud 클라이언트 검증은 이번 범위에서 제외했다.
