# 로컬 HWP Easy 0.2.25 검증 기록

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [개선·남은 작업](remaining-work.md) · [0.2.24 기록](local-release-0.2.24.md)

2026년 10월 15일, 설치된 **0.2.24**로 공개 12개 양식을 다시 검사하고 발견한 문제를 **0.2.25 소스·검증 패키지**로 보완했다. 이어 Codex 설치본을 **0.2.25**로 갱신하고 새 채팅에서 실제 편집·같은 파일 저장·별도 복구를 확인했다. Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다. 공개 게시·포털 작업은 수행하지 않았다.

## 공개 12개

출처는 [rhwp 고정 커밋](https://github.com/edwardkim/rhwp/tree/1a76570e833917d15817415a53c09ad61ab3203f)의 공개 표본이다. 0.2.20부터 사용한 카탈로그의 URL·크기·SHA-256을 대조했다. 원본은 읽기만 하고 복사본에서 누름틀 또는 두 칸의 답변·글자/문단 서식·그림을 묶어 편집했다.

**0.2.24 기준 검사:** 12개 모두 같은 파일 저장·정확한 복구·마지막 실패의 원자적 거부·독립 OLE 판독을 통과했다. 한컴 2020 자동화 API로 원본·편집본·복구본 36개 파일·155쪽을 열고 모든 쪽을 이미지로 만들었다. 복구한 50쪽은 원본과 픽셀이 같았다. 요청한 합성 문구도 모두 확인했다.

이 결과만으로 배치 성공을 선언하지 않았다. 지도 그룹이 답변을 덮는 사례와 중첩 표 안의 장문이 쪽 아래로 잘리는 두 사례를 실제 이미지에서 확인했다. 원래부터 배치가 불안정한 표본의 기존 겹침도 남아 있다.

| 표본 | 최종 복합 검사 쪽 수 | 확인 사항 |
| --- | --- | --- |
| 01·02 누름틀 표지 | 각각 3→3 | 두 필드·서식·그림, 원래 장식 보존 |
| 03·04·06 도형 양식 | 각각 1→1 | 텍스트·서식·그림과 도형 보존 |
| 05 벡터 지도 그룹 | 1→1 | 복합 편집 후 겹침을 재현하고 별도 위치 이동으로 해소 |
| 07 중첩 셀 페이지 | 17→19 | 긴 답변의 네이티브 쪽 이동과 전체 복구 |
| 08 좁은 중첩 표 | 1→2 | 짧은 합성 답변의 실제 배치 확인. 장문은 별도 엄격 정책에서 저장 거부 |
| 09 중첩 표·캡션 | 12→12 | 답변·서식·그림과 원래 표/그림 보존 |
| 10 중첩 표 흐름 | 1→1 | 짧은 합성 답변의 실제 배치 확인. 장문은 별도 엄격 정책에서 저장 거부 |
| 11 누름틀 셀 | 1→1 | 두 필드·서식·그림, 셀 식별 유지 |
| 12 혼합 중첩 셀 | 8→9 | 답변과 후속 내용의 쪽 이동, 원래 콘텐츠 보존 |

0.2.25의 최종 12개 복합 검사는 08·10에 **명시적으로 짧은 시험 답변**을 사용했다. 제품이 장문을 자동으로 줄인 결과가 아니다. 같은 장문 요청을 `reject_new_risk`로 실행하면 `NEW_LAYOUT_RISK`로 거부하며 파일과 백업 수가 변하지 않는다. 중첩 표 장문의 자동 쪽 분할은 해결한 것으로 처리하지 않는다.

한컴은 시험 환경에만 설치되어 있으며 제품 실행 조건이 아니다. 위 최종 네이티브 검사의 합계는 **90개 파일·237쪽**, 복구 픽셀 비교는 **76쪽**이다. 같은 파일의 반복 검사를 별도 문서 종류로 세지 않는다. 이 확인은 해당 시험 문서·요청·폰트 환경에 한정된다.

첫 기능 커밋 `a89199e`의 [CI 실행](https://github.com/spark142857142857/hwp-easy/actions/runs/38712795918)은 9개 작업이 성공했다. Windows 기본 작업도 Node 검사·Python 291개 검사·호출 정책·패키지 빌드 단계는 성공했지만 마지막 정리에서 18분 제한에 걸려 작업 전체가 취소됐다. `0bb3620`은 기본/복잡한 개체 작업에서 중복 실행하던 Node 검사 10개를 각 플랫폼의 복잡한 개체 작업으로 모았다. 두 작업의 검사 파일 합집합과 18분 작업 제한·개별 실행 제한은 같다. 최종 `0bb3620`의 [재실행](https://github.com/spark142857142857/hwp-easy/actions/runs/38715305302)은 **Windows·Linux 10개 작업 모두 성공**했고 마지막 정리까지 정상 종료했다. 실제 설치와 공개 상태는 [프로젝트 상태](project-status.md)에서 구분한다.

## Codex 설치와 새 채팅 검증

검증한 ZIP을 새 영구 마켓플레이스 경로에 준비한 뒤 정식 `codex plugin marketplace`·`plugin add` 명령으로 설치했다. 실제 캐시는 `~/.codex/plugins/cache/hwp-easy/hwp-easy/0.2.25`다. 기존 0.2.24 설치 사본과 ZIP을 보관했다.

| 검사 | 결과 |
| --- | --- |
| 설치·자원 | 0.2.25 설치·활성 확인. 설치된 25개 파일과 검증 ZIP 전체 바이트 일치. 실행기·WASM 해시 일치 |
| 스킬 발견 | 새 app-server 호스트에서 활성 스킬 1개·발견 오류 0개. `allow_implicit_invocation:false` 유지 |
| 설치 실행기 | 본문·셀 두 문단 저장, 오래된 버전 저장 거부, 무변경 무저장, 이력·SVG, 원본 복구·편집본 복구·다시 원본 복구 통과. 별도 Python 독립 판독 통과 |

| 네이티브 확인 | 새 채팅의 원본·편집본·복구본 9개 파일·9쪽 열기·이미지·요청 문구 확인. 복구 3쪽은 원본 픽셀과 동일 |
| 설치 보존 | Claude Code·Cursor 0.2.19의 각각 23개 파일·전체 트리 해시가 갱신 전후 동일. 공개 ZIP·디렉터리 게시 상태는 갱신하지 않음 |
| computer-use | 0회. 파일 처리는 설치 runner, 네이티브 검사는 한컴 자동화 API·저장한 이미지 사용 |

설치 발견·명시적 파일 읽기·실제 모델 실행을 확인한 결과다. 이번 검사에 메뉴 클릭이나 선택 참조의 자동 주입 검증은 포함하지 않는다. 해당 합성 문서의 네이티브 확인을 임의 문서의 인쇄 배치 인증으로 확대하지 않는다.

합성 벡터 그룹은 용지 왼쪽 위의 기존 위치에서 본문 아래로 이동했다. 중첩 셀 글상자는 원래 용지 왼쪽에 놓인 위치·크기를 유지하며 문구만 바뀌었다. 후자를 셀 안쪽 자동 재배치나 크기 자동 조정의 성공으로 해석하지 않는다.

요청·실제 응답·원본/편집/복구 사본·독립 판독·이미지는 ignored `outputs/codex-0.2.25-20261015/`에 보관했다. 앞의 공개 양식 90개 파일·237쪽 집계와 이번 새 채팅 집계는 별도다.

## 남은 제한

중첩 표 장문의 자동 분할, 다단/셀 부동 개체의 자동 위치 탐색, 필드·그림이 든 복잡한 꼬리말, 그룹 내부 글상자·개별 하위 그룹 편집, 네이티브와 동일한 쪽 계산은 후속 작업이다. 저장·복구 검증과 쪽 배치 인증을 구분한다. 다음 설치·공개 순서는 [남은 작업](remaining-work.md)에서 관리한다.
