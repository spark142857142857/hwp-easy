# HWP Easy 스킬 발견과 명시적 호출

[문서 인덱스](README.md) · [사용 가이드](quick-start.md) · [프로젝트 상태](project-status.md)

Codex에서 **HWP Easy가 보이지 않거나 호출이 전달되지 않을 때** 읽는 진단 안내입니다. 현재 Codex 설치본은 0.2.25입니다. 새 호스트의 스킬 발견과 설치된 스킬을 명시적으로 읽은 새 로컬 채팅의 실제 편집·같은 파일 저장·별도 복구를 확인했습니다. [현재 검증 기록](local-release-0.2.25.md)을 참조하세요. 이번 검사는 메뉴 클릭·선택 참조의 자동 주입 검사가 아닙니다. 아래 0.2.17 진단과 0.2.19의 정식 스킬 선택 참조 검증은 이전 기록으로 구분합니다.

2026년 10월 12일, 기본 목록 숨김의 이유를 확인하고 스킬 본문이 잘리는 결함을 수정해 메인 **0.2.17**을 실제 설치했다. `allow_implicit_invocation:false`인 스킬은 기본 모델 목록에서 숨겨지며, 선택용 발견 목록에는 남는다. 기본 목록에 없다는 이유로 설치 실패로 판단하지 않는다. 사용자가 명시적으로 호출할 때만 적용하는 정책은 유지한다.

0.2.16의 본문 13,062바이트는 플러그인 스킬 제한인 8,000바이트에서 잘렸다. 0.2.17은 핵심 지침을 6,282바이트로 줄이고 이전 상세 지침 전체를 참조 파일에 보존했다. 실제 선택 참조로 전달된 6,282바이트가 설치 파일과 정확히 같았고 복구 안내도 끝까지 포함됐다. 패키지·ZIP·설치 준비에서 제한 초과와 참조 누락을 검사해 재발을 막는다.

## 사용자가 선택하는 경로

새 채팅의 스킬 선택 메뉴에서 **HWP Easy**를 검색해 선택하고 파일과 수정 내용을 지정한다. Codex CLI에서는 `$`를 입력한 뒤 `HWP`를 검색하거나 `/skills`에서 선택한다. 설치된 스킬의 정식 이름은 `hwp-easy:edit-local-hwp`다. 도구로 채팅을 생성하는 요청에 이름만 적어 넣는 방식은 실제 메뉴 선택을 검증하지 않는다.

메뉴에도 나타나지 않을 때는 `codex plugin list --marketplace hwp-easy --json`에서 설치·활성 상태를 먼저 확인한다. 설치가 활성인데 메뉴가 갱신되지 않는 경우, 진행 중인 작업을 마친 뒤 앱을 다시 열어 확인한다. [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)는 명시적 호출 정책과 변경 후 재시작 안내를 설명한다. 이번 진단에서 앱을 재시작하거나 전역 설정을 바꾸지는 않았다.

## 이전 진단에서 확인한 범위

| 경로 | 결과 |
| --- | --- |
| 설치 목록 | `hwp-easy@hwp-easy`, `localVersion:0.2.17`, 설치·활성 모두 참. |
| 정식 `skills/list` | `hwp-easy:edit-local-hwp`가 활성 설치 경로로 발견됨. 발견 오류 없음. |
| 기본 모델 목록 | 항목 없음. 자동 호출 금지에 따른 정상 동작. |
| 정식 CLI 선택 메뉴 | **HWP Easy**가 표시되고 한국어 설명이 영어 앞에 위치함. |
| 선택 후 본문 전달 | 실제 대화 기록의 별도 `<skill>` 메시지에서 0.2.16은 8,000바이트 잘림, 수정한 0.2.17은 6,282바이트 전체 일치를 확인함. 정식 설치 발견 경로를 사용함. |
| CLI의 모델 실행 | 계정의 모델 지원 오류로 요청이 거부됨. 스킬 주입 확인과 모델 실행 성공을 구분함. |
| 앱 도구로 생성한 새 채팅 | 호출 문자열은 받았지만 본문·정식 스킬 참조는 받지 못함. 그 경로의 전달 문제는 남으며 수동 메뉴 선택의 실패를 뜻하지 않음. |
| 데스크톱 메뉴 | 사용자가 제공한 두 화면에서 검색 결과 표시와 입력창의 선택된 HWP Easy 항목을 확인함. 실제 전송·문서 실행은 아직 별도임. |

이전 파일 처리 검증은 정식 발견 결과의 설치 스킬을 명시적으로 읽어 적용했고 같은 파일 저장·재읽기·정확한 원본 복구를 통과했다. 이 검증을 메뉴 선택 성공으로 바꾸지 않는다. 이전 실패 보고서도 보존하며, 잘못된 기본 목록 실패 판정은 이 후속 설명으로 정정한다.

## 원인과 검사 기준

공식 Codex 소스의 [호스트 스킬 등록](https://github.com/openai/codex/blob/ddb33e34b278ca1b7d16d1e68f8ad363a2042f2e/codex-rs/ext/skills/src/provider/host.rs#L147)은 자동 호출을 허용하지 않는 스킬을 기본 프롬프트에서 숨긴다. [명시적 선택 처리](https://github.com/openai/codex/blob/ddb33e34b278ca1b7d16d1e68f8ad363a2042f2e/codex-rs/ext/skills/src/selection.rs#L21)는 활성 스킬의 선택 참조와 이름을 처리한다. [플러그인 본문 제한](https://github.com/openai/codex/blob/ddb33e34b278ca1b7d16d1e68f8ad363a2042f2e/codex-rs/ext/skills/src/render.rs#L21)은 UTF-8 8,000바이트다. 이 소스는 공개된 고정 커밋의 설명 근거이며, 데스크톱 실행 파일 전체의 버전 일치를 증명하지는 않는다.

새 채팅 검사는 설치 발견, 선택 메뉴 표시, 명시적 본문 전달, 실제 문서 실행을 별도로 기록해야 한다. 자동 호출 금지 스킬의 기본 목록 표시를 성공 조건으로 삼지 않는다. CLI 메뉴 선택으로 전달된 본문은 실제 대화 기록에서 확인했고, 앱 도구의 단순 문자열 전달 결과는 별도 보고서로 남겼다.

진단 자료와 대화 기록의 필요한 항목만 추린 결과는 ignored `outputs/skill-discovery-diagnosis-20261012/`에 보관한다. 스킬·참조·패키지 검사와 메인 설치를 0.2.17로 갱신했다. 실행기·WASM·원격 보관본은 동일하며 자동 호출 금지 정책을 유지했다. 설치된 실행기의 파일 처리·독립 판독도 다시 통과했다.
