## B1 종료 후 남은 잠금이 편집·복구를 계속 차단

**P2 · 미해결** — [저장 잠금 획득](../src/one_hwp/local_file.mjs#L115), [잠금 정리](../src/one_hwp/local_file.mjs#L136)

정상 저장은 `finally`에서 잠금을 지우지만 프로세스가 종료되면 실행되지 않는다. 기존 잠금은 항상 `DOCUMENT_BUSY`로 처리하며 내용에는 작업 소유자나 종료 여부를 판별할 정보가 없다. 이후 `restore`도 같은 저장 경로를 쓰므로 원본 백업이 있어도 복구가 막힌다.

재현은 정상 합성 HWP를 한 번 저장한 뒤, 별도 프로세스에서 `saveLocal`을 호출하고 게시 직전 `renameSync` 지점에 `process.exit(91)`을 주입했다. 실제 프로세스가 종료된 후 **수정하지 않은 설치 runner**로 재검사했다.

| 확인 | 실제 결과 |
| --- | --- |
| 다음 편집 | `DOCUMENT_BUSY`, 저장 안 됨 |
| 확인된 원본 백업으로 복구 | `DOCUMENT_BUSY`, 복구 안 됨 |
| 현재 파일 | 종료 전 바이트 유지 |
| 이력 조회 | 기존 백업을 읽을 수 있음 |

원본 손상 사례로 기록하지 않는다. 문제는 종료된 작업의 잠금으로 같은 파일의 후속 작업이 계속 막히는 것이다. 실행 중인 저장을 침범하지 않으면서 종료된 잠금을 판별·해소하는 절차와 회귀 검사가 필요하다. 무조건 잠금을 삭제하는 방법을 사용자 안내로 삼지 않는다.

## B2 같은 문단의 그림 사이에서 새 넘침을 놓침

**P2 · 미해결** — [새 위험 비교 키](../src/one_hwp/local_layout.mjs#L52), [엄격 정책 적용](../src/one_hwp/local_runner.mjs#L160)

`newLayoutIssues`는 문단 ID·종류·구역·크기·가용 폭으로 기존 위험을 상쇄한다. 결과에 있는 `picture_index` 등 개체 식별은 비교 키에 없다. 같은 문단에서 한 그림의 넘침을 없애고 다른 그림에 같은 크기의 넘침을 만들면 이전 위험으로 취급한다.

실제 설치 runner에서 중첩 표 바깥 셀의 같은 문단에 그림 두 개를 넣고, 하나의 묶음으로 폭을 서로 바꾸어 확인했다.

| 상태 | 그림 0 폭 | 그림 1 폭 | 셀 가용 폭 | 위험의 대상 |
| --- | --- | --- | --- | --- |
| 편집 전 | 30,000 | 1,800 | 19,957 | 그림 0 |
| 편집 후 | 1,800 | 30,000 | 19,957 | 그림 1 |

`layout_policy:"reject_new_overflow"`인데도 **`saved:true`, `new_issues:[]`**로 같은 파일에 저장됐다. 그림 1의 새 위험은 전체 `issues`에는 남는다. 그 후 원본을 바이트 단위로 정확히 복구했다.

문단뿐 아니라 구조 변경을 따라가는 개체 식별로 위험을 비교해야 한다. 단순히 현재 그림 번호만 추가하면 삽입·삭제로 번호가 바뀌는 경우를 놓칠 수 있으므로 두 그림 교환, 번호 변경, 문단 이동을 함께 검증해야 한다.

## I1 쪽 하단 고정 글상자의 장문 넘침 경고

**개선 필요 · 미완료** — [현재 배치 검사 진입](../src/one_hwp/local_runner.mjs#L29), [글상자 부분 편집](../src/one_hwp/local_text_boxes.mjs#L46)

표가 없는 문서는 현재 셀 중심의 배치 검사에서 검사 대상이 비어 있다. 글상자의 텍스트 보존·고정 도형 보존과 실제 페이지에서 모든 글자가 보이는지는 별개다. 엄격 정책도 아직 이 범위를 검사하지 않는다.

쪽 하단에 고정한 사각형 글상자(폭 18,000, 저장 높이 4,000, 세로 위치 69,000)에 합성 답변 20줄을 넣었다. `reject_new_risk`에서도 저장됐고 `issues`·`new_issues`가 비어 있었다. 저장 후 읽기에서 20줄과 원래 도형 속성을 확인했다. 한컴 2020은 한 쪽으로 렌더링했으며 **아래쪽 줄은 쪽 밖으로 나가 이미지에 보이지 않았다.** 원본 복구는 전체 바이트·페이지 픽셀이 같았다.

본문 위쪽의 별도 20줄 글상자는 네이티브에서 늘어나 모든 줄이 보였다. 따라서 글상자 장문이 항상 잘린다고 일반화하지 않는다. 이번 재현은 **쪽 하단 고정 프로필**이다. 자동 크기 변경을 이미 지원한다는 주장 없이, 고정 글상자 텍스트의 추정 높이·쪽 경계를 경고하거나 엄격 정책에서 거부하는 개선이 필요하다.

## 검토·테스트 범위

코드는 로컬 파일 발행·이력·복구, 요청 실행과 묶음 대상 추적, 새 위험 비교, 부동 배치와 글상자 편집을 검토했다. 프로젝트 전체의 보안 감사나 임의 HWP의 시각적 호환성 인증은 아니다.

| 검사 | 결과·범위 |
| --- | --- |
| Node/WASM | `test_rhwp_bridge.mjs`와 `test_local_*.mjs` 483개 통과, 실패·취소 없음 |
| Python 현재 소스 | 291개 실행, 4개 건너뜀. Windows에서 심볼릭 링크 권한이 없는 3개와 POSIX 권한 전용 1개 |
| 설치된 0.2.25 | 본문·실제 두 문단 셀 편집, 계획 무저장, 버전 충돌·무변경 검사, 이력·미리보기, 원본·편집본 왕복 복구와 독립 OLE 판독 |
| 자체 포함 분리 패키지 | 부동 그룹·그림·벡터 그룹·글상자, 하단 보호, 셀·중첩 셀 글상자 등 15건. 계획/저장 해시·같은 파일 저장·정확한 복구·독립 레코드 판독 |
| 기존 GitHub CI | 10월 18일 조회한 `e593a0c`의 [10개 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38718871929) 모두 성공. 이번 로컬 검사와 구분 |
| 설치·공개 상태 | Codex 0.2.25, Claude Code·Cursor 설치 manifest 0.2.19. GitHub 공개 사전 릴리스 0.2.19 재확인. 포털은 조회하지 않음 |

실행 환경은 Windows, Node 22.17.0, Python 3.13.2다. Python의 첫 실행은 가상환경 `site-packages`의 오래된 `one_hwp`를 불러 80개 실패·12개 오류가 보고됐다. `one_hwp.__file__`을 확인하고 **프로세스에만 `PYTHONPATH=src`를 지정한 현재 소스 재실행**은 통과했다. 이 환경 불일치를 현재 소스의 미해결 오류로 세지 않는다. 전역 설정·설치본을 바꿔 통과시킨 결과가 아니다.

기본 검사는 다음과 같이 재현할 수 있다. 새 보고 경로를 사용하고, 네이티브 확인은 한컴이 있는 개발 환경에서만 별도로 수행한다.

```powershell
$cases = Get-ChildItem tests/test_local_*.mjs | Sort-Object Name | ForEach-Object FullName
node --test --test-concurrency=2 tests/test_rhwp_bridge.mjs @cases
$env:PYTHONPATH = Join-Path (Get-Location).Path 'src'
$env:HWP_EASY_NATIVE_TESTS = '1'
$env:HWP_EASY_RUNTIME_DIR = (Get-Location).Path
.venv/Scripts/python.exe -B -m unittest discover -s tests -p 'test_*.py' -v
```

실제 설치 runner의 SHA-256은 `3477d0e2141dc9f0fb99760dc81713cd2ffdbf5a98d57dd4802fc494b554cd2f`이며 분리 패키지의 실행기도 같았다. 요청·응답·합성 HWP·종료 주입 스크립트·네이티브 이미지는 ignored `outputs/review-20261018/`에 보관한다. 실제 오류를 남기는 재현은 위 조건으로 분리한 합성 폴더에서만 실행했다.

개인 문서·설치·공개 패키지를 편집하지 않았다. Claude Code·Cursor 갱신, 새 채팅 생성, 포털 제출, Linux 실행은 이번 검사에 포함하지 않았다. **computer-use 0회**이며 선택적 네이티브 검사는 COM API와 로컬 이미지 판독으로 수행했다.
