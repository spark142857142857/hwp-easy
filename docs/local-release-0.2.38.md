# 로컬 HWP Easy 0.2.38 검증 기록

[남은 F2](remaining-work.md#f2-세부-현황) · [지원 기능](supported-features.md#소스-0238-추가-기능) · [프로젝트 상태](project-status.md)

검증일: **2026년 10월 22일**. F2-B4의 좁은 셀·혼합 글자 크기·지원 결합 문자를 추가했다. 소스·검증 패키지는 0.2.38이며 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19다.

## 구현과 지원 경계

셀 폭이 글자 크기의 두 배 미만이면 일괄 거부하던 제한을 없애고, **완전한 글자 묶음 하나가 셀에 들어가는지** 검사한다. 전체 서식 문자열에서 얻은 자연 폭을 사용하고, 단어가 들어가면 유지하되 긴 단어는 글자 묶음 사이에서만 줄을 나눈다. 분해형 한글·결합 악센트를 코드 포인트별로 쪼개거나 원래 문자열을 정규화하지 않는다. 문서의 UTF-16·글자/문단 서식·표 너비/여백/테두리는 보존한다.

혼합 글자 크기는 줄별 최대 크기와 인접 줄의 큰 크기로 간격을 예약한다. 문단 전체를 한 크기로 바꾸거나 글꼴을 줄이지 않는다. `reflow_table`과 재열기 후 자동 동기화가 같은 계산을 사용한다. 기존 행 높이는 최소값이며 줄인 글의 빈 공간 회수는 F2-D 추가 범위다.

검증 프로필은 깊이 2·3의 좁은 셀, 한 문단의 8/10/18pt 혼합, 분해형 한글·결합 라틴 악센트·가로 CJK/그리스/키릴 문자다. 다른 글꼴/크기/굵기 등 지표가 한 글자 묶음 안에서 바뀌거나, 묶음 하나가 셀 폭보다 크면 저장 전에 거부한다. 아랍어·인도계·태국어 조형, ZWJ/복수 문자 이모지와 지원 밖의 결합 표지는 `TABLE_REFLOW_SHAPING_UNVERIFIED`로 거부한다. 기존 단일 기호의 보통 폭 프로필과 구분한다.

새 문자의 QA는 **색을 바꾸지 않은 원래 페이지**를 사용한다. 조사 중 한글에서 색/서식만 바꾸어도 좁은 셀의 줄바꿈이 달라지는 현상을 확인했다. 따라서 검사용 색 표시를 원래 배치의 증거로 사용하지 않는다. 이 표시 차이와 글꼴 대체·다른 reader의 동일한 줄/쪽 계산은 F3에 남긴다. 문자열 검색 성공이나 쪽 수 증가만으로 표시 완료를 판정하지 않는다.

최종 증거는 무시된 `outputs/f2-038-20261022/final-metrics/`, `final-text/`의 `cases.json`, `summary.json`, `independent-summary.json`, `native/results.json`, `native/summary.json`, `native-input-match.json` 및 `final-table-tests.log`, `final-complex-tests.log`다. 실행기 보수 검사 추가 후 최종 파일 69개의 바이트가 실제 네이티브 입력과 같은지 전부 대조한다. 조사·색 표시·중간 결과는 수치에 중복 합산하지 않는다. 개인 문서는 사용하지 않았다.

이번 증분 단계는 수동 `scope:table-metrics`의 Windows/Linux 관련 **2개 작업**으로 확인한다. 기본 전체 구성은 새 문자 지표 작업을 분리한 **18개 작업**이며 이번 부분 실행과 구분한다. 커밋·실제 실행 결과는 [Source checks](https://github.com/spark142857142857/hwp-easy/actions/workflows/checks.yml)와 로컬 `outputs/f2-038-20261022/ci-result.json`에 연결한다. 전체 18개 CI는 이번에 실행하지 않는다.
