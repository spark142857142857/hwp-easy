# 로컬 HWP Easy 0.2.36 검증 기록

[남은 F2](remaining-work.md#f2-세부-현황) · [지원 기능](supported-features.md#소스-0236-추가-기능) · [프로젝트 상태](project-status.md)

검증일: **2026년 10월 22일**. F2-B2의 정렬 셀과 복수 중첩 표 호스트를 추가했다. 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다.

## 구현 범위

- **정렬 셀:** 가로 셀의 위/가운데/아래 정렬을 그대로 보존하면서 표·셀·조상 행의 최소 높이를 늘린다. 예약된 정렬 값, 세로 글과 지원 밖의 줄바꿈 설정은 저장 전에 거부한다.
- **복수 표 호스트:** 같은 셀 문단의 여러 중첩 표를 원래 앵커 순서대로 접두 글 아래 세로 배치한다. 명시적 `reflow_table`의 배치 변경으로, 기존 같은 줄 인라인 표도 세로 배치가 된다. 결과의 `nested_host_layout:"anchor_order_vertical_stack_below_prefix"`로 보고한다.
- **후속 동기화:** 모든 형제 표 높이를 먼저 계산한 뒤 앞선 표 높이·위아래 바깥 여백을 합쳐 각 표 위치를 결정한다. 역순 높이 계산 도중 아직 계산하지 않은 형제 높이를 읽지 않는다. 파일을 다시 열어 앞쪽 표를 늘려도 뒤쪽 표 위치와 조상 높이를 최종 저장 전에 함께 동기화한다.
- **보존:** 글/글자 서식·정렬 플래그·원시 앵커/컨트롤 순서·병합·열 너비·안팎 여백·테두리·인스턴스 ID·다른 스트림을 보존한다. 흐름·높이·위치와 파생 줄 캐시만 허용된 범위에서 변경한다.

지원하지 않는 표 사이/뒤쪽 글과 한 본문 호스트의 복수 루트 표는 계속 거부한다. 흐름 조정은 선택한 루트 트리 전체에 적용하며, 임의의 독립 부동 개체를 자동으로 옮기지 않는다. 단일 단·깊이 1–3·일반 문단/글자 지표·충분한 너비와 기존 높이/작업량 한도를 유지한다.

| --- | --- |
| Node/WASM 회귀 | **353개 통과**: 기존 복합 303개와 표 흐름/호스트 50개. 정렬·세로 병합·형제 오프셋·후속 동기화·지원 밖 무저장 포함 |
| 새 분리 패키지 | **14건**. 정렬 루트/세로 병합/깊이 3, 정렬별 두 표의 앞/뒤 선택, 세 표·큰 기존 최소 높이·바깥 여백·재열기 후 앞/뒤 표 편집 |
| 기존 F2 패키지 회귀 | 흐름 13건·후속 동기화/복잡 꼬리말 11건. 새 사례와 합쳐 **38건**의 계획/저장 편집 후보 해시·같은 파일 저장·무변경 이력 불변·정확한 원본 복구 |
| 독립 OLE/원시 레코드 | **38건 통과**. 선택한 내용과 상속 서식, 표 흐름/높이/위치 변경을 대조하고 정렬·앵커 순서·너비·여백·테두리·비대상 정의/스트림 보존 |
| 실제 Windows 한글 | **114개 파일·206쪽**, 복구 **48쪽** 원본/복구 픽셀 동일 |
| 새 사례 실제 표시 | 14건에서 모든 답변 줄의 실제 잉크·쪽 위치·셀 프레임, 형제 표의 표시 순서와 비겹침·후속 본문을 대조. 기존 꼬리말·교차 구역 사례도 재검사 |
| computer-use | **0회**. 파일/Node/WASM·독립 reader와 분리된 한글 자동화 API 사용 |

한글에서 문자열을 찾았다는 사실만으로 표시됐다고 판정하지 않는다. 새 사례는 원래 쪽 이미지 생성 후 **메모리에서만** 답변과 형제 표 글의 색을 구분해 추가 검사 이미지를 만든다. 표시된 답변 줄 수가 각 쪽 검색 결과와 정확히 같은지, 글이 실제 셀 프레임 안에 있는지, 각 형제 표의 잉크 범위가 앵커 순서대로 겹치지 않는지 확인한다. 색 변경 전후의 글자 위치·쪽 수를 대조하며 HWP 파일은 저장하지 않는다. 복구 비교에는 원래 색의 이미지를 사용한다.

네이티브 검증은 신뢰한 합성 문서만 사용한다. 한글 자동화는 QA에만 사용하며 제품 실행기는 한글 설치 없이 동작하는 공통 Node/WASM이다. 대표 배치 검증이 모든 reader·폰트의 동일한 쪽 계산을 인증하지 않으므로 `layout_verified:false`를 유지한다.

최종 로컬 증거는 무시된 `outputs/f2-036-20261022/hosts/`, `flow/`, `sync/`의 `cases.json`, `summary.json`, `independent-summary.json`, `native/results.json`, `native/summary.json`과 `regression.log`, `complex-tests.log`다. 초기 `align-probe`·`host-probe`는 최종 수치에 합산하지 않는다. 회귀 87개 중 복합 검사와 중복된 37개도 총수에 중복 합산하지 않는다.

기능 묶음은 `01a25f7` 한 커밋으로 게시했다. 전체 14개 작업의 [첫 CI](https://github.com/spark142857142857/hwp-easy/actions/runs/39772839616)에서 Windows 표 작업은 소스 50개·기존 패키지 24건·새 패키지 14건과 독립 판독까지 모든 검사 단계를 통과했으나, 마지막 정리 중 기존 8분 제한으로 취소됐다. 이 전체 실행을 성공으로 기록하지 않는다.

공개한 기능 이력은 유지하고 CI 설정 보완을 후속 커밋으로 분리했다. 표 작업 한도를 늘어난 검사량에 맞춰 10분으로 조정하고, 기본 전체 검사와 별도로 `scope: table-flow`를 추가해 Windows/Linux 표 작업 2개만 재실행한다. 엔진·패키지·개별 편집/미리보기 한도는 변경하지 않는다. 기본 전체 실행은 기존 14개 작업과 모든 검사 명령을 유지한다. 부분 성공을 전체 성공으로 표시하지 않으며, 두 실행의 검사 커밋·실제 결과와 동일 실행기 해시는 로컬 `outputs/f2-036-20261022/ci-first-run.json`, `ci-result.json`, `summary.json`으로 연결한다.

## 남은 범위

표 사이/뒤쪽 글, 한 본문 호스트의 복수 루트 표, 아주 좁은 셀·혼합 글자 크기·복잡한 문자 조형, 독립 부동 개체/미확인 꼬리말과 성장 표의 충돌 회피가 남는다. 글을 줄인 뒤 기존 행 최소 높이 축소·빈 공간 최적화도 후속 작업이다. 실제 설치·새 채팅과 공개 상태는 [남은 작업](remaining-work.md)에서 별도로 관리한다.
