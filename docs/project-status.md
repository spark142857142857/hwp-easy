# 프로젝트 상태

[프로젝트 개요](../README.md) · [문서 인덱스](README.md) · [사용 가이드](quick-start.md)

기준일: **2026년 10월 13일**. 현재 메인 소스·검증 패키지는 서버 없이 실행하는 **HWP Easy 0.2.22**, Codex 설치본은 **0.2.20**입니다. Claude Code·Cursor 설치와 공개 ZIP은 **0.2.19**를 유지합니다. 원격 0.1.9는 보관한 이전 구현입니다.

<a id="현재-배포와-실제-설치"></a>

## 배포 및 설치

| 구분 | 확인한 상태 |
| --- | --- |
| 메인 소스 | 0.2.22에서 중첩 그룹 전체 회전·크기, 복잡한 문단 경계와 셀 폭 넘침 진단·표 맞추기를 추가했습니다. 소스·분리 패키지 검증이며 설치 갱신·공개 배포는 별도입니다. [검증 기록](local-release-0.2.22.md) |
| 공통 엔진 | 한 소스의 Node 실행기와 @rhwp/core 0.8.6 WASM을 사용합니다. 같은 버전으로 생성한 앱별 패키지는 동일 실행 자원을 포함합니다. |
| 실제 설치 | Codex 0.2.20. Claude Code·Cursor는 0.2.19를 유지하고 이번 작업 전후 전체 설치 파일 해시가 같음을 확인했습니다. |
| 호출 정책 | Codex 스킬 선택 또는 명시적 스킬 참조, Claude Code·Cursor의 `/hwp-easy` 호출. 자동 적용은 금지합니다. |
| 공개 패키지 | [0.2.19 사전 릴리스](https://github.com/spark142857142857/hwp-easy/releases/tag/hwp-easy-local-v0.2.19)를 공개했습니다. 앱별 ZIP과 SHA-256을 제공하며 로그인 없는 다운로드와 해시를 확인했습니다. |
| OpenAI 디렉터리 | 기존 원격 제출은 심사 중·미게시입니다. 로컬 0.2.19 초안의 스킬 검사는 `Checks passed`입니다. 포털이 스킬 전용 제출 접수 제한과 정책 URL 누락을 차단 항목으로 표시하여 심사 미제출 상태입니다. [등록 기록](local-directory-submission.md)을 참고하세요. |

## 검증 결과

| 흐름 | 결과와 근거 |
| --- | --- |
| 0.2.22 그룹·문단·넘침 | 회귀·보호 검사 411개, 분리 패키지 18건의 계획·같은 파일 저장·정확한 복구와 독립 원시 판독을 통과했습니다. [검증 범위](local-release-0.2.22.md) |
| 0.2.21 표 편집 | 로컬 회귀 391개, 새 분리 패키지 14건과 공개 중첩 표 축 6건의 저장·복구·독립 OLE 판독을 확인했습니다. 한컴 자동화 검사와 범위는 [0.2.21 기록](local-release-0.2.21.md)을 따릅니다. |
| Codex 실제 호출 | 새 로컬 채팅에 0.2.20 스킬을 명시적으로 요청했습니다. 실제 모델이 본문·두 문단 셀과 중첩 표 행·누름틀을 편집해 두 파일을 각각 한 번 저장하고, 별도 후속 요청으로 정확히 복구했습니다. 메뉴 클릭 검사는 아닙니다. |
| Claude Code·Cursor | 0.2.18의 실제 `/hwp-easy` 모델 호출이 통과했습니다. 0.2.19는 실제 설치본의 파일 처리와 독립 판독을 다시 통과했습니다. Cursor 검증 대상은 CLI이며 IDE 채팅 검사는 이번 범위에서 제외했습니다. |
| 공개 복잡한 양식 | 0.2.20으로 고정된 공개 12개에서 여러 칸·긴 답변·서식·그림을 한 번에 수정·같은 사본 저장·복구했습니다. 일부 개체와 개별 블록은 여전히 읽기 전용입니다. |
| 미리보기 캐시 | 수정 후 UTF-16 텍스트와 첫 쪽 BMP 썸네일을 갱신합니다. 공개 12개에서 두 자원의 갱신을 독립 판독했습니다. |
| 한컴 배치 확인 | 0.2.20 공개·합성 18개 사본의 46쪽을 자동화 API로 렌더링했습니다. 대표 공개 문서는 3쪽 유지·8→9쪽 이동을 확인하고 복구한 11쪽의 픽셀이 원본과 같았습니다. 알려진 배치 한계는 검증 기록에 남깁니다. |
| 회귀 및 설치 검사 | 로컬 회귀 377개, 새 기능 분리 실행 17개와 설치 실행기의 저장·복구 검사 통과. 설치본과 공개 사례는 별도 Python OLE/레코드 판독으로 확인했습니다. |
| 대용량 및 배포 재설치 | 8만 코드 포인트 편집 6개와 정확한 복구를 통과했습니다. GitHub ZIP 세 개를 다시 받아 체크섬 대조 후 새 경로의 실행기·독립 판독을 통과했습니다. |

최신 소스 검사는 [0.2.22 검증 기록](local-release-0.2.22.md), 실제 Codex 설치·모델 호출은 [0.2.20 검증 기록](local-release-0.2.20.md)에 정리합니다. 검증 코드 `0d04fb5`의 [Windows·Linux CI 10개 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38353110296)이 모두 통과했습니다. 0.2.21 기능 커밋 `eb8b35b`의 [Windows·Linux CI 10개 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38362789720)도 모두 통과했습니다. 이후 변경의 상태는 [Actions](https://github.com/spark142857142857/hwp-easy/actions)에서 확인합니다.

## 남은 작업

| 분야 | 후속 작업 |
| --- | --- |
| 최신 클라이언트 호출 | 사용자 요청으로 보류. 기능 업데이트가 정리된 뒤 Claude Code·Cursor 패키지 갱신과 실제 AI 호출 재확인. 0.2.18 실제 호출·0.2.19 설치 실행기 검증은 통과 |
| 다른 사용자 설치 | 다른 PC·새 사용자 환경에서 설치·업데이트·Node 실행 조건을 확인. 현재 유지관리자의 새 폴더 설치·업데이트 검증은 통과 |
| 양식 복합 작업 | 0.2.20에서 공개 12개 복합 편집·같은 파일 저장·복구와 독립 판독을 통과. 고정 바닥글·인쇄 배치 등 실제 양식별 최종 검토는 계속 필요 |
| 편집 확장 | 0.2.22에서 중첩 그룹 전체 변환·복잡한 문단 경계·폭 넘침 진단을 추가. 임의 하위 그룹 변환, 다른 필드 유형·미지원 표 프로필, 긴 문단의 높이·쪽 나눔·부동 개체 겹침 처리는 후속 범위 |
| 디렉터리 출시 | 로컬판 개인정보처리방침·약관 준비와 확정 후 URL 연결. 스킬 검사는 통과했으며 접수 제한 해제 후 심사·게시 진행 |
| Cloud | 우선순위를 낮춘 별도 작업. 새 환경에 패키지·파일 전달, 편집과 결과 회수 전체 흐름 |

복잡한 문단의 정렬·간격은 0.2.19에서 지원합니다. Codex 0.2.20 설치·실제 호출은 검증했으며 다른 앱 갱신·공개 배포는 별도입니다. 임의 문서의 전체 배치를 지원한다고 표시하지 않습니다. 현재 요청 가능한 작업은 [지원 기능과 제한](supported-features.md)을 따릅니다.

<a id="이전-기록을-읽을-때"></a>

## 이전 구현 및 기록

원격 업로드·OAuth·Sites·D1/R2와 기존 심사는 [이전 MVP 이력](mvp-status.md), [원격 출시 기록](public-plugin-release.md)에 보관합니다. 원격 0.1.9 코드와 ZIP은 유지하며 로컬 메인을 사용하기 위해 원격 서버를 준비할 필요는 없습니다.

개별 기록의 “후보”, “미설치”, “심사 중”은 해당 검사 시점의 관측입니다. 최신 상태는 이 문서, 상세 근거는 연결된 검증 기록에서 관리합니다.
