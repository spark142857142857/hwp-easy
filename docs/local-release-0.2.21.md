# 로컬 0.2.21 표 편집 검증

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [Codex 0.2.20 설치 검증](local-release-0.2.20.md)

2026년 10월 13일의 공통 엔진 소스·분리 패키지 검증입니다. 0.2.21은 병합 중첩 표, 개체가 든 셀의 명시적 삭제와 표 배치 편집을 확장합니다. Codex 설치는 **0.2.20**, Claude Code·Cursor 설치와 공개 ZIP은 **0.2.19**를 유지합니다. 이번 변경은 설치 갱신·공개 게시·포털 제출을 포함하지 않습니다.

## 변경 범위

| 대상 | 동작 | 저장 조건 |
| --- | --- | --- |
| 병합 중첩 표 | 행·열 추가·삭제 | 격자와 크기를 증명하고 경계에 걸친 병합 셀의 문단을 보존. 병합에 덮이는 추가 칸에는 빈 문자열만 허용 |
| 중첩 셀 경계 | 셀 병합·분리 | 병합은 빈 문단을 포함한 모든 문단·혼합 서식·누름틀·그림·안쪽 표를 보존. 분리는 기존 내용을 왼쪽 위 셀에 유지 |
| 개체 셀 삭제 | 요청한 행·열과 해당 셀의 전체 내용 삭제 | 모든 영향받는 셀의 문단 내용과 원시 서브트리 SHA-256을 비교. 잘못된 값이나 삭제된 대상에 대한 후속 작업은 전체 묶음 거부 |
| 표 배치 | 열 너비·저장 행 높이, 셀 여백·세로 정렬, 표 여백·간격 | 병합 범위를 합산하고 좁아진 셀에 남는 그림·표가 들어가는지 검사. 동일 요청은 무저장 |
| 예전 형식 셀 | 46바이트·이름 확장 헤더와 텍스트 기록 없는 빈 문단 | 검증한 폭 참조만 갱신. 새 셀에 기존 이름 필드를 복제하지 않음 |
| 새 빈 셀 | 글자·그림·누름틀 후속 입력 | 한글 호환 빈 문단 기록을 사용하고 실제 입력 때 텍스트를 생성. 빈 요청은 바이트·수정 시각·복구 이력을 유지 |

표는 최대 50행·50열·256개 격자 위치이며, 중복·빈 격자나 영역 속성이 있는 표는 거부합니다. 행·열 변경은 기존 모든 병합 범위와 일치하는 내부 크기를 증명해야 합니다. 전체가 병합돼 크기가 숨겨진 표의 분리에는 기존 크기와 일치하는 전체 열·행 크기를 지정할 수 있습니다. 크기·여백 편집은 별도 `layout_editable`로 표시합니다.

복구와 비대상 보존은 기존 같은 파일 저장 경로를 사용합니다. 셀을 지워도 사용하지 않는 이미지 스트림·정의와 복구 사본은 남으며 영구 삭제로 표현하지 않습니다. 입력란의 고정 바닥글, 중첩 그룹 회전·크기, 다른 필드 유형과 복잡한 문단 경계 편집은 이번 확장에 포함하지 않습니다.

## 검사 결과

| 검사 | 결과 | 확인한 내용 |
| --- | --- | --- |
| Windows·Linux CI | 10개 작업 모두 통과 | 기능 커밋 `eb8b35b`의 [Source checks](https://github.com/spark142857142857/hwp-easy/actions/runs/38362789720) |
| 로컬 회귀 | 391개 통과 | 기존 본문·표·그림·서식·저장·복구와 새 표 경로. 새 전용 검사 14개 포함 |
| 분리 패키지 | 합성 14건 통과 | 2·3단 병합 표 축, 개체 셀 병합·분리·삭제, 안쪽 표 전체 삭제, 네 배치 작업의 묶음 저장 |
| 공개 양식 | 고정 공개 3개·축 변경 6건 통과 | 원본 해시 유지, 계획과 저장 해시 일치, 같은 시험 사본 저장·정확한 복구 |
| 독립 Python 판독 | 합성 14건·공개 6건 통과 | OLE 스트림, 모든 원시 표 격자·셀 문단 수·병합 범위·개체 기록, 삭제 확인 해시, 바이트 복구 |
| 한컴 자동화 API | 수정 전·후·복구 파일 36개 열기, 172쪽 렌더링 | 요청한 추가 내용의 TEXT 판독, 파일 무변경, 복구한 58쪽의 BMP 픽셀 해시 일치 |
| 패키지 준비 | ZIP 25개 파일 검사 통과 | 실행기·WASM·고지·명시적 호출 정책과 새 설치 준비 폴더 검사. 실제 설치는 별도 |

공개 코퍼스는 RHWP의 고정 커밋 `1a76570e833917d15817415a53c09ad61ab3203f`에서 온 비개인 문서입니다. 개인 `testdocs`와 원본은 편집하지 않았고 파일 업로드·computer-use는 사용하지 않았습니다. 로컬 파일 처리는 Node/WASM, 독립 판독은 Python, 외부 호환성 확인만 기존 한컴 자동화 API를 사용했습니다. 한글은 제품 실행 조건이 아닙니다.

이전 검사에서 전체 쪽 이미지를 만들지 못했던 공개 양식 7은 한컴 API의 `MoveDocEnd`로 쪽 계산을 완료한 뒤 모든 쪽을 렌더링했습니다. 행 추가는 17쪽 유지, 열 추가는 줄바꿈 변화로 17→18쪽이며 복구는 17쪽과 원본 이미지로 돌아왔습니다. 이는 검증한 문서의 결과이며 임의 문서의 인쇄·폰트·최종 배치를 인증하지 않습니다.

아주 좁은 3단 합성 표에서는 글자가 한 글자씩 줄바꿈되거나 셀 경계에 가려지는 배치를 관찰했습니다. 원시 글자와 한컴 TEXT 판독은 보존됐지만 전체 표시·인쇄 상태의 통과로 계산하지 않습니다. 내부 여백과 글자 크기에 따른 넘침 확인·보고, 고정 개체 재배치는 후속 범위입니다. 이를 자동 글꼴 축소나 내용 삭제로 숨기지 않습니다.

한글 검사 중 새 빈 셀의 CR만 든 텍스트 기록이 열기 실패를 일으키는 것을 발견해 호환 빈 문단 프로필로 수정했습니다. 세 단계 중첩 합성 표의 제어 위치와 부모 셀 내부 너비도 고쳤습니다. 수정 전 실패 산출물과 최종 성공 산출물을 구분해 보관합니다.
