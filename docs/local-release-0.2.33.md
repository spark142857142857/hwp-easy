# 로컬 HWP Easy 0.2.33 검증 기록

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md#소스-0233-추가-기능) · [남은 작업](remaining-work.md)

2026년 10월 22일. F1-B의 복수 중첩 표·접두부 줄바꿈·여러 문단의 조상 정렬을 추가해 **F1의 지원 프로필 구현을 완료**한다. 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다.

## 변경 내용

- 동일 크기·동일 글의 중첩 표도 **원시 제어 순서와 전체 셀·문단 경로**로 구분한다. WASM의 잘린 중첩 식별자와 표 표시 좌표를 실제 한글의 원점으로 사용하지 않는다.
- 인라인 표·앞선 글을 원래 토큰 순서로 조합한다. 표의 바깥 여백, 자동/명시적 줄바꿈, 줄 높이·간격과 양쪽 정렬을 반영한다. 같은 줄에 있는 표와 다음 줄로 내려간 표를 구분한다.
- 앞뒤 평문 문단을 포함한 전체 내용 높이로 조상 셀의 위/가운데/아래 정렬을 계산한다. 고정된 셀·표 치수와 원래 정렬은 변경하지 않는다.
- 사각형 글상자뿐 아니라 지원 그림·그림 그룹에도 같은 투영을 적용한다. 선택 개체의 오프셋과 매핑된 줄 캐시만 바꾸며 내용·서식·앵커·이미지·crop·행렬·다른 제어를 보존한다.

한 Node/WASM 엔진을 유지한다. 서버·한글 설치는 제품 실행 조건에 추가하지 않는다. 네이티브 검사는 신뢰한 합성 파일에 한컴 자동화 API를 사용하며 computer-use 호출은 0회다.

## 조판 차이와 지원 조건

실제 한글은 줄이 바뀐 문단의 양쪽 정렬에서 글·표 사이 간격을 늘리는 반면, 현재 WASM은 긴 셀 접두부의 글자 폭을 눌러 표시할 수 있다. 기존 셀의 `charX`를 자연 글자 폭으로 사용하면 잘못된 표 원점이 된다. 임시 왼쪽 정렬 문서에서 같은 글꼴·크기의 자연 폭을 측정하고, 원시 인라인 흐름을 별도로 조합한다. 임시 문서는 원본에 저장하지 않는다.

폭 ±4%의 민감도 검사를 거쳐 세로 줄바꿈 결과가 달라지면 저장 전에 거부한다. 가로 위치가 달라질 때는 가능한 셀 내부의 공통 영역에 개체를 넣는다. 이 범위는 **폰트 추정**이며 다른 환경의 폰트 대체나 모든 HWP 조판을 인증하지 않는다. `layout_verified:false`, `engine_checked:false`, `NESTED_FLOATING_RENDER_ORIGIN_DISAGREEMENT`를 유지한다.

새 흐름은 깊이 2·3의 검증 가능한 고정 격자, 가로 평문, 문단별 단일 글자 크기, 보통 문자 폭/간격, 100–300% 줄 간격, 문단 여백·들여쓰기·앞뒤 간격 0을 지원한다. 알 수 없는 제어·복잡한 문자 조형·혼합 크기·세로 줄바꿈 불확실성·부족한 고정 셀 공간은 원본과 이력을 바꾸지 않고 거부한다. 앞선 행의 높이가 달라지는 자동 확장·중첩 표 쪽 분할은 F2, 외부 한글과 WASM 표시 차이는 F3에 남는다.

## 검증 중 보완

조합 흐름의 표 표시 틀을 제외하면서 주변의 다른 본문 표까지 장애물에서 빠질 수 있는 경계 경우를 수정했다. 전체 원시 경로와 관측된 셀 글 위치로 해당 흐름의 표만 분류하고, 다른 본문 표는 계속 장애물로 남긴다. 300% 줄 간격에서는 WASM의 안쪽 표 틀이 조상 밖으로 표시될 수 있어 단순 포함 관계 대신 이 분류를 적용한다. 분류 검색에도 200,000회 제한을 둔다. 다른 본문 표를 보존하는 회귀와 300% 줄 간격의 앞뒤 문단·아래 정렬 회귀를 추가했다.
