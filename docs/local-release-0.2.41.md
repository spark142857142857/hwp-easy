# 로컬 HWP Easy 0.2.41 검증 기록

[남은 F2](remaining-work.md#f2-세부-현황) · [지원 기능](supported-features.md#소스-0241-추가-기능) · [프로젝트 상태](project-status.md)

검증일: **2026년 10월 23일**. F2-C2에 같은 쪽의 빈 공간을 활용하는 독립 부동 배치를 추가한다. 소스·검증 패키지는 0.2.41이며 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19다.

## 구현과 지원 경계

앞선 일반 본문 높이와 계산된 루트 표의 최소 높이·여백, 부동 개체의 고정 문단 예약 높이를 누적한다. 예약 높이와 후속 글 여유가 한 쪽에 들어가면 기존 쪽을 재사용한다. 여러 쪽에 걸친 선행 흐름·미확인 본문·시작 위치가 증명되지 않은 뒤쪽 구역은 위치를 추측하지 않고 새 쪽으로 분리한다. 표 높이를 모두 계산한 뒤 부동 공간을 배정하며, 한 호스트의 복수 루트 정규화도 마지막 루트에서 배정한다.

0.2.40의 별도 빈 본문 앵커·회전 없는 그림/지원 짧은 단순 글상자 프로필을 유지한다. 부동 상태, 원래 가로 위치·크기·crop·이미지와 글/글자 서식·앵커 순서를 보존한다. 한 쪽의 여유를 활용해도 개체의 고정 문단 높이와 후속 글 여유는 줄이지 않는다. 앞쪽 본문을 길게 편집한 경우도 재열기 후 자동 동기화하여 공간 부족과 개체/후속 글 가림을 재검사한다.

기존 명시적 쪽 나눔은 기본 보존한다. `floating_page_breaks:"recompute_managed"`는 관리형 빈 앵커의 기존 나눔을 다시 계산하라는 명시 요청에만 사용한다. 정확히 일치하는 흐름/고정 높이 프로필의 나눔을 계획에 표시하고 제거할 수 있다. 생성 이력을 판별하는 기능은 아니므로 같은 프로필로 작성한 나눔도 재계산 대상이 된다. 일반 문단의 나눔은 변경하지 않는다. 알 수 없는 정책 값·지원 밖 구조·고정 틀을 넘는 편집은 저장 전에 거부한다.

이 기능은 보수적 한 쪽 공간 활용이다. 불확실한 다중 쪽의 마지막 여유, 글 혼합/셀 안 앵커·추가 좌표/회전/그룹/글상자 내부는 후속 확장으로 남긴다. F2 핵심 마감은 행 최소 높이 축소·빈 공간 최적화와 대표 양식의 마감 회귀·범위 확정 두 묶음으로 관리한다.
