# Codex 설치본과 새 채팅 검증 0.5.1

[프로젝트 상태](project-status.md) | [통합 배포](unified-release-0.5.1.md) | [남은 작업](remaining-work.md)

2026년 10월 28일, 현재 PC에 설치된 **0.5.1**을 새 Codex 채팅에서 검증했습니다. 일반 본문과 표 셀, 65줄 중첩 표, 그룹 내부 글과 필드 및 하위 그룹 변형을 요청했습니다. 그룹 문서는 최초 요청이 거절됐고 JSON 항목 순서를 맞춘 뒤에 통과했습니다. 이 조건부 결과와 소스 수정을 구분합니다.

## 설치와 호출

설치 파일 25개가 공개 0.5.1 배포본과 일치합니다. 새 Codex 호스트의 스킬 발견은 `hwp-easy:edit-local-hwp` 1개, 활성 상태, 오류 0개였습니다. `allow_implicit_invocation:false`를 유지했습니다.

별도로 만든 로컬 채팅에서 스킬을 명시 호출하고 설치된 SKILL과 참조를 읽었습니다. 해당 채팅은 설치 캐시의 실행기만 사용해 실제 요청을 만들었습니다. 부모의 검증 코드는 판독과 배치 대조를 위한 개발 QA이며 사용자 편집 실행기를 대체하지 않습니다. 스킬 메뉴의 클릭과 UI 자동 주입은 이번에 검사하지 않았습니다.

## 실제 편집과 복구

| 합성 문서 | 확인한 내용 | 결과 |
| --- | --- | --- |
| 일반 본문과 표 셀 | 본문 한 곳, 답변 셀을 실제 두 HWP 문단과 이모지로 변경. 무변경 요청에서 저장과 백업 불변 | **통과** |
| 중첩 표 | 답변 8줄에서 65줄로 확장, 표 높이와 쪽 흐름 조정. 비대상 본문과 표 보존 | **통과** |
| 그룹 내부 편집 | 누름틀 값과 이름 및 안내 변경, 형제 글상자 편집, 첫 하위 그룹 이동과 회전 및 크기 변경 | **0.5.1 항목 순서 우회 조건부 통과** |

세 문서 모두 계획 전후 파일 해시와 백업 목록이 같았습니다. 실제 편집은 각 파일의 같은 경로에 한 번 저장했고 계획과 저장의 검증 후보 해시가 일치했습니다. 편집본 사본과 전체 쪽 SVG를 남긴 뒤 별도 restore 요청으로 원본을 정확히 복구했습니다. 복구 후에도 편집본 백업이 유지됐습니다.

독립 Python OLE/레코드 판독은 요청한 글과 문단, 필드 속성, 비대상 제어와 스트림 및 글꼴 정의 보존을 확인했습니다. 최초 실패 두 건과 최초 2/3 결과는 보존했습니다. 재검증은 실패한 그룹 문서에만 수행했습니다.

## 실제 배치

새 채팅이 만든 원본과 편집본 및 복구본 **9개 파일, 10쪽**을 별도 숨김 한글 인스턴스에서 무저장으로 열었습니다. 텍스트와 쪽 수를 확인했고 검사 후 입력 파일 바이트는 그대로였습니다. 원본과 복구본 **3쪽의 픽셀이 일치**했습니다.

중첩 표는 실제 한글과 설치 미리보기 모두 **1쪽에서 2쪽**으로 이어졌습니다. 65줄이 빠지거나 중복되지 않았고 두 번째 쪽은 **L038**부터 시작했습니다. 원본 8줄과 복구 8줄을 포함한 81줄의 쪽 소속을 대조했습니다. 그룹 내부 글 4개도 표시되며, 편집 후 회전 그룹의 원본 문단 ID와 표시 글이 일치합니다. 설치 실행기가 반환한 편집 후 SVG는 별도 검사한 뷰와 같습니다.

일반 HWP 전체의 글꼴과 인쇄 배치를 인증한 것은 아닙니다. `layout_verified:false`와 기존 지원 밖 조건을 유지합니다. 실제 한글 검사는 개발 QA이며 HWP Easy 실행에 한글 설치가 필요하다는 뜻은 아닙니다.

## B7 JSON 객체 항목 순서 오류

0.5.1은 `expected_metadata`의 이름, 안내, 명령이 실제 문서와 같아도 객체의 항목 순서가 다르면 `EXPECTED_FIELD_METADATA_MISMATCH`로 거절합니다. 필드 변경 작업의 순서를 바꿔도 해결되지 않았습니다. `name, guide, command` 순서로 직렬화한 요청은 같은 설치본에서 통과했습니다. 첫 두 거절은 저장 전에 발생했고 원본은 유지됐습니다.

원인은 객체 비교를 JSON 문자열의 문자 순서로 처리한 공통 함수였습니다. 그룹 속성의 항목 순서를 뒤집은 별도 회귀에서도 같은 종류의 `EXPECTED_GROUP_MISMATCH`를 재현했습니다.

**소스에서는 수정했습니다.** 객체 키를 정규화해 비교하고 배열 순서는 유지합니다. 필드 기대값의 정확한 키 집합과 값 검사도 유지합니다. 본문과 그룹 필드의 항목 순서 6종, 계획 무저장, 같은 파일 저장, 무변경 무저장, 누락 및 추가 키와 오래된 값 거부, 정확한 복구를 회귀 검사에 추가했습니다. 그룹 속성의 순서와 중첩 객체 및 배열 순서도 검사합니다.

수정 전 새 회귀의 실패를 확인한 뒤 수정했습니다. 수정 소스의 별도 실행기 빌드에서도 원래 거절된 필드 순서와 뒤집은 그룹 속성 순서로 계획과 같은 파일 저장 및 정확한 복구, 독립 판독을 통과했습니다. 이 편집 결과는 실제 배치를 검사한 0.5.1 우회 결과와 바이트가 같습니다.

**공개 npm과 GitHub, 현재 세 앱 설치본은 0.5.1을 유지합니다.** 이번 수정은 소스와 검증까지이며 설치본 교체나 새 버전 게시를 하지 않았습니다. 다음 작업은 이 수정을 새 패치 버전으로 묶어 배포하는 것입니다. 이미 게시한 0.5.1의 내용을 바꿔 재사용하지 않습니다.
