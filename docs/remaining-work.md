갱신일: **2026년 10월 15일**. 기능·배치 검증의 기준은 10월 13일의 **0.2.23**이다. 이 문서는 앞으로 할 작업의 상태·우선순위·완료 기준을 관리한다. 현재 제공하는 기능은 [지원 기능](supported-features.md), 배포·설치 현황은 [프로젝트 상태](project-status.md), 제품 범위와 결정은 [PRD](PRD.md)를 기준으로 한다.

## 현재 단계

**로컬에서 읽기 → 편집 → 같은 파일 저장 → 복구하는 핵심 흐름은 구현·검증을 마쳤다.** 지원하는 표·누름틀·그림·그룹·문단의 편집 범위도 넓어졌다. 현재는 복잡한 양식의 배치와 배포 전 검증을 마무리하는 단계다.

핵심 흐름의 완성과 모든 HWP 구조의 자유 편집은 구분한다. 특히 부동 개체를 유지하는 재배치, 고정 바닥글과의 충돌, 미지원 개체·리스트, 외부 한글과의 페이지 계산 차이는 남아 있다. 완료율을 하나의 숫자로 표시하기보다 아래 완료 기준으로 판단한다.

## 편집 기능의 남은 작업

아래 우선순위와 작업 순서는 제안이다. 상태는 `미완료`, `범위 결정 필요`, `보류`, `외부 확인 필요`로 구분하며, 완료 시 대상 버전과 검증 기록을 함께 연결한다.

| ID | 우선순위·상태 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| F1 | 높음 · 미완료 | **부동 상태를 유지하는 개체 재배치** | 선택 개체의 기준 좌표계·크기·이미지·그룹 구조를 보존하면서 필요한 위치를 조정해 본문/다른 개체와의 충돌을 해소. 의도된 로고·워터마크와 충돌을 구분하고, 해결하지 못한 경우를 명시. 수정·같은 파일 저장·복구와 실제 쪽 이미지 확인 |
| F2 | 높음 · 미완료 | **고정 바닥글·고정 개체와 긴 본문/표의 충돌 처리** | 본문 가용 영역과 고정 영역을 구분하고 문단·표의 쪽 이어짐과 연동. 바닥글과 내용을 보존한 대표 양식의 전후 쪽 배치·끝 글자 표시·복구 확인 |
| F3 | 중간 · 미완료 | **WASM 배치 진단의 정확도 개선** | 폰트 대체·페이지 계산 차이와 실제 넘침을 구분할 수 있는 재현 사례·회귀 검사 확보. 현재 60줄 사례처럼 네이티브에서는 정상인데 WASM에서 남는 높이 경고의 원인과 처리 범위를 기록 |
| F4 | 중간 · 범위 결정 필요 | **미지원 개체·문서 구조 확장** | 내부 하위 그룹의 직접 변환, 다른 필드 유형·도형·문단 리스트·표 프로필 중 실제 수요가 높은 대상을 선택. 각 프로필의 편집 조건·비대상 보존·실패 거부·저장·복구를 검증한 뒤 지원 목록에 추가 |

**F1의 현재 대안은 이미 구현되어 있다.** 0.2.23은 선택 개체를 ‘글자처럼 취급’해 문단이 높이를 확보하도록 한다. 부동 상태를 유지하는 F1과는 동작이 다르므로 완료 항목과 남은 항목을 섞지 않는다. 원래 위치가 중요한 개체를 일괄 변환하는 방식으로 처리하지 않는다.

## 실사용·배포를 마무리할 작업

| ID | 상태 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| R1 | 미완료 | **선택한 안정 버전을 Codex에 설치하고 새 채팅에서 검증** | 설치 자원·버전·명시적 호출 정책 확인. 실제 모델이 일반 문서와 복잡한 양식을 편집하고 같은 파일 저장·별도 요청 복구까지 완료. 0.2.20의 성공 기록은 유지하며 후속 버전 결과를 추가 |
| R2 | 미완료 | **최종 후보로 공개·합성 양식의 복합 작업 재검증** | 기존 0.2.20 공개 12개 검증을 토대로 최신 후보의 글·표·누름틀·그림·흐름 조정을 묶어 검사. 충돌 거부·무변경 무저장·비대상 보존·같은 파일 저장·정확한 복구와 대표 쪽 배치 확인. 공개·합성 원본은 보존 |

| R4 | 미완료 | **공개할 버전·패키지·문서 확정** | 실제 검증한 지원 범위로 버전을 선택하고 README·설치 안내·요청 참조·라이선스·ZIP·체크섬을 일치시킴. 게시 후 공개 다운로드의 해시 확인. 개인 문서·인증 정보는 패키지에서 제외 |

R5는 코드만으로 해결할 수 없는 외부 절차를 포함한다. 10월 13일의 접수 제한을 현재도 유지 중이라고 단정하거나, 원격판 승인 이력만으로 로컬판 심사가 간소화됐다고 판단하지 않는다. 로컬 실사용 검증과 디렉터리 게시 완료는 각각 관리한다.

## 권장 진행 순서와 마무리 기준

1. **배치 보강:** F1 → F2. 현재 사용자가 계속 개선을 요청한 기능을 우선 처리한다.
2. **후보 검증·버전 확정:** R2 → R4의 패키지/문서 확정. F3에서 드러난 차이는 해결 결과 또는 남은 제한으로 기록한다.
3. **실제 설치 검증:** R1 → R3. 새 채팅과 새 사용자 환경에서 설치부터 복구까지 확인한다.
4. **앱 확대·공개:** 대상 버전이 정리되면 D1을 재개하고, R4의 게시·다운로드 확인과 R5를 진행한다. R5의 현재 접수 여부·정책 준비는 앞 단계와 병행 확인할 수 있다.

| 마일스톤 | 완료 판단 |
| --- | --- |
| 로컬 실사용 안정화 | 지원하기로 정한 범위에서 R2·R1·R3 통과. 알려진 배치 한계와 미지원 거부가 재현되고, 사용자가 편집 결과를 확인하고 복구할 수 있음 |
| 후속 공개 릴리스 | R4 완료. 세 앱을 같은 버전으로 게시한다면 D1의 실제 검증 결과도 확보 |
| 디렉터리 출시 | R5의 심사·게시가 실제 완료. 포털 업로드·자동 검사 통과만으로 완료 처리하지 않음 |
| 지속적 기능 확장 | F3·F4를 수요와 재현 사례별로 진행. 모든 HWP 구조를 지원할 때까지 출시를 무기한 미루는 완료 조건으로 삼지 않음 |

## 유지할 범위와 기록 방식

- 제품은 공통 Node/WASM 엔진을 쓰는 로컬 HWP 편집이다. 스킬은 명시적으로 호출하고, 기본 저장은 검증한 같은 파일 저장·복구다.
- 원격 0.1.9 코드·ZIP은 보관한다. 중앙 서버 운영이나 원격판 통합은 현재 남은 필수 작업에 넣지 않는다.
- HWPX·PDF·DOCX 변환·내보내기는 제품 범위 밖이다. 기존 COM 코드는 보관한 프로토타입이며 네이티브 호환성 검증을 제품의 한글 설치 의존성으로 바꾸지 않는다.
- 새로운 독립 GUI·설치 프로그램 같은 제품 확장은 R3의 사용성 문제와 수요를 확인한 뒤 범위를 결정한다.
- 기능 완료 시 이 문서의 ID·상태·완료 기준을 갱신하고 릴리스 검증 기록을 연결한다. 소스 버전, 실제 설치, 공개 ZIP, 심사 상태는 각각 기록한다.
- 심사·게시 같은 외부 상태에는 확인 날짜를 붙인다. 예정 작업과 과거 검증 결과를 현재 완료 상태로 섞지 않는다.
