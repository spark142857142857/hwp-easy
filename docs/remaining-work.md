갱신일: **2026년 10월 15일**. 기능·배치 검증의 기준은 10월 15일의 **0.2.25**이다. 이 문서는 앞으로 할 작업의 상태·우선순위·완료 기준을 관리한다. 현재 제공하는 기능은 [지원 기능](supported-features.md), 배포·설치 현황은 [프로젝트 상태](project-status.md), 제품 범위와 결정은 [PRD](PRD.md)를 기준으로 한다.

## 현재 단계

**로컬에서 읽기 → 편집 → 같은 파일 저장 → 복구하는 핵심 흐름은 구현·검증을 마쳤다.** 지원하는 표·누름틀·그림·그룹·문단의 편집 범위도 넓어졌다. 현재는 복잡한 양식의 배치와 배포 전 검증을 마무리하는 단계다.

핵심 흐름의 완성과 모든 HWP 구조의 자유 편집은 구분한다. 0.2.24에서 부동 개체 재배치·고정 바닥 영역 보호·사각형 글상자의 대표 프로필을 검증했다. 다단/복잡한 꼬리말·미지원 개체/리스트·외부 한글과의 페이지 계산 차이는 남아 있다. 완료율을 하나의 숫자로 표시하기보다 아래 완료 기준으로 판단한다.

아래 우선순위와 작업 순서는 제안이다. 상태는 `대표 프로필 완료·후속 범위 남음`, `미완료`, `보류`, `외부 확인 필요`로 구분하며, 완료 시 대상 버전과 검증 기록을 함께 연결한다.

**0.2.25 후속 결과:** F1은 벡터 도형 그룹의 바깥 이동을 추가해 공개 지도/답변 겹침을 해결했다. F2는 공개 표지의 60줄 답변·하단 장식 위치를 확인했고, 장문 중첩 표 2개의 잘림은 선택한 엄격 정책의 저장 거부로 보완했다. **중첩 표 장문의 자동 분할은 미완료**다. F3는 인라인 개체의 부동 충돌 오탐과 중첩 표 쪽 계산의 과도한 확신을 줄였다. F4의 **셀·중첩 셀 단순 글상자 편집은 완료**했으며 그룹/상자 내부 글상자와 복잡한 내부 제어는 남는다. [검증 기록](local-release-0.2.25.md)

**F1의 inline 전환 대안도 유지한다.** 0.2.23은 선택 개체를 ‘글자처럼 취급’해 문단이 높이를 확보하도록 한다. 0.2.24의 부동 상태 유지 재배치와는 별도 동작이다. 원래 위치가 중요한 개체를 일괄 변환하는 방식으로 처리하지 않는다.

## 권장 진행 순서와 마무리 기준

1. **배치 후속 범위 선택:** F1–F4의 0.2.24 대표 프로필은 완료했다. 남은 다단·복잡한 꼬리말·개체 프로필은 실제 재현 사례로 범위를 정한다.
2. **버전 확정·설치:** R2의 0.2.25 재검증은 완료했다. R4 후보 확정 후 R1의 Codex 설치를 갱신하고 R3를 진행한다. F3에서 드러난 차이는 제한으로 유지한다.
3. **다른 사용자 설치 검증:** R1의 0.2.24 대표 새 채팅 검증은 완료했다. R3에서 새 사용자 환경의 설치·업데이트·복귀를 확인한다.
4. **앱 확대·공개:** 대상 버전이 정리되면 D1을 재개하고, R4의 게시·다운로드 확인과 R5를 진행한다. R5의 현재 접수 여부·정책 준비는 앞 단계와 병행 확인할 수 있다.

| 마일스톤 | 완료 판단 |
| --- | --- |
| 로컬 실사용 안정화 | 지원하기로 정한 범위에서 R2·R1·R3 통과. 알려진 배치 한계와 미지원 거부가 재현되고, 사용자가 편집 결과를 확인하고 복구할 수 있음 |
| 후속 공개 릴리스 | R4 완료. 세 앱을 같은 버전으로 게시한다면 D1의 실제 검증 결과도 확보 |
| 디렉터리 출시 | R5의 심사·게시가 실제 완료. 포털 업로드·자동 검사 통과만으로 완료 처리하지 않음 |

## 유지할 범위와 기록 방식

- 제품은 공통 Node/WASM 엔진을 쓰는 로컬 HWP 편집이다. 스킬은 명시적으로 호출하고, 기본 저장은 검증한 같은 파일 저장·복구다.
- 원격 0.1.9 코드·ZIP은 보관한다. 중앙 서버 운영이나 원격판 통합은 현재 남은 필수 작업에 넣지 않는다.
- HWPX·PDF·DOCX 변환·내보내기는 제품 범위 밖이다. 기존 COM 코드는 보관한 프로토타입이며 네이티브 호환성 검증을 제품의 한글 설치 의존성으로 바꾸지 않는다.
- 새로운 독립 GUI·설치 프로그램 같은 제품 확장은 R3의 사용성 문제와 수요를 확인한 뒤 범위를 결정한다.
- 기능 완료 시 이 문서의 ID·상태·완료 기준을 갱신하고 릴리스 검증 기록을 연결한다. 소스 버전, 실제 설치, 공개 ZIP, 심사 상태는 각각 기록한다.
- 심사·게시 같은 외부 상태에는 확인 날짜를 붙인다. 예정 작업과 과거 검증 결과를 현재 완료 상태로 섞지 않는다.
