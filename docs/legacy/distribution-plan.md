# 일반 사용자를 위한 배포 계획

> 이전 Windows COM 프로토타입의 배포안입니다. 2026년 10월 2일의 [제품 요구사항 초안](../PRD.md)은 한글 설치 없이 클라우드에서 에이전트가 HWP를 편집하는 방향을 제안합니다. 아래의 한글 필수 조건과 EXE·GUI 우선 순서는 새 목표가 아니며, 현재는 참고 자료로 보존합니다.

이 문서는 **설계안**입니다. 이번 단계에서는 설치 파일·GUI·연결 마법사를 구현하거나 설치하지 않고, MCP 등록·사용자 설정 변경도 수행하지 않습니다. 현재 실행 방법은 [개발자 안내](development.md)에 있습니다.

## 현재와 목표

현재 구현은 Windows 한글 자동화 엔진을 사용하는 안전한 문서 작업, 개발자용 CLI, 표준 입출력 방식의 로컬 MCP입니다. 다운로드할 설치 프로그램, 폴더 선택 화면, 원클릭 Codex 연결, 공개 플러그인은 아직 없습니다.

목표는 **한글이 설치된 일반 사용자가 Python 설치나 명령어 입력 없이** 사용하는 것입니다. 한글 엔진 자체의 구현·배포, 클라우드 한글 서버, 문서 디자인 편집기, 자동 포털 제출은 이번 배포안의 범위가 아닙니다. 기본은 HWP 수정·새 HWP 저장이며 PDF/DOCX는 별도 선택입니다.

## 먼저 만들 배포물

`HWP Easy Setup.exe`와 `HWP Easy Portable.exe`는 예정된 이름입니다. 아직 제공되는 파일이 아닙니다. 첫 배포는 실행 환경을 함께 묶은 Windows 로컬 프로그램과 폴더 선택·환경 확인 화면을 우선합니다.

프로그램에는 자체 실행에 필요한 런타임과 의존성을 포함하되 한글 엔진·공식 보안 DLL·매뉴얼은 포함하지 않습니다. 사용자의 기존 한글 설치와 파일 접근 승인 환경을 진단합니다. 등록된 보안 모듈이 없으면 원인과 승인 절차를 설명하고, 모듈 설치나 레지스트리 변경이 필요한 경우 그 변경·권한·배포 조건을 검토한 뒤 별도 명시 동의를 받아야 합니다. 현재 코드는 이를 설치·등록하지 않습니다.

포터블 버전이라고 한글 설치나 승인 환경까지 불필요해지는 것은 아닙니다. 숨은 개발자 설정이 필요한 상태를 “더블클릭만 하면 완료”라고 소개하지 않습니다.

## 예정된 사용 흐름

1. 프로그램 실행 후 한글·보안 모듈·출력 파일시스템 상태를 확인합니다.
2. 사용자가 작업 폴더를 선택합니다. 기본값으로 사용자 홈이나 드라이브 전체를 허용하지 않습니다.
3. 기본 문서 작업은 선택한 폴더의 HWP 원본과 새 HWP 출력에 한정합니다.
4. AI 연결을 원하면 대상 클라이언트·서버 명령·허용 폴더·설정 범위를 미리 보여줍니다.
5. 사용자가 연결 버튼을 눌러 승인한 경우에만 필요한 연결을 추가합니다.

설정 변경 전에는 보호된 로컬 백업을 만들고, 실패 시 복구할 수 있어야 합니다. 연결 해제는 추가한 항목만 제거하고 기존 MCP·스킬·다른 설정을 보존합니다. 중간에 설정이 바뀌었으면 옛 백업으로 파일 전체를 무조건 덮어쓰지 않습니다. 백업·진단 로그에도 비밀값이나 개인 원문을 불필요하게 수집하지 않습니다.

## MCP와 플러그인의 역할

로컬 MCP는 사용자 PC에서 한글을 제어하는 연결 도구입니다. 플러그인은 스킬·MCP 연결 정보를 묶는 배포 단위이지, Windows 실행 파일의 설치나 한글 사용권을 대신하지 않습니다. 공식 안내는 데스크톱의 로컬 STDIO 연결과 원격 HTTP 연결을 구분합니다. [OpenAI MCP 안내](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

플러그인 패키징을 진행할 경우 현재 공식 형식의 루트 `plugin.json`, 필요한 `mcp.json`, `skills/` 및 OpenAI 확장 메타데이터를 검토합니다. 이 문서에서는 manifest를 생성·등록하지 않습니다. 공개 제출은 원격 HTTPS 경로가 안내되며 로컬 MCP는 별도 지원 문의가 필요하므로, 로컬 도구를 포장했다고 공개 디렉터리 배포가 승인된 것은 아닙니다. [OpenAI 플러그인 패키징 안내](https://developers.openai.com/plugins/build/plugins)

원격 플러그인만으로 사용자 PC의 한글을 직접 제어할 수 있다고 약속하지 않습니다. 로컬 브리지는 여전히 필요하며, 별도 인증·권한·정보 전달 설계 없이 로컬 포트를 공개하거나 임시 터널을 공개 배포 방식으로 삼지 않습니다. 우선 로컬 설치와 명시적 연결을 완성하고 공개 플러그인 경로는 별도 검토합니다.

스킬의 `allow_implicit_invocation: false`는 명시 호출 선호를 유지하는 설정이지 MCP 인증 게이트가 아닙니다. 서버 등록만으로 특정 문서를 읽고 수정할 권한이 생기는 것도 아닙니다. 클라이언트의 도구 승인과 서버의 경로·출력 보호 조건을 각각 유지해야 합니다. 앱의 비대화 모드 역시 인증·사용자 동의를 대신하지 않습니다.

## EXE 빌드 전에 해결할 사항

현재 worker 실행은 `sys.executable -m one_hwp.worker`에 의존합니다. 동결된 프로그램에서 `sys.executable`은 Python 인터프리터가 아닌 EXE 자신을 가리킬 수 있으며, 현 CLI로는 worker에 진입하지 못하는 문제가 재현됐습니다. **EXE 전용 worker 진입점 또는 동봉 런타임의 명확한 worker 실행 경로를 먼저 구현·시험해야 합니다.** 소스 실행이나 wheel 빌드 통과를 설치형 프로그램의 성공으로 취급하지 않습니다.

GUI와 MCP의 실행 경로도 구분해 MCP 표준 출력에는 프로토콜 데이터만 내보내야 합니다. COM 시간 초과·정리 실패 시 작업용 인스턴스와 남은 사본을 알리고, 기존 사용자 한글 세션을 일괄 종료하지 않습니다.

## 첫 설치형 배포의 통과 조건

다음은 아직 충족을 주장하지 않는 출시 전 점검 항목입니다.

- Python·개발 도구가 없는 깨끗한 Windows에서 설치형·포터블 실행을 검증합니다.
- 한글이 없으면 명확한 한국어 오류와 준비 안내를 표시합니다. 한글이 있지만 보안 모듈이 없는 경우도 구분하며 무단 설정 변경 없이 안내합니다.
- 실제 EXE에서 worker 실행·종료, 로컬 MCP 연결과 프로토콜, 잘못된 요청·시간 초과·정리 실패를 시험합니다.
- 선택 폴더 밖 경로·심볼릭 링크/접합점·기존 출력 덮어쓰기를 차단하고 원본 해시 불변 조건을 확인합니다. 경로 제한을 운영체제 보안 샌드박스로 소개하지 않습니다.
- 검증된 NTFS 환경의 하드링크 공개를 시험합니다. 지원하지 않는 파일시스템에서는 안전한 오류를 내고 덮어쓰기 위험이 있는 복사로 자동 우회하지 않습니다.
- 합성 HWP의 본문·표·여러 줄 필드를 편집해 저장·재열기와 시각 확인을 분리합니다. 기본 작업에서 PDF/DOCX가 생성되지 않는 것도 확인합니다.
- 연결 승인 전 설정 불변, 승인 후 기존 항목 보존, 변경 중 오류·중복 연결·동시 수정에서 백업/복구와 연결 해제를 시험합니다.
- 설치·삭제·업데이트가 사용자 문서와 다른 연결을 지우지 않는지 확인합니다.

개인 문서를 설치형 테스트에 사용하지 않습니다. 모의 테스트·MCP 연결 성공·합성 네이티브 성공·화면 배치 검증은 별개의 근거로 기록합니다. DOCX 출력의 시각 검증과 임의의 복잡한 양식 전체의 동일성은 현재 입증되지 않았습니다.

## 배포 권리와 출시 준비

런타임·pywin32·MCP SDK·선택 PDF 라이브러리 등 동봉 구성요소의 라이선스·고지·재배포 조건을 확인하고, 배포 파일 서명·해시·업데이트 검증 방법을 검토합니다. 보안 경고를 끄도록 안내하는 방식으로 서명·신뢰 문제를 우회하지 않습니다.

한컴은 개인 비상업 자동화 이용과 상업 이용의 조건을 구분합니다. 상업적 솔루션·앱 개발 이용에는 한컴 승인과 별도 라이선스가 필요하며, 소스 저장소의 공개 여부가 엔진·보안 DLL의 배포 권한을 주지는 않습니다. [한컴 자동화 공식 안내](https://developer.hancom.com/hwpautomation)

설치형 파일의 실제 출시, 로컬 연결 지원과 공개 플러그인 검토가 각각 완료된 뒤에만 해당 다운로드·연결·배포 상태를 README에 표시합니다.
