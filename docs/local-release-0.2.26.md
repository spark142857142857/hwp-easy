# 로컬 HWP Easy 0.2.26 오류 수정·진단 보완

[남은 작업](remaining-work.md) · [프로젝트 상태](project-status.md) · [원래 리뷰](code-review-2026-10-18.md)

2026년 10월 18일, [0.2.25 리뷰](code-review-2026-10-18.md)의 B1·B2를 수정하고 I1을 지원 프로필에서 보완했다. 기능 커밋은 `3f9cc48`이다. **소스·검증 패키지는 0.2.26이며 실제 Codex 설치는 0.2.25**, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다. 설치 갱신·새 채팅·포털 제출·공개 게시를 수행한 기록이 아니다.

### B1 저장 중단과 잠금

소유 파일이 들어 있는 디렉터리를 먼저 준비해 원자적으로 게시하고, 기존 버전과의 경쟁에는 원래 이름의 배타적 잠금 파일을 함께 사용한다. 잠금 파일도 완성된 메타데이터를 게시하므로 작성 도중 종료돼 빈 잠금만 남는 구간을 피한다. PID·호스트 이름 해시·고유 토큰으로 현재 호스트에서 종료된 소유자만 회수한다. 성공 응답의 `abandoned_lock_recovered:true`로 회수를 확인한다.

**이전 형식의 한계:** 0.2.25 이하의 소유자 없는 잠금 파일, 다른 호스트 기록, 살아 있거나 재사용된 PID, 검증할 수 없는 기록은 `DOCUMENT_BUSY`로 유지한다. 이 파일을 자동 삭제한 것으로 처리하지 않는다. 기존 버전의 남은 잠금 판별·안내와 공유 파일시스템 검증은 R3의 호환성 확인에 남긴다. 종료 전에 만들어 둔 원본 백업·임시 파일은 복구 근거로 보존한다.

### B2 개체 식별과 엄격 정책

문단 ID만으로 위험을 상쇄하지 않고 구역 안에서 유일한 개체 인스턴스를 함께 비교한다. 묶음에서 삭제한 그림의 위험은 새 그림이 같은 번호를 재사용해도 상쇄에 쓰지 않는다. 0 또는 중복 인스턴스처럼 식별이 불확실한 개체는, 엄격 정책의 변경 요청에서 기존 위험도 보수적으로 거부할 수 있다. 바이트가 같은 무변경 요청은 저장·백업을 만들지 않는다.

### I1 글상자 높이 추정

`FIXED_TEXT_BOX_MAY_EXCEED_PAGE_HEIGHT`를 추가했다. 세로·단일 단 용지에서 종이 위쪽을 기준으로 배치한 지원 본문 사각형의 글자 크기·줄바꿈·문단 간격과 남은 종이 높이를 비교한다. 기본 `report`는 경고를 반환하고, `reject_new_risk`는 새로운 추정 위험을 `NEW_LAYOUT_RISK`로 거부한다.

텍스트와 도형의 위치·크기를 임의로 바꾸지 않는다. 내부 여백·다른 기준/정렬·세로쓰기·정확한 폰트 메트릭·외부 한글의 자동 상자 확장은 인증하지 않는다. 이 보완은 고정 글상자 장문의 **위험 진단·선택적 저장 차단**이며 자동 크기 조정이나 모든 쪽 배치의 해결은 아니다.

종료 주입은 폐기 가능한 복사 runner에만 적용했고 이후 재시도·복구는 배포 원본과 바이트가 같은 runner로 수행했다. 일반 텍스트 엔진이 갱신하는 DocInfo의 파생 커서 위치 외에는 비대상 정의·내용·스트림을 독립 판독했다. 개인 문서는 사용하지 않았다. 이전 공개 12개·237쪽 검사를 이번 버전에서 다시 실행한 것으로 세지 않는다.

Windows·Linux의 [기능 커밋 CI](https://github.com/spark142857142857/hwp-easy/actions/runs/39110409969)는 10월 18일 자동 실행 중단 방침에 따라 취소 요청했다. 이후에는 [주요 단계에서 전체 CI를 수동 실행](developer-guide.md#검사)하며, 취소한 실행이나 로컬 통과를 새 Linux CI 통과로 기록하지 않는다.
