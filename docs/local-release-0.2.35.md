# 로컬 HWP Easy 0.2.35 검증 기록

[남은 F2](remaining-work.md#f2-세부-현황) · [지원 기능](supported-features.md#소스-0235-추가-기능) · [프로젝트 상태](project-status.md)

검증일: **2026년 10월 22일**. F2의 세로 병합·지원 복잡 꼬리말·후속 편집 자동 동기화를 추가했다. 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다. 설치·새 채팅·공개 게시는 이번 범위에 포함하지 않는다.

## 구현과 보존 범위

- **세로 병합:** 셀의 높이를 걸쳐 있는 행 높이의 합으로 계산한다. 복원 가능한 기존 행 높이를 유지하고 짧은 span부터 부족분만 늘린다. 셀별 높이·표 전체 높이·조상 높이가 서로 일치하도록 동기화한다. 격자와 병합 구조를 바꾸지 않는다.
- **이후 편집 자동 동기화:** 루트와 모든 중첩 표가 표준 흐름 프로필에 맞으면, 재열기 후 글·글자 크기·셀 문단 변경도 최종 저장 전에 높이를 다시 계산한다. 첫 `reflow_table` 뒤 같은 묶음에서 추가로 바꾼 내용도 반영한다. 비공개 스트림이나 외부 세션 상태를 추가하지 않는다.
- **원자성:** 계획 단계에서는 저장하지 않으며 편집과 동기화를 한 후보 파일·한 저장으로 처리한다. 지원하지 않는 동기화나 후속 연산 실패 시 원본과 백업 수를 유지한다. `table_auto_sync`가 확인한 루트와 실제 변경 여부를 보고한다.
- **복잡 꼬리말:** 여러 문단·혼합 글자 서식·지원 인라인 표·자동 쪽 번호·홀짝 적용 설정을 보존한다. 하단 보호를 늘린 만큼 첫 꼬리말 문단 간격을 보상하고 하위 줄 캐시를 무효화한다. 기존 정의는 수정하지 않고 필요한 문단 서식만 추가한다.

일반 표의 기존 줄바꿈 문단을 나중에 편집할 때 `INVALID_TEXT_RANGE`로 거부되던 경로를 보완했다. 지원 셀은 검증된 원시 편집 경로를 사용하고, 읽기 결과의 편집 가능 표시도 맞췄다. 셀 문단 삽입 뒤 같은 묶음의 원래 대상도 추적한다. 루트의 기존 인스턴스 ID로 후속 변화를 확인하며 모호한 중복 ID는 거부한다.

후속 교차 점검에서는 두 구역의 표를 섞어 편집할 때, 다른 표의 명시적 흐름 조정이 대기 중인 자동 동기화 기준을 덮어쓰는 결함을 재현했다. 처음 기록한 기준을 유지하도록 수정하고 두 구역의 독립 저장·복구·실제 쪽 배치를 회귀에 추가했다. 이미 공개한 기능 커밋 `b54dbec`은 보존하고 이 결함은 후속 수정 커밋으로 묶었다.

복잡 조회의 표 문맥은 이미 검사한 상태를 재사용한다. 일반 조회도 셀 해시·문단/개체 속성·흐름 문맥에서 같은 상태를 재사용해 중복 문서 해석을 줄였다.

## 계획 해시와 CI 보완

`verified_edit_sha256`은 파생 미리보기 갱신 전 검증된 편집 후보를, `output_sha256`은 갱신 후 실제 저장 파일을 식별한다. 5초 제한의 미리보기 worker가 계획에서는 성공하고 저장에서는 시간 초과되면, 본문이 같아도 미리보기 때문에 최종 파일 해시가 달라질 수 있다. 이 전환을 강제로 재현해 실제 worker 입력 바이트·편집 후보 해시가 같은지 검사하고, 후보가 다르면 계속 실패하도록 했다. 저장·버전 검사와 정확한 복구 계약은 유지한다.

기존 Windows 복합 CI는 302개 회귀를 통과했으나, 부동 개체 이동의 전체 파일 해시 비교 오류 뒤에도 다음 명령이 실행되다가 30분 제한으로 종료됐다. 해당 이동 12건은 로컬 재검사를 통과했다. 최종 검사는 후보 해시를 우선 대조하고, 미리보기 상태도 같으면 최종 파일 해시까지 대조한다. CI는 기존 모든 명령을 유지하면서 복합/부동 패키지 작업을 분할하고 명령마다 독립 단계로 만들어 첫 실패에서 멈춘다. 전체 수동 검사는 14개 작업이며 개별 편집/미리보기 제한은 늘리지 않았다.

흐름 13건은 이전 깊이 1–3/8·85줄, 후속 행, 가로 병합, 일반 꼬리말과 새 루트/중첩 세로 병합이다. 추가 11건은 서로 다른 두 구역의 표 혼합 편집과 재열기 후 깊이 1–3 편집, 루트 세로 병합, 한국어 중첩 세로 병합, 여러 문단·쪽 번호·인라인 표·짝수 쪽 번호/홀수 표 꼬리말이다. 짝수 꼬리말은 원본에도 실제 짝수 쪽을 만들어 적용과 위치를 비교했다. 개인 문서는 사용하지 않았다.

원시 레코드 검사는 셀 내용 변경과 상속 스타일을 독립적으로 대조한다. 꼬리말 내부 표/번호 컨트롤은 흐름 변경 마스크에서 제외해 원래 바이트가 유지되는지 확인한다. 자동 동기화의 글자 크기 변경·문단 삽입·비대상 본문 편집·높이 비축소와 미지원 꼬리말의 무저장은 별도 회귀에 포함한다.

최종 로컬 증거는 무시된 `outputs/f2-035-20261022/final-flow/`, `final-sync/`의 `cases.json`, `summary.json`, `independent-summary.json`, `native/results.json`, `native/summary.json`과 `final-tests.log`, `common-tests.log`다. `probe`, `v3`, `v4`, 이전 `flow-final`/`sync-final` 등 중간 결과는 최종 수치에 합산하지 않는다.

이전 `b54dbec`의 [첫 CI](https://github.com/spark142857142857/hwp-easy/actions/runs/39760550114)는 추가 결함 발견 후 중단했다. 이후 `f597296`의 [CI](https://github.com/spark142857142857/hwp-easy/actions/runs/39762761822)는 11개 성공·Windows 복합 작업 제한 시간 종료로 전체 미통과였다. 분할한 최종 소스에서 수동 CI를 실행하며, 앞선 실행을 최종 소스 통과로 기록하지 않는다. 검사 소스 커밋과 실제 결과는 [Source checks의 해당 커밋 실행](https://github.com/spark142857142857/hwp-easy/actions/workflows/checks.yml)과 로컬 `outputs/f2-035-20261022/ci-result.json`으로 연결한다. 한글 없는 CI와 Windows 한글 배치 검사는 별개다. 완료 후 CI 결과만으로 별도 문서 커밋을 추가하지 않는다.

## 남은 범위

가운데/아래 정렬 셀, 같은 호스트의 복수 표/뒤쪽 글, 아주 좁은 셀·혼합 크기·복잡한 문자 조형, 독립 부동 그림/글상자·미확인 필드/세로 꼬리말과 문단 개체 충돌 회피는 남는다. 현재 행 높이는 보수적 최소 공간이며 글을 줄인 뒤 자동 축소·빈 공간 최적화는 하지 않는다. 지원 단일 단·깊이·너비·문단/글자 지표와 높이 한도는 [0.2.34 기본 계약](local-release-0.2.34.md)을 유지한다. 대표 한글 배치는 확인했지만 외부 한글 버전 전체의 동일한 폰트/쪽 계산을 인증하지 않으며 `layout_verified:false`를 유지한다.
