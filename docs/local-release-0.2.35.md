# 로컬 HWP Easy 0.2.35 검증 기록

[남은 F2](remaining-work.md#f2-세부-현황) · [지원 기능](supported-features.md#소스-0235-추가-기능) · [프로젝트 상태](project-status.md)

검증일: **2026년 10월 22일**. F2의 세로 병합·지원 복잡 꼬리말·후속 편집 자동 동기화를 추가했다. 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다. 설치·새 채팅·공개 게시는 이번 범위에 포함하지 않는다.

## 구현과 보존 범위

- **세로 병합:** 셀의 높이를 걸쳐 있는 행 높이의 합으로 계산한다. 복원 가능한 기존 행 높이를 유지하고 짧은 span부터 부족분만 늘린다. 셀별 높이·표 전체 높이·조상 높이가 서로 일치하도록 동기화한다. 격자와 병합 구조를 바꾸지 않는다.
- **이후 편집 자동 동기화:** 루트와 모든 중첩 표가 표준 흐름 프로필에 맞으면, 재열기 후 글·글자 크기·셀 문단 변경도 최종 저장 전에 높이를 다시 계산한다. 첫 `reflow_table` 뒤 같은 묶음에서 추가로 바꾼 내용도 반영한다. 비공개 스트림이나 외부 세션 상태를 추가하지 않는다.
- **원자성:** 계획 단계에서는 저장하지 않으며 편집과 동기화를 한 후보 파일·한 저장으로 처리한다. 지원하지 않는 동기화나 후속 연산 실패 시 원본과 백업 수를 유지한다. `table_auto_sync`가 확인한 루트와 실제 변경 여부를 보고한다.
- **복잡 꼬리말:** 여러 문단·혼합 글자 서식·지원 인라인 표·자동 쪽 번호·홀짝 적용 설정을 보존한다. 하단 보호를 늘린 만큼 첫 꼬리말 문단 간격을 보상하고 하위 줄 캐시를 무효화한다. 기존 정의는 수정하지 않고 필요한 문단 서식만 추가한다.

일반 표의 기존 줄바꿈 문단을 나중에 편집할 때 `INVALID_TEXT_RANGE`로 거부되던 경로를 보완했다. 지원 셀은 검증된 원시 편집 경로를 사용하고, 읽기 결과의 편집 가능 표시도 맞췄다. 셀 문단 삽입 뒤 같은 묶음의 원래 대상도 추적한다. 루트의 기존 인스턴스 ID로 후속 변화를 확인하며 모호한 중복 ID는 거부한다.

복잡 조회의 표 문맥은 이미 검사한 상태를 재사용한다. 일반 조회도 셀 해시·문단/개체 속성·흐름 문맥에서 같은 상태를 재사용해 중복 문서 해석을 줄였다.

흐름 13건은 이전 깊이 1–3/8·85줄, 후속 행, 가로 병합, 일반 꼬리말과 새 루트/중첩 세로 병합이다. 추가 10건은 재열기 후 깊이 1–3 편집, 루트 세로 병합, 한국어 중첩 세로 병합, 여러 문단·쪽 번호·인라인 표·짝수 쪽 번호/홀수 표 꼬리말이다. 짝수 꼬리말은 원본에도 실제 짝수 쪽을 만들어 적용과 위치를 비교했다. 개인 문서는 사용하지 않았다.

원시 레코드 검사는 셀 내용 변경과 상속 스타일을 독립적으로 대조한다. 꼬리말 내부 표/번호 컨트롤은 흐름 변경 마스크에서 제외해 원래 바이트가 유지되는지 확인한다. 자동 동기화의 글자 크기 변경·문단 삽입·비대상 본문 편집·높이 비축소와 미지원 꼬리말의 무저장은 별도 회귀에 포함한다.

최종 로컬 증거는 무시된 `outputs/f2-035-20261022/verified-flow/`, `verified-sync/`의 `cases.json`, `summary.json`, `independent-summary.json`, `native/results.json`, `native/summary.json`과 `final-tests.log`, `common-tests.log`다. `probe`, `v3`, `v4`, 이전 `flow-final`/`sync-final` 등 중간 결과는 최종 수치에 합산하지 않는다.

이번 주요 단계에서 Windows/Linux 수동 CI를 한 번 실행한다. 검사 소스 커밋과 실제 결과는 [Source checks의 해당 커밋 실행](https://github.com/spark142857142857/hwp-easy/actions/workflows/checks.yml)과 로컬 `outputs/f2-035-20261022/ci-result.json`으로 연결한다. 한글 없는 CI와 Windows 한글 배치 검사는 별개다. 완료 후 CI 결과만으로 별도 문서 커밋을 추가하지 않는다.

## 남은 범위

가운데/아래 정렬 셀, 같은 호스트의 복수 표/뒤쪽 글, 아주 좁은 셀·혼합 크기·복잡한 문자 조형, 독립 부동 그림/글상자·미확인 필드/세로 꼬리말과 문단 개체 충돌 회피는 남는다. 현재 행 높이는 보수적 최소 공간이며 글을 줄인 뒤 자동 축소·빈 공간 최적화는 하지 않는다. 지원 단일 단·깊이·너비·문단/글자 지표와 높이 한도는 [0.2.34 기본 계약](local-release-0.2.34.md)을 유지한다. 대표 한글 배치는 확인했지만 외부 한글 버전 전체의 동일한 폰트/쪽 계산을 인증하지 않으며 `layout_verified:false`를 유지한다.
