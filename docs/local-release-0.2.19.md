# 로컬 0.2.19 변경과 검증

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [개발 가이드](developer-guide.md)

2026년 10월 13일의 로컬 메인 검증 기록입니다. 세 클라이언트는 같은 실행기와 `@rhwp/core` 0.8.6 WASM을 사용합니다. HWP Easy 서버와 한컴 설치 없이 편집하며 스킬은 명시적으로 호출합니다. 한컴 비교는 결과 확인용 검사로, 실행 의존성이 아닙니다.

## 변경 사항

복잡한 문서의 대상 매핑을 문단·제어·셀 경로로 확인하도록 바꿨습니다. 머리말·꼬리말·글상자·일부 그룹 개체를 보존하면서 검증된 본문·셀을 수정할 수 있습니다. 모델과 원시 텍스트가 일치하지 않는 개별 블록에는 편집 ID를 주지 않으며, 전체 개체를 읽었다고 표시하지 않습니다. 텍스트가 같다는 이유로 다른 위치를 고르지 않습니다.

검증된 복잡한 본문과 2·3단 중첩 셀 문단에 정렬, 줄 간격, 좌우 여백, 들여쓰기, 앞뒤 간격 변경을 추가했습니다. 기존 줄 간격 방식과 공유 서식 정의는 유지하고 선택 문단에 파생 정의를 적용합니다. 중첩 표의 행·열 구조 변경은 지원하지 않습니다.

내용 검증이 끝나면 내장 `PrvText`를 최대 4,096 UTF-16 단위로 갱신하고 첫 쪽을 긴 변 180픽셀 이하의 24비트 BMP `PrvImage`로 만듭니다. 썸네일 전용 resvg WASM과 NanumGothic Regular를 배포하며 문서 글꼴 정의와 시스템 폰트는 바꾸지 않습니다. 글꼴 대체와 미지원 렌더링 요소가 있어 최종 조판 인증은 아닙니다.

썸네일 작업은 별도 프로세스에서 5초 시간 제한과 256 MiB JS 힙 제한을 적용합니다. 힙 제한은 전체 WASM 메모리 한도를 뜻하지 않습니다. 실패하면 갱신된 텍스트와 실패 상태를 반환하고 오래된 이미지는 비웁니다. 내용 검증을 통과한 저장은 유지합니다. 변화 없는 요청은 캐시도 재생성하지 않으며 복구는 이전 캐시를 포함한 원본 바이트 전체를 되살립니다. 썸네일 시간 제한을 강제로 발생시켜 빈 이미지 스트림의 올바른 종료 위치, 정상 재읽기·저장·복구와 계획/저장 해시 일치도 검사했습니다. 초기 CI에서 발견한 빈 스트림 할당 오류는 공개 릴리스 전에 수정했습니다.

CFB 재배치가 필요한 연속 편집에서도 기존 스크립트·문서 옵션·요약·이미지 등 비대상 스트림을 유지하도록 로컬 쓰기 경로를 보완했습니다. 각 단계에서 압축된 비대상 바이트를 비교합니다. 보관한 원격 Worker에는 적용하지 않습니다.

## 공개 양식

상위 프로젝트의 고정 커밋 [`1a76570e833917d15817415a53c09ad61ab3203f`](https://github.com/edwardkim/rhwp/tree/1a76570e833917d15817415a53c09ad61ab3203f)의 공개 HWP 12개를 SHA-256으로 고정했습니다. 원본은 유지하고 새 검사 폴더의 사본을 수정했습니다. 개인 문서는 사용하지 않았습니다.

이전 검사는 4개 문서의 선택 편집과 8개의 부분 읽기를 확인했습니다. 0.2.19는 **12개 모두에서 각각 검증 가능한 한 대상**의 수정·같은 사본 저장·정확한 복구를 통과했습니다. 12개 모두 새 미리보기 텍스트와 BMP를 생성했습니다. 모든 블록·그룹·누름틀·문서 구조를 편집할 수 있다는 뜻은 아닙니다.

독립 Python 검사는 수정 범위, UTF-16 텍스트, 비대상 제어와 압축 스트림, 미리보기 형식, 복구 후 원본 해시를 확인했습니다. [Node 검사](../scripts/check-local-public-corpus.mjs)와 [독립 판독](../scripts/check-local-public-corpus.py)으로 재검사할 수 있습니다.

## 배치 확인

기존 등록된 보안 모듈과 한컴 자동화 API의 소유한 숨김 인스턴스로 공개 사본을 읽고 BMP를 생성했습니다. 레지스트리 변경·모듈 설치·한컴 재저장·일반 파일 선택의 computer-use는 수행하지 않았습니다.

| 대표 문서 | 비교 범위 | 관측 |
| --- | --- | --- |
| 누름틀 양식 | 수정 전후 3쪽씩 | 3쪽 유지. 수정 값과 여러 줄 입력에 따른 항목 이동 확인. 다른 두 쪽 픽셀 일치 |
| 중첩 표 양식 | 수정 전후 8쪽씩 | 8쪽 유지. 앞 세 쪽 픽셀 일치. 답변이 늘면서 뒤쪽 항목이 다음 쪽으로 이동하는 배치 확인 |
| 합성 원본 | 1쪽 | 한컴 읽기·렌더링 성공 |

총 23쪽 이미지를 생성하고 11쌍을 비교했습니다. 빈 스트림 수정이 포함된 최종 패키지로 23쪽을 다시 렌더링했고, 앞서 비교한 이미지와 모든 픽셀이 일치했습니다. 대표 변경 화면을 확인했으며 모든 글꼴·페이지의 조판 인증이나 임의 문서 지원으로 확대하지 않습니다.

## 회귀와 배포

로컬 회귀 353개와 업데이트를 포함한 설치 검사 17개가 통과했습니다. 마지막 미리보기 정렬·무변경 수정은 관련 검사 19개와 설치본 검사로 다시 확인했습니다. 새 매핑·문단 서식·미리보기 검사를 Linux·Windows CI 목록에 추가했습니다.

배포 코드 `ef12b12`의 [CI 10개 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38343187666)이 모두 통과했습니다. Linux·Windows에서 로컬 회귀, 복잡한 개체, 두 개인 스킬 패키지, 대용량·검색 검사와 보관한 Worker 회귀를 실행했습니다. 각 검사 결과를 실제 앱 모델 호출이나 최종 조판 인증과 혼동하지 않습니다.

한 요청에서 80,000 코드 포인트를 삽입하는 대용량 검사 6개도 통과했습니다. 실제 UTF-16 단위 80,825개, 전체 원시 텍스트·혼합 서식, 읽기 페이지 조합, 계획 무저장, 같은 파일 저장과 정확한 복구를 별도 판독으로 확인했습니다. 썸네일은 시간 제한에 따라 생성하거나 실패 상태와 함께 비우며, 대용량 문서의 최종 쪽 배치를 인증한 검사는 아닙니다.

합성·공개 사본, 앱 실행 기록과 한컴 결과는 ignored `outputs/progress-20261013/`에 보관합니다. 계정 정보가 들어갈 수 있는 원시 호스트 로그는 공개하지 않습니다. ZIP은 실행 자원·지침·고지·빌드 명세만 포함합니다.

[공개 사전 릴리스](https://github.com/spark142857142857/hwp-easy/releases/tag/hwp-easy-local-v0.2.19)에 Codex·Claude Code·Cursor ZIP과 체크섬을 게시했습니다. 게시 후 인증 정보 없이 세 ZIP과 체크섬을 내려받아 앞서 새 설치를 검증한 패키지와 SHA-256이 같음을 확인했습니다. 디렉터리 승인과는 별개이며 포털 진행 상태는 [프로젝트 상태](project-status.md)와 [로컬 등록 기록](local-directory-submission.md)을 따릅니다. 원격 0.1.9 코드와 ZIP은 보관하며 Cloud는 후순위입니다.
