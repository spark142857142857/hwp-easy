## 구현과 보존 범위

호스트 문단을 글/표/인라인 개체별로 나눌 때 **ClickHere 시작·끝을 같은 조각에 유지**한다. 필드 값·이름·안내·ID와 UTF-16 글/서식을 보존하고, 새 문단의 코드 포인트 범위와 원시 UTF-16 범위를 각각 대조한다. 빈 값의 짧은 안내 표시에 한 줄을 보수적으로 추가 예약하고 긴 안내는 저장 전에 거부한다. 혼합 서식과 한글/보조 문자 앞뒤의 범위 이동을 검사한다. 필드가 표나 그림을 감싸면 분할 전에 거부한다.

회전 없는 지원 인라인 그림과 단순 사각형 글상자는 **원래 앵커 순서의 별도 문단**에 둔다. 줄 간격 영향(`affectLineSpacing`)을 켜고 충분한 너비·쪽 높이를 검사한다. 그림 크기·crop·이미지 스트림, 글상자 틀·내부 글과 서식 및 나머지 흐름 설정은 보존한다. 단순 글상자는 여백 없는 한 문단·짧은 한 줄·보통 글자 지표와 들어갈 공간을 요구한다.

분할된 원래 호스트 문단 대상은 무효화한다. 필드·글상자와 내부 문단은 원래 레코드를 따라 추적해 같은 편집 묶음에서도 수정할 수 있다. 그림은 새로 읽어 새 호스트 대상과 그림 번호를 선택한다. 중첩 필드의 장문 입력은 조상 높이를 동기화하고, 본문 필드는 reader의 일반 문단 흐름을 따른다. 재열기 후 그림 크기·글상자 내용 변경도 동기화 검사에 포함한다. 고정 틀을 넘는 글상자 편집과 뒤늦은 기대 값 오류는 파일·이력을 바꾸지 않는다.

기존 표/깊이/작업량/높이 한도를 유지한다. 분할 호스트는 제어 앵커 64개·필드 32개·인라인 그림/글상자 16개로 제한한다. 다른 필드 종류·컨트롤을 감싼 필드·그룹/회전/독립 부동 개체·복잡한 글상자 내부는 추가 범위다. 추가 외국어 조형 D3는 최후순위로 유지한다.

네이티브 QA는 HWP를 저장하지 않는다. 원래 페이지·복구 픽셀을 먼저 만들고 메모리의 글자 색으로 글/표 순서를 구분한다. 기존 색과 같은 빈 누름틀 안내 표시는 답변 잉크로 집계하지 않는다. 실제 그림은 원래 이미지의 알려진 색 패턴·크기·가로 원점으로 찾고 글상자는 원래 테두리와 내부 글을 대조한다. 그림 표시 영역은 래스터 처리의 약 2픽셀 경계를 감안하며, 검색 성공만으로 표시 완료를 판정하지 않는다.

한글 `GetFieldText`는 문단 내부 LF를 생략하므로 값 대조와 별도로 독립 UTF-16 레코드·전체 네이티브 글·실제로 보이는 필드 줄을 검사한다. 좁은 셀에서 검사용 색 변경이 재조판에 영향을 주는 F3 경계는 유지하며, 이번 지원 프로필 검증을 모든 reader의 동일한 조판 보장으로 해석하지 않는다. `layout_verified:false`다.

최종 증거는 무시된 `outputs/f2-039-20261022/shipped-controls/`, `shipped-text/`의 `cases.json`, `summary.json`, `independent-summary.json`, `native/results.json`, `native/summary.json`, `native-input-match.json`과 `shipped-source.log`와 `verified-complex-tests.log`에 보관한다. 기존 표 사례는 동일한 바이트의 0.2.38 네이티브 증거를 연결하며 새 사례와 중복 합산하지 않는다. 조사/중간 결과와 개인 문서는 수치에 포함하지 않는다.

수동 `scope:table-controls`는 기존 글/호스트 작업을 재사용해 관련 Windows/Linux **2개 작업**만 실행한다. 기존 전체 **18개 작업**은 유지하며 이번에 실행하지 않는다. 검사 커밋·실제 실행 결과는 [Source checks](https://github.com/spark142857142857/hwp-easy/actions/workflows/checks.yml)와 로컬 `outputs/f2-039-20261022/ci-result.json`에 연결한다.
