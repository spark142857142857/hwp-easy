## 실제 호출과 배치

앞선 0.5.1의 새 Codex 채팅에서 일반 본문과 두 문단 셀, 65줄 중첩 표, 그룹 내부 글과 필드 및 하위 그룹 편집을 검사했습니다. 최초 필드 요청 두 건은 B7로 저장 전에 거절됐고, 항목 순서를 맞춘 뒤 저장과 복구를 통과했습니다. 실패 기록을 보존했으며 이번 패치에서는 해당 순서 제한을 제거했습니다.

당시 실제 한글에서 원본과 편집본 및 복구본 9개 파일과 10쪽을 확인했습니다. 복구 3쪽의 픽셀이 같았고 중첩 표는 1쪽에서 2쪽으로 이어져 두 번째 쪽은 L038부터 시작했습니다. 그룹 내부 글 4개도 표시됐습니다. 0.5.2의 B7 출력은 이 배치 검증 파일과 바이트가 같습니다.

0.5.2에서는 설치된 실행기를 검사했으며 세 앱의 모델 호출을 모두 반복한 것은 아닙니다. Claude Code와 Cursor CLI의 이전 실제 호출과 Cursor 마지막 응답의 사용량 제한은 [당시 기록](https://github.com/spark142857142857/hwp-easy/blob/baad6d4513b9918bd718bb5f1f3beb5027d43edb/docs/unified-release-0.5.1.md)을 따릅니다. 새 Codex 채팅의 상세 결과는 [0.5.1 기록](https://github.com/spark142857142857/hwp-easy/blob/baad6d4513b9918bd718bb5f1f3beb5027d43edb/docs/local-install-0.5.1.md)에 있습니다.

## 배포 자원과 경계

실행기 SHA-256은 `fcb97619d81eb83dd77a056f5321da9868855305ace05ff5b2e0439d3084457f`, HWP WASM은 `8000e4ce320b7994dca6bcd58be0c862144c7b805576504e523a420439da658b`입니다. 공개 파일의 전체 해시는 [릴리스의 SHA256SUMS](https://github.com/spark142857142857/hwp-easy/releases/tag/hwp-easy-local-v0.5.2)를 확인합니다.

첫 CI의 검사 커밋은 `baad6d4513b9918bd718bb5f1f3beb5027d43edb`입니다. 두 Windows 작업은 22분과 18분 한도에 걸려 취소됐고, 제품 코드를 유지한 채 Windows 한도를 30분으로 조정해 해당 2개만 재검증했습니다. 재검증 커밋과 첫 커밋의 `src`, `packages`, `plugins`, `tests`는 같습니다.

이후 문서 정리는 로컬 링크 검사로 확인하며 CI 커밋과 후속 문서 커밋을 구분합니다. 이번 패치와 문서 정리에서 computer-use는 사용하지 않았습니다.

다른 PC, Cursor IDE와 Cloud 전체 흐름, 모든 문서 구조의 인쇄 배치를 인증하지 않습니다. `layout_verified:false`와 지원 밖의 경고를 유지합니다. 원격 0.1.9와 Windows COM은 보관 상태입니다.

로컬 상세 근거는 ignored `outputs/release-0.5.2-20261028/`에, 이전 검증 사본은 로컬 보관 인덱스에 정리합니다. 개인 문서와 인증 정보 및 원시 호스트 로그는 공개 릴리스에 포함하지 않습니다.
