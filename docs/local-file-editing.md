## 자주 쓰는 양식과 여러 줄 답변

로컬 패키지 후보 **0.2.15**는 누름틀이나 중첩 표, 그림 그룹이 있는 문서에서 선택한 글자의 서식을 변경할 수 있다. 굵게, 기울임, 밑줄, 취소선, 크기, 색, 글꼴을 지원한다. 문서별 조건과 시험 결과는 아래에 정리했다.

0.2.19의 구조 기반 대상 매핑, 복잡한 문단 서식, 내장 미리보기 갱신과 연속 저장 보존은 [현재 검증 기록](local-release-0.2.19.md)을 따릅니다. 아래 캐시 미갱신·미지원 항목은 각 이전 버전 당시의 기록입니다.

## 복잡한 문서의 글자 서식

`format_text`는 실제 본문, 안쪽 셀 대상 또는 누름틀 ID를 받는다. 누름틀 ID에서는 `expected_old`가 필드 값 전체이고 범위는 값 기준 유니코드 코드 포인트다. 블록 ID에서는 블록 전체 텍스트와 그 기준 범위를 쓴다. 읽기에 반환되는 `style.character_runs`는 항상 블록 기준이며 각 구간의 실제 글자 속성을 포함한다. 이모지 양쪽 UTF-16 단위와 LF의 스타일을 확인한다. 탭 또는 필드, 표, 그림 앵커를 가로지르는 범위는 저장 전에 거부한다.

기존 글자 정의와 비대상 스타일 ID를 그대로 두고 요청된 속성만 파생 정의에 반영한다. 글꼴은 일곱 언어별 이름을 재사용하거나 검증 가능한 동일 크기 글꼴 표에 추가하며 실제 폰트 파일은 설치하지 않는다. 선택 문단의 스타일 개수와 줄 캐시만 갱신한다. 정의 증가에 필요한 로컬 CFB 재배치 이후 독립 판독으로 스트림 목록, 모든 다른 압축 스트림 바이트, 요청 결과를 검사한다. 원래 필드, 표, 그림 기록과 다른 본문은 유지하며 반복 요청은 동일 바이트이면 저장, 복구 사본을 만들지 않는다. 기존 미리보기 캐시는 그대로 두므로 최신 내용은 본문 재읽기로 판정한다.

[단위 검사](../tests/test_local_complex_format.mjs) 24개는 혼합 서식, 필드 상대 범위, 2/3단 중첩 셀, 그룹 그림 보존, 여러 줄/이모지, 기존/새 글꼴, 잘못된 요청, 묶음 실패 무저장, 비압축 DocInfo의 4096바이트 경계 증가를 확인한다. [분리 패키지 검사](../scripts/check-local-complex-format.mjs)는 합성 11건과 `testdocs/` 3개 양식 사본의 16건에서 계획 무저장, 같은 파일 저장, 전체 재읽기, 반복 무저장, 정확한 복구를 통과했다.

실제 원본에 복잡한 객체는 없어 사본에 합성 누름틀, 중첩 표, 그룹 그림을 넣어 시험했다. [독립 Python 검사](../scripts/check-local-complex-format.py)는 두 집계의 모든 기존 정의, 비대상 압축 스트림, UTF-16 스타일과 제어 기록을 확인했다. 개인 원본, 파일명, 본문, 해시는 출력/전송하지 않았으며 비공개 결과는 ignored `outputs/common-forms-20261011/complex-format-real/`에 보관한다. 전체 로컬 단위 333개, 공통 엔진 34개와 기존 분리 패키지 흐름도 통과했다.

이 후속은 글자 서식 확장이다. 복잡한 문단의 새 문단 생성, 누름틀 생성/수식, 중첩 표의 구조, 문단/표 서식 변경, 그룹 자식 그림 교체 및 외부 한글의 최종 페이지 배치는 후속 범위다. computer-use 없이 파일 검사로 완료했고 원본, 운영 Sites, 심사 제출본은 변경하지 않았다.

이전 **0.2.14**는 누름틀 값과 중첩 셀의 범위 수정에 여러 줄, 빈 줄을 허용한다. 복잡한 객체 경로에서는 LF를 **같은 문단 안의 HWP 문자 제어 10**으로 저장한다. 필드 경계, 표, 그림 앵커와 기존 문단 수를 유지하며, 해당 문단의 줄바꿈 비트만 실제 결과에 맞춰 갱신한다. 한 번 넣는 값은 최대 100줄이고 다른 입력 제어 문자는 거부한다. 일반 본문과 셀의 여러 문단 생성 경로와 구분한다.

일반 문단의 `text_range_editable`은 보이는 문구뿐 아니라 실제 raw 기록을 확인한다. 구역 설정이 붙은 첫 문단은 한 줄 제목 교체가 가능하더라도 부분 수정 후보로 표시하지 않는다. 에이전트는 지원 제목에 `replace_text`를 쓰고 여러 문단 답변은 적합한 다음 본문과 셀에 넣는다. 사전 검사는 실제 요청의 저장 가능 여부를 계속 확인한다.

세 `testdocs/` 양식의 413개 raw 문단을 72개 편집 조건 유형으로 분류했다. 대표 위치의 초기 사전 검사 195개 중 186개가 통과했고, 구역, 표 앵커 등이 있는 위치의 9개 작업은 저장 없이 거부됐다.

이후 [양식 검사](../scripts/check-local-common-forms.mjs)의 지원 유형 **68개**에 세 문단 합성 답변을 넣어 무저장 계획, 같은 사본 경로 저장, 전체 재읽기, 정확한 바이트 복구를 확인했다. [독립 Python 판독](../scripts/check-local-text.py)도 68개 결과의 문단, 모든 UTF-16 서식, 비대상 기록, 스트림을 검사했다.

첫 문단 제목 교체 두 건도 저장, 전체 재읽기, 복구를 통과했다. 413개 위치 모두를 수정한 결과나 의미에 맞는 모든 칸의 인증으로 간주하지 않는다.

이 검사는 `node scripts/check-local-common-forms.mjs outputs/common-forms-check --testdocs`로 명시적으로 실행한다. 실제 파일 이름, 내용, 해시를 출력하거나 전송하지 않으며 결과는 ignored `outputs/` 안에만 보관한다. 이번 기록은 `outputs/common-forms-20261011/`에 있다. 모든 원본은 그대로이고 한글, 브라우저 자동 조작은 사용하지 않았다. 파일 편집, 저장에는 computer-use가 필요하지 않으며 실제 쪽 배치 문제가 있을 때 별도로 확인한다. 이번 여러 줄 결과의 외부 뷰어 배치는 미검증이다.

전체 로컬 회귀 **309개**와 공통 엔진 **34개**가 통과했다. 갱신한 분리 패키지는 합성 복잡한 객체 **16개**와 실제 양식 복사본의 **19개** 사례를 저장, 재열기, 복구하고 독립 Python으로 비교했다. 실제 양식에는 해당 객체가 없어 합성 누름틀, 중첩 표, 그림 그룹을 추가한 검사이며, 기존 양식의 68유형 검사와 구분한다. ZIP의 17개 파일, 실행기와 WASM 해시를 확인했다. 로컬 실행 후보를 만든 것이며 전역 설치, 운영 Sites, 심사 제출본은 변경하지 않았다.

## 누름틀과 중첩 표, 그림 그룹 편집

로컬 후보 **0.2.13**은 `read`에서 누름틀 `fields`, 그림 `picture_groups`와 중첩 셀의 `cell_path`를 반환한다. 동일 이름의 필드는 이름 대신 반환된 필드 대상 ID와 기존 전체 값을 사용한다.

누름틀 값 수정, 비우기는 `set_field`, 안쪽 셀의 부분 수정은 `splice_text`, 그룹 전체 이동은 `move_picture_group`, 자식 그림 하나의 자르기는 `crop_group_picture`이다. 작업 형식은 [로컬 요청 형식](../plugins/hwp-easy/skills/edit-local-hwp/references/requests.md)에 설명한다.

사용자가 내부 JSON을 작성할 필요는 없다.

본문과 표 셀의 경로를 최대 8단계까지 순회하고 raw 문단 순서, 텍스트와 대응한다. 3단계 표와 그룹 안 그룹의 네 그림 선택을 합성 회귀에서 검사했다. 누름틀의 시작, 종료 앵커를 유지하고 혼합 서식의 남은 모든 UTF-16 단위는 같은 글자 스타일 ID를 유지한다. 치환한 글자는 처음 삭제한 글자의 서식을 상속한다. 일반 범위 수정이 필드나 표, 그림 앵커를 가로지르면 저장하지 않는다. 같은 값으로 수정하면 파일, 시각, 복구 사본을 다시 쓰지 않는다.

그룹 이동은 바깥 개체의 가로, 세로 오프셋만 바꾸며 크기, 변환 행렬, 자식 관계를 유지한다. 그룹 그림 자르기는 명시적 자식 번호의 네 crop 값만 바꾸며 다른 그림과 모든 이미지 스트림을 유지한다. 그림 그룹의 크기 변경, 회전, 이미지 교체, 필드 생성, 삭제, 수식/외부 연결 실행, 중첩 표 행, 열 변경과 복잡한 문서의 문단 구조, 새 서식 정의 추가는 지원하지 않는다. 복잡한 객체가 있는 문서는 해당 선택 편집 경로를 사용하며 일반 구조 작업으로 우회하지 않는다. 캡션, 머리말 등 비셀 목록은 이 경로에서 거부한다. 본문/셀 텍스트의 대응 성공을 모든 개체 내용의 완전 읽기로 표시하지 않는다.

[패키지 검사](../scripts/check-local-complex.mjs) 11개와 세 `testdocs/` 양식 복사본의 14개 사례가 무저장 계획, 같은 경로 저장, 재열기, 검색, 원래 바이트 복구를 통과했다. 원본에는 필드, 중첩 표, 그림 그룹이 없어 복사본에 합성 객체를 추가했다. [독립 Python 검사](../scripts/check-local-complex.py)는 OLE 스트림을 별도로 판독해 선택 범위, 스타일 앵커, 줄 캐시 또는 이동/crop 값 이외의 모든 기록과 스트림이 정확히 같음을 검사했다.

비공개 사례, 집계는 ignored `outputs/complex-20261011/real-inline/`에 보관한다. 기존 `PrvText`/`PrvImage` 미리보기 캐시도 그대로 보존하며 새 내용의 판정에는 실제 본문 재열기를 사용한다. 원본, 운영 Sites, 심사 제출본은 변경하지 않았다. 고정 엔진의 경로 기반 API와 원시 보존 검사는 설치된 `@rhwp/core 0.8.6`에서 실행했으며, 경로 좌표는 [상위 프로젝트의 경로 계약](https://github.com/edwardkim/rhwp/issues/2717)을 참고했다.

한글 2020의 100% 화면에서 합성 누름틀 수정본과 중첩 표, 두 JPEG 그림 그룹의 수정 전후를 비교했다. 수정한 값, 안쪽 셀의 관계와 자식 그림 표시를 확인했고 한글에서 파일을 저장하지 않았다. 최초 비인라인 중첩 시험 파일은 겹침이 있어 시각 검증 실패로 기록하고 인라인 표 시험 파일로 수정해 재검사했다. 전체 페이지, 글꼴, 이모지 글리프와 임의 기존 복잡한 객체의 배치 인증은 아니다.

## 문구 검색과 혼합 서식 문단 삭제

로컬 후보 **0.2.12**는 본문과 표 셀의 문구를 정확한 대소문자, 문자열로 찾아 버전별 대상 ID, 코드 포인트 범위와 짧은 문맥을 반환한다. 이모지와 내부 읽기 조각 경계를 넘는 문구도 실제 범위로 찾는다. 기본 50개, 최대 200개 결과를 같은 해시, 검색어의 cursor로 이어 받을 수 있다. 검색은 저장하지 않으며 본문과 셀 밖의 지원하지 않는 개체는 별도로 보고한다. 문단과 셀을 가로지르는 검색, 정규식과 Unicode 정규화 검색은 포함하지 않는다. 수정은 전체 대상 텍스트를 다시 읽고 기존 계획, 저장 검사를 사용한다.

다른 서식이 섞인 일반 문단을 삭제할 때 불필요한 단일 서식 제한도 제거했다. 본문과 셀의 두 번째 이후 문단에서 요청한 문단만 제거하고, 남은 문단의 모든 서식, raw 레코드, 셀 수를 비교한다. 첫 셀 문단과 숨은 제어가 있는 문단의 삭제 제한은 유지한다.

검색 회귀 18개와 혼합 삭제 회귀 2개를 포함한 전체 로컬 회귀 280개가 통과했다. 다른 파일 버전이나 검색어의 cursor는 엔진 생성, 문서 조회 전에 거부한다. 분리 패키지의 텍스트, 문단 42개와 검색→범위 수정→저장→복구 4개 및 세 `testdocs/` 복사본의 검색, 수정 5개를 독립 Python/raw 판독했다. 검색의 모든 페이지를 한 번 조회한 결과와 비교하고, 파일의 바이트, 수정 시각이 그대로임을 확인했다. 혼합 삭제도 실문서 복사본 다섯 위치에서 정확한 복구와 남은 문단의 모든 raw 바이트, 서식 보존을 독립 판독했다.

원본은 변경하거나 전송하지 않았다. Windows의 이전 CI는 긴 글 검사에서 전체 12분 job 제한으로 중단됐다. Linux와 Windows의 긴 글/검색 패키지 검사를 별도 12분 작업으로 분리했다. 0.2.12 커밋의 [여섯 CI 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38119071548)은 모두 성공했다.

최종 조합 검사에서는 같은 세 실문서 복사본의 본문과 셀 다섯 위치에 문단 복제→부분 수정→정렬, 여러 문단 삽입→글자 서식→정렬, 셀의 여러 문단→병합 표 폭→셀 여백, 정렬→표 간격을 적용했다. 12개 묶음, 38개 작업의 한 번 저장 결과는 개별 재조회, 저장한 결과와 모든 decoded 스트림이 같았고, 독립 Python의 작업별 raw 검사 38개와 원래 바이트 복구가 통과했다. 한글 2020의 실문서 사본 두 화면에서 병합 셀의 세 문단, 주변 표 경계와 본문의 가운데 정렬, 파란 굵은 기울임, 남은 혼합 서식을 확인했다. 이번 개선의 집중 화면 검사는 총 14개이며 전체 문서의 모든 쪽 배치를 인증한 결과는 아니다.

최종 ZIP의 17개 파일을 실제로 별도 폴더에 풀고 manifest의 실행기, WASM 해시를 대조했다. 추가 `node_modules` 없이 같은 다섯 실문서 위치에 부분 수정, 글자 서식, 문단 복제를 묶어 저장한 뒤, 읽기 전용 검색과 이력, 이전 버전 복구와 편집본 재복구의 정확한 바이트 왕복을 확인했다. 낡은 해시의 편집과 다른 검색어 cursor도 저장 없이 거부됐다. 합성 일반/병합 표 두 회귀는 두 그림을 유지한 표 폭 변경→전체 표 이동→선택 그림 회전→셀 여백→다른 칸 수정을 한 번 저장하고, 두 번째 단계의 오래된 그림 속성 실패 시 전 작업이 무저장임을 확인한다.

## 문단 복제와 로컬 복구 이력

로컬 후보 **0.2.11**은 일반 본문과 셀 문단을 바로 뒤에 복제하며, 전체 텍스트, 혼합 글자 서식, 문단 속성을 유지한다. 빈 문단도 지원하고 새 문단의 인스턴스 값과 셀의 문단 수를 검사한다. 첫 읽기의 원래 대상은 일괄 작업 안에서 추적하고 새 복사 문단은 다시 읽어 선택한다. 숨은 제어, 기존 LF, 탭이 없는 100,000 UTF-16 단위 이내의 대상에 적용한다.

선택한 파일의 현재 해시로 이전 저장본을 읽기 전용 조회하는 `history`도 추가했다. 사본의 소속 경로, 실제 바이트 해시를 확인하고, 다른 문서, 손상, 누락, 링크된 사본은 반환하지 않는다. 기본 10개, 최대 50개, 디렉터리 2,048개 항목과 실제 사본 100개 검사의 유한 범위를 사용한다. 조회는 폴더나 파일을 만들지 않으며 복구는 사용자 요청에 따라 별도로 수행한다. 기록 시각과 오래된 metadata 파일 수정 시각은 로컬에서 바뀔 수 있어 불변 기록이나 자동 undo stack으로 표현하지 않는다.

문단 복제의 새 회귀 10개와 복구 이력 회귀 15개를 포함한 전체 로컬 회귀 258개가 통과했다. 분리 패키지의 텍스트, 문단 40개와 세 `testdocs/` 복사본의 복제 5개도 무저장 계획, 같은 파일 저장, 정확한 복구 및 독립 Python/raw 서식 판독을 통과했다. 한글 2020의 합성 본문과 셀 두 화면에서 복제된 혼합 서식과 표 경계를 확인했다. 모든 원본은 그대로이며 전체 쪽 배치 인증은 아니다.

## 긴 혼합 서식 문장의 처리

로컬 후보 **0.2.10**은 원시 HWP의 전체 텍스트, 서식 구간과 모델 좌표를 맞춘 뒤, 중복된 글자별 엔진 조회를 줄인다. 기존 글자마다의 UTF-16 서식 레코드 보존과 요청한 정의 변경 검사는 유지한다. 구간 경계, 중간 모델 값이 다르거나 단순 텍스트 구조의 근거가 부족하면 기존 전체 검사로 돌아간다. 로컬 실행에서만 켜며 운영 원격 경로의 기본값과 검사, 입력 한도는 유지한다.

같은 합성 8만 자 삽입의 로컬 측정은 7,599ms에서 2,092ms로 줄었다. 4천, 2만, 8만 자 세 결과의 모든 decoded 스트림은 개선 전과 동일했다. 이 측정은 해당 PC의 합성 사례이며 일반 양식이나 운영 서버의 속도 보장은 아니다. 전체 로컬 회귀 233개, 공통 엔진 34개, 기존 보수적 스타일 검사 5개와 별도 증명/대체 경로 검사 5개가 통과했다.

분리 패키지의 본문과 셀에 80,000 코드 포인트(80,825 UTF-16 단위)를 넣은 6개 사례는 이어 읽기의 정확한 조립, 서식 변경, 분리, 병합, 무저장 계획, 같은 파일 저장, 복구와 독립 raw 판독을 통과했다. 세 실문서 복사본의 본문과 셀 다섯 위치에는 2만 코드 포인트의 합성 답변을 넣고 서식 변경, 분리, 병합, 정확한 복구 15개를 독립 raw 판독으로 확인했다. 한글 2020의 한 실문서 사본에서는 긴 답변의 파란 굵은 기울임 서식과 남은 검정 글자, 24쪽 결과 중 표시된 한 쪽을 확인했다. 모든 24쪽을 비교한 검사는 아니다.

## 문단과 표의 위치 이동

로컬 후보 **0.2.9**는 일반 본문 문단과 지원 표 전체를 같은 구역의 본문 문단 뒤로 옮긴다. 혼합 글자 서식, 표의 병합, 셀 내용, 크기와 지원 셀 그림을 전체 raw 그룹으로 보존한다. 처음 읽은 원래 대상과 이동 기준 ID를 한 묶음 안에서도 추적하므로, 옮긴 문단, 칸을 이어서 수정할 수 있다. 이미 원하는 위치이면 바이트, 수정 시각, 복구 파일을 바꾸지 않는다.

새 이동 회귀 20개와 동일 바이트 저장의 충돌 검사, 분리 패키지 8개 및 세 `testdocs/` 복사본의 7개가 통과했다. 독립 Python/olefile은 순서가 바뀐 전체 레코드 그룹을 비교하고, 본문 목록 끝 비트만 정규화해 나머지 바이트와 다른 모든 스트림의 정확한 보존을 확인했다. 실문서 7개는 본문 이동 5개와 한 양식의 원래 병합 표 이동 2개이며, 본문이 없는 양식에는 복사본에 합성 뒤 문단을 추가한 뒤 원래 빈 문단을 옮겼다. 원본은 변경, 전송하지 않았다.

첫 본문 그룹은 구역 설정을 유지하기 위해 고정한다. 구역 설정과 함께 첫 문단에 묶인 표, 셀 안 문단의 순서 이동과 일부 제어만 추출하는 이동은 이번 범위에 포함하지 않는다. 이동은 내용 순서를 바꾸므로 최종 페이지 배치는 달라질 수 있으며, raw 보존이 모든 페이지의 시각적 보증은 아니다.

2026년 10월 11일 구현, 검증. Codex가 실행 환경에서 접근할 수 있는 **지정한 HWP 파일을 직접 읽고, 수정 후 같은 경로에 저장**하는 로컬 기능이다. 문서를 서버로 업로드하거나 브라우저, 다운로드 링크를 열지 않는다. 기존 원격 플러그인 0.1.9의 심사와는 별개이며 이번 코드를 그 제출본에 반영하지 않았다.

사용자는 파일을 지정하고 바꿀 내용을 요청한다. 에이전트가 읽기, 대상 확인, 저장 전 검사, 수정과 저장 후 재열기를 수행한다.

> 이 로컬 HWP의 ‘지원 동기’ 칸을 다음 두 문단으로 바꿔줘. 같은 파일에 저장해줘.

파일 경로를 지정하면 해당 경로에 저장한다. 대화에 첨부한 사본만 접근할 수 있다면 그 사본을 편집한다. 첨부 사본이 PC 원본 경로와 자동 연결되어 있다고 판단하지 않는다. Cloud에서는 Cloud 실행 환경의 파일을 편집하며 PC 파일이 자동 동기화되지 않는다.

## 추가한 기능

- 기존 본문과 표 셀의 텍스트 교체와 빈 칸 채우기. 기존 원격 엔진의 raw 보존, 혼합 서식, 글꼴 선택 검사를 로컬에서 재사용한다.
- 혼합 글자 서식을 유지하는 부분 삽입, 삭제, 길이가 다른 치환. 남겨 둔 글자의 서식은 유지하고 새 글자는 변경 위치의 서식을 사용한다. 본문과 셀의 원하는 위치에서 실제 문단을 분리하고, 문단 속성이 같은 인접 일반 문단을 재병합할 수 있다.
- 여러 줄 답변을 **실제 HWP 문단**으로 저장. 표 셀 안의 새 문단과 기존 LF 줄바꿈이 있는 대상도 검사한다.
- 본문 문단 뒤에 새 문단 추가, 직사각형 표 생성과 셀 내용 입력. 기존 문단, 표의 위치가 이동해도 비대상 내용을 비교한다.
- 본문 문단 삭제, 인접 본문과 셀 문단 병합, 첫 문단 다음의 셀 문단 삭제. 삭제 대상에 숨은 제어가 있으면 저장 전 거부하며 병합할 두 문단의 내용, 서식을 확인한다.
- 직사각형 표와 기존 병합 표의 행, 열 추가/삭제. 삽입 경계를 가로지르는 병합 셀은 확장하고, 삭제할 행, 열을 가로지르는 병합 셀은 축소하며 그 내용을 유지한다. 완전히 삭제되는 칸과 축소되는 병합 칸의 전체 문단 내용을 확인한다. 새 칸은 인접 칸의 지원 서식을 사용하며 변경 축 방향의 표 크기가 늘거나 줄어든다.
- 기존 병합 셀을 원래 격자로 나누기, 완전히 선택한 직사각형 셀 범위 병합. 첫 셀의 문단을 보존하고 다른 셀의 비어 있지 않은 문단을 이어 붙인다. 다른 셀의 빈 문단은 병합 과정에서 제거한다. 나눌 때 전체 폭, 높이의 정수 나머지도 유지한다.
- 선택 글자 범위의 글꼴 이름, 크기, 색, 굵게, 기울임, 밑줄, 취소선 변경, 문단 정렬, 줄 간격, 여백, 들여쓰기, 문단 전후 간격 변경. 글꼴은 7개 언어별 ID와 필요한 새 이름 정의를 확인하며 기존 정의를 보존한다. 글꼴 파일을 설치하거나 포함하지 않는다.
- 일반, 병합 표의 열 폭, 저장 행 높이, 셀 안 여백, 위/가운데/아래 정렬, 표 여백, 셀 간격 변경. 셀 텍스트, 혼합 서식, 그림은 유지한다. 저장 행 높이는 최소 크기이며 내용에 따라 표시 높이가 늘어날 수 있다.
- 본문, 최상위 표 셀의 일반 문단에 여러 로컬 PNG/JPEG 삽입, 그림 번호로 고른 개체의 교체, 크기, 위치, 네 방향 자르기, 각도 회전과 제거. 셀 그림은 셀 문단에 인라인으로 저장한다. 교체는 틀 크기, 위치, 회전을 유지하고 새 이미지 전체를 사용한다. 선택하지 않은 그림과 다른 문단과 셀을 보존한다.
- 검증된 페이지 번호 제어의 원시 바이트를 그대로 보존하면서 다른 지원 대상의 구조 변경을 허용한다. 페이지 번호 자체를 읽거나 바꾸는 기능은 아니다.
- 같은 파일 저장과 저장 전 이전 버전 보관. 요청한 경우에만 Save As를 사용한다. 현재 해시와 다른 파일에는 저장하지 않는다.
- 원본 바이트 복구, 버전에 고정된 이어 읽기, 기본 SVG 미리보기.

문단, 표 생성과 표 구조 변경은 균일 글자 서식의 지원 대상을 요구한다. 부분 텍스트, 문단 경계는 혼합 글자 서식을 유지하며, 서로 다른 지원 작업을 한 번에 검사, 저장할 수 있다. 병합 표 행, 열 변경은 겹침 없는 완전한 격자와 일반 셀 문단을 요구하고, 최대 512행, 128열, 4,096격자 위치를 검사한다. 새 칸의 서식은 균일해야 한다. 삽입 행 높이, 열 폭은 인접 축의 저장 크기를 사용하고, 표시 높이가 더 큰 표의 비율도 유지한다. 확장된 병합 칸에 걸린 삽입 슬롯의 `texts`는 빈 문자열이어야 한다.

셀 나누기, 병합은 숨은 개체가 없는 검증 가능한 직사각형을 요구한다. 첫 셀 문단 삭제, 문단 속성이 다른 문단의 병합, 숨은 제어를 포함한 혼합 서식 재구성, 그림을 포함한 셀의 표 구조 변경, 그림 그룹의 회전, 크기 변경/교체, 캡션, 필드 생성/삭제, 중첩 표 구조, 일반 쪽 배치 변경은 아직 지원하지 않는다. 그림은 단일 구역, 일반 본문/셀 문단당 최대 32개, 삽입, 교체는 1 MiB 이하 PNG 또는 8비트 기본/점진 JPEG로 제한한다. 이미지 한 변은 8,192픽셀 이하, 전체는 1,600만 픽셀 이하이며 JPEG는 1개 또는 3개 성분을 지원한다.

그림 제거, 교체 후에도 사용하지 않는 이전 이미지 바이트와 복구 사본은 남으므로 민감정보 영구 삭제로 안내하지 않는다. 입력, 출력 4 MiB, 일반 모델 2,000,000 UTF-16 단위, 작업 프로세스 60초의 한도를 적용한다. 원격의 400,000 단위 한도는 로컬 실행에 적용하지 않는다.

여러 그림이 있는 문단에서는 현재 읽기에 나온 문단별 `picture_index`와 전체 `expected_properties`로 개체를 선택한다. 추가, 삭제 후 번호를 다시 읽는다. 자르기 양은 표시 틀이 아닌 원래 이미지의 크기를 기준으로 하며, 원본 1픽셀당 75 HWP 단위다. 양쪽 합이 원본 크기 이상인 요청은 저장 전에 거부한다. 회전은 -359~359도의 정수이며 외곽 틀, 중심, 변환 행렬을 함께 저장한다. 각도를 바꾸면 중심을 유지하도록 틀 크기와 위치가 조정된다. PNG/JPEG의 파일 구조 검사는 전체 픽셀 디코더를 대체하지 않는다.

## 저장과 검증

부분 텍스트, 문단 경계 변경은 숨은 제어가 없는 일반 문단을 대상으로 한다. 서로 다른 글자 서식은 유지하지만 문단 속성이 다른 두 문단은 병합하지 않는다. 혼합 run은 최대 32개이며 줄바꿈 추가는 문단 분리나 여러 문단 치환을 사용한다. 표 메타데이터 변경은 완전하고 겹치지 않는 최상위 격자를 요구한다. 열 폭, 행 높이는 각 축의 크기 배열을 받아 병합 칸의 span 합으로 저장한다.

읽기, 미리보기, 계획은 파일을 저장하지 않는다. 편집은 현재 파일 해시, 대상 ID와 기존 전체 텍스트를 확인하고, 메모리에서 수정, 직렬화, 재열기, 내용 및 raw 레코드 검사를 거쳐 게시한다. 구조 변경에서는 기존 블록의 위치 이동, 요청한 새 문단/표의 내용, 셀 문단 수와 끝 플래그, 기존 글자/문단 정의 및 다른 스트림을 확인한다.

이전 파일은 같은 폴더의 `.hwp-easy-backups`에 문서별로 연결해 보관한다. 복구할 때도 현재 버전을 새로 보관한다. 이 폴더는 개인 문서를 포함할 수 있어 공유, 업로드하지 않는다. 스크립트 간 잠금과 파일 해시 확인을 사용하지만 다른 프로그램 전체를 묶는 OS 트랜잭션은 아니며 Windows ACL, 전원 장애 복구와 외부 뷰어의 모든 배치를 인증하지 않았다.

최초 검증은 개인정보 없는 실제 합성 HWP로 수행했다. 한국어, 공백 경로의 같은 파일 저장, 무저장 계획, 여러 문단 셀 답변, 새 본문 문단, 표 생성, 재열기, 기본 SVG, 이전 바이트 복구를 **node_modules가 없는 분리 폴더의 실제 패키지 프로세스**에서 통과했다. 별도 Python `olefile`/레코드 판독으로 새 셀 문단, 본문, 표 텍스트와 기존 글꼴, 문단 정의 및 다른 스트림 보존을 확인했다. 이 합성 검사에는 사용자 문서를 사용하지 않았다.

### 사용자 제공 문서의 로컬 복사본 검사

같은 날 사용자가 `testdocs/`의 실문서로 편집 검증을 요청한 뒤 최상위 HWP **3개를 로컬 복사본으로만** 검사했다. 이전 10월 3, 5, 7일 보고서는 `testdocs/`의 HWP 3개에 대한 읽기, 구조 검사였으며 실제 편집, 저장 성공 기록이 아니었다. 첫 복사본 검사에서 한 양식의 구조 편집에 `CELL_PRESERVATION_MISMATCH`가 발생했다. pinned writer가 기존 셀 LIST_HEADER의 불투명한 zero word를 `0x0400`으로 바꾸는 현상이 새 구조 경로에서도 발생한 것이다.

기존 헤더 순서, 이동된 호스트, 전체 셀 문단 수와 나머지 헤더 바이트를 먼저 대조하고 **그 정확한 두 바이트 전이만 원본 값으로 복구**했다. 새 표의 헤더는 바꾸지 않으며 재열기 모델 일치와 전체 raw 보존 검사를 유지한다. 합성 회귀에 셀 여러 문단, 본문 문단 추가, 표 생성의 zero word 보존과 다른 전이 거부를 추가했다.

첫 단계는 12개 작업 중 9개가 통과하고 첫 문서의 구조 변경 3개가 거부됐다. 후속 조사에서 해당 문서의 미지원 요소는 페이지 번호 제어임을 확인했다. 기존의 엄격한 페이지 번호 원시 바이트 보존 프로필을 구조 편집에도 적용했으며, 읽기 결과는 여전히 부분 지원으로 표시한다. 또한 빈 문단의 표 생성 시 엔진이 현재 문단을 재사용하는 동작을 보완해 선택 문단 **뒤**에 표를 넣도록 했다.

### 병합 표의 행과 열, 글꼴과 셀 그림 검사

로컬 후보 **0.2.3**은 `testdocs/`의 세 복사본에서 새 **31개 사례**를 통과했다. 원래 병합 표가 있는 두 문서의 행, 열 추가/삭제 8개, 기존 지원 대상의 글꼴 변경 3개, 본문 그림 삽입, 교체, 크기 변경, 제거 12개, 표 셀 그림의 같은 네 작업 8개다. 모든 사례는 실제 패키지의 무저장 계획 → 같은 경로 저장 → 전체 이어 읽기 → 정확한 이전 바이트 복구를 수행했다. 독립 Python/olefile 원시 판독도 **31/31**을 통과했다. 원본 3개는 불변이며 내용, 이름, 해시는 전송하거나 공개하지 않았다.

병합 표 삭제에서 저장 순서가 행, 열 순서와 다른 양식도 실제 좌표로 헤더를 대응했다. 요청 밖 셀의 내용, 서식, 불투명 헤더 값은 그대로 대조하며, 엔진이 잘못 재계산하는 표 외곽 크기와 병합 셀 크기를 명시한 변경 범위로 보완했다. 글꼴 변경은 실제 언어별 ID와 이름 기록, 기존 혼합 run의 나머지 속성을 확인한다. 셀 그림은 엔진의 표 밖 floating 삽입 결과를 선택 셀 문단의 실제 인라인 개체로 옮겨 저장하며, 크기 변경으로 표의 다른 칸 높이가 바뀌지 않게 한다.

실문서에는 원래 그림이 없어 그림 검사는 합성 PNG를 넣고 **다른 크기의 PNG로 교체**한 범위다. 임의의 기존 개인 이미지, 한 문단의 여러 그림, 외부 한글 화면 배치 인증으로 확대하지 않는다. ignored `outputs/advanced-edit-20261011/extended-copy-cases/`에 검증 사본과 익명 집계를 보관한다.

로컬 회귀 97개, 분리 폴더 패키지의 연속 편집과 원래 파일 복구, 독립 합성 원시 검사 18개도 통과했다. 회귀에는 병합 경계 삽입/삭제, 확장된 병합 칸에 요청 텍스트를 숨기려는 입력의 거부, 기존 병합 내용 확인, 빈 셀과 이모지 위치의 그림 저장, 교체를 포함한다. 운영 사이트와 심사 중인 원격 패키지는 이 변경에 포함되지 않는다.

### 여러 그림과 JPEG, 자르기와 회전

로컬 후보 **0.2.4**는 `testdocs/` 세 복사본에서 새 **50개 사례**를 통과했다. 본문 세 곳과 표 셀 두 곳에 PNG, 기본 JPEG, 점진 JPEG를 함께 넣고, 가운데 그림만 자르기, 해제, 90도/34도/0도 회전, 교체, 삭제했다. 각 작업은 실제 패키지의 무저장 계획 → 같은 경로 저장 → 전체 이어 읽기를 수행했고, 각 연속 작업 끝에 원래 바이트로 복구했다. 독립 Python `olefile`/원시 레코드 판독도 **50/50**을 통과했다. 세 원본은 그대로이며 개인 문서, 내용, 이름, 해시는 전송하거나 공개하지 않았다. 원래 이미지가 없는 양식에 합성 PNG/JPEG를 넣은 범위다.

원래 BodyText를 재사용해 선택한 그림과 앵커만 바꾸며 다른 그림, 본문과 셀 헤더, 기존 이미지 스트림을 그대로 비교한다. 실제 셀의 34도 회전이 작은 스트림 저장 공간 경계에서 거부되는 문제를 재현하고, 한 개의 미니 섹터와 필요한 루트/miniFAT 섹터를 각각 최대 하나만 늘리는 로컬 보완을 추가했다. 기존 FAT 용량, 다른 스트림의 바이트와 위치는 유지하며 더 큰 할당 변경은 저장 전에 거부한다. 짧아진 압축 BodyText는 허용된 zero tail로 기존 공간을 유지한다. 운영 경로의 구조 보완은 기존 검사를 그대로 사용한다.

로컬 회귀 **105개**, CFB v3/v4의 공간 경계, 잘못된 할당 거부 검사 5개, 공통 엔진 34개, 가드 회귀, Python 284개(4개 제외)가 통과했다. node_modules 없는 분리 패키지의 합성 그림 연속 작업 **20건**, 기존 연속 편집, 복구, 독립 기존 그림/서식 18건과 구조 검사도 통과했다.

이번 그림 20건과 실문서 사본 50건은 Python/Pillow로 합성 raster 디코딩과 크기까지 별도 확인했다. 회귀는 빈 셀, 이모지, 음수/임의 각도, 회전 후 크기 변경, 교체, 다른 그림 보존, 오래된 속성, 번호 누락, 범위 초과 자르기와 손상 JPEG의 저장 전 거부를 포함한다. 외부 한글 프로그램의 그림 배치 확인은 남아 있다.

교체는 자르기 범위와 저장된 원본 이미지 크기를 모두 새 raster 크기로 갱신하며 틀, 회전, 선택하지 않은 그림을 보존한다. 검증 사본과 익명 집계는 ignored `outputs/picture-edit-20261011/real-copy-cases-4/`에 보관한다.

원시 변환 행렬은 [고정 RHWP serializer](https://github.com/edwardkim/rhwp/blob/e8800c8def63449808a4092798442652ed460552/src/serializer/control.rs)의 형식을 따르며, JPEG framing은 [ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)을 참고했다.

그룹 개체, 캡션, 그림을 포함한 셀의 구조 변경을 일반 지원으로 확대하지 않는다.

### 한글 2020 화면 확인과 셀 그림 크기 보완

로컬 후보 **0.2.5**는 한글 2020의 실제 화면 비교에서 발견한 셀 그림 크기 오류를 수정했다. 셀에 인라인 그림을 저장할 때 공통 헤더 속성을 `1`로 설정해 절대 폭, 높이 기준이 사라졌고, 한글은 크기를 종이 비율로 해석해 그림을 납작하게 표시했다. 인라인 비트와 절대 크기 기준을 함께 유지하는 `0x000a0001`로 보완했다.

이 값은 [한컴 HWP 5.0 형식 revision 1.3](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)의 공통 개체 속성 표 70에 따른다. 본문과 셀 그림의 폭/높이 기준을 회귀와 독립 Python 판독에서 함께 검사한다.

수정한 실제 분리 패키지로 세 `testdocs/` 복사본의 **50/50**, 독립 Python/Pillow **50/50**, 합성 그림 **20/20**과 로컬 회귀 **105/105**를 다시 통과했다. 기존 분리 패키지의 연속 편집, 29개 복구 사본, 독립 구조 및 고급 편집 검사도 통과했다. 수정 코드 `e538bc7`의 [Linux와 Windows CI 네 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38110386470)은 모두 성공했다.

한글 2020의 **100% 배율**에서 수정 패키지가 저장한 다음 **13개 화면**을 직접 비교했다. 본문 그림은 같은 로컬 패키지의 위치 변경으로 서로 떨어뜨린 비교 사본을 사용했고, 셀 그림은 인라인 배치 그대로 확인했다. 문서 번호는 개인 파일 이름을 대신한 익명 식별자다.

| 문서, 대상 | 직접 확인한 화면 | 결과 |
| --- | --- | --- |
| 문서 01 본문 | 여러 그림 중 가운데 JPEG의 34도 회전 | 1/1 |
| 문서 01 넓은 표 셀 | 여러 그림의 나란한 배치와 가운데 JPEG의 34도 회전 | 1/1 |
| 문서 02 본문 | 여러 그림 중 가운데 JPEG의 34도 회전 | 1/1 |
| 문서 02 좁은 표 셀 | 기준 배치, 네 방향 자르기, 해제, 90도/34도/0도 회전 | 6/6 |
| 문서 03 본문 | 기준 배치, 네 방향 자르기, 90도/34도 회전 | 4/4 |

선택한 JPEG만 잘리거나 회전했고 나머지 PNG, 점진 JPEG의 틀과 방향이 유지됐다. 자르기는 표시 틀을 유지했고 해제하면 전체 패턴이 다시 보였다. 90도와 34도 회전은 중심과 전체 모서리를 확인했으며 0도로 되돌리면 수평 틀이 복원됐다. 본문 그림은 서로 겹치지 않았고, 넓은 셀은 나란히, 좁은 셀은 여러 줄로 표시됐다. 좁은 셀은 그림을 수용하며 행 높이가 늘고 한 문서는 1쪽에서 2쪽으로 재배치됐다. 보이는 인접 칸 경계는 정렬을 유지했다.

그림, 화면, 개인 문서는 공개하거나 업로드하지 않았다. 화면 비교 중 한글에서 파일을 저장하지 않았고, 검사 후 세 원본과 비교 파일의 바이트를 다시 확인했다. 양식 두 개의 원래 버전 헤더에 대한 한글 2020 상위 버전 안내는 별도 관측이며 헤더를 바꿔 숨기지 않았다. 13건은 지정한 그림 영역의 관찰이고, 모든 50개 작업의 화면 검사나 전체 페이지, 글꼴, 인쇄, 임의의 기존 이미지 배치 인증이 아니다. 그룹 그림, 캡션, 그림을 포함한 셀의 표 구조 변경은 후속 범위다.

**PNG 색상 추가 비교 2건:** 기존 1×1 회색, 알파 PNG는 한글에서 원래 검정 픽셀과 다른 회색 그라데이션으로 표시됐다. 앞의 13건에서 이 PNG의 틀, 배치는 관찰했지만 픽셀 표시 성공으로 간주하지 않는다. 별도 64×40 RGB PNG를 실제 패키지로 본문과 표 셀의 첫 그림에 교체한 두 사본에서는 빨강, 초록, 파랑, 노랑 영역과 흰 십자, 기존 틀 크기와 두 JPEG의 보존을 확인했다. 일반 RGB PNG의 두 화면은 통과했으며, 1×1 회색, 알파 PNG의 표시 차이 원인은 미해결로 남긴다. 입력 이미지와 저장된 이미지 바이트는 독립 판독에서 같다.

검증 사본은 ignored `outputs/picture-edit-20261011/real-copy-cases-5/`, 추가 비교 사본, 로컬 화면, 관찰 기록은 `outputs/picture-viewer-20261011/`에 보관한다. 개인 문서 자료를 제외한 로컬 실행 패키지는 `hwp-easy-local-0.2.5.zip`으로 준비했다. 운영 Sites, 전역 설치, 심사 중인 원격 0.1.9에는 반영하지 않았다.

## 개발과 패키징

### 부분 텍스트, 문단 경계와 표 배치 후속 검사

후보 **0.2.6**은 `testdocs/` 세 복사본의 기존 본문과 셀 다섯 곳에서 부분 삽입/삭제, 다른 길이 치환, 전체 비우기, 양 끝/중간 문단 분리, 재병합 **50개 사례**를 통과했다. 표가 있는 두 문서의 원래 병합 표에서 열 폭, 행 높이, 셀 여백/세로 정렬, 표 간격 **12개 사례**도 통과했다.

모든 사례는 실제 분리 패키지의 무저장 계획, 같은 사본 경로 저장, 재열기와 정확한 이전 바이트 복구를 수행했고 별도 Python `olefile`/raw 판독도 각각 50/50, 12/12를 확인했다. 세 원본은 그대로이며 이름, 본문, 해시는 공개하지 않았다.

최종 소스의 로컬 회귀 165개, 공통 엔진 34개, node_modules 없는 분리 패키지의 텍스트 26개, 표 배치 14개, 기존 그림 20개와 이전 구조/서식 독립 검사도 통과했다.

텍스트 검사는 코드 포인트와 raw UTF-16 run을 함께 대조한다. 이모지 중간을 잘못 나누는 run은 변경 전에 거부하고, 새 문단의 인스턴스 값은 기존 문단과 구분해 검사한다. 표 배치는 기존 압축 BodyText 공간을 유지하는 raw 패치를 사용해 다른 스트림과 불투명 제어 헤더 꼬리를 그대로 보존한다. 한글 2020에서 합성 병합 표의 열 폭, 행 높이 두 화면과 실문서 사본의 혼합 부분 치환, 문단 분리 두 화면을 확인했다. 이 네 화면은 지정한 결과의 확인이며 전체 페이지 조판 인증은 아니다. 사본, 화면은 ignored `outputs/improvement-loop-20261011/`에 보관한다.

### 여러 편집을 한 번에 저장

후보 **0.2.7**은 텍스트, 서식, 문단, 표, 그림 작업을 최대 100개까지 한 요청으로 검사하고 한 번 저장한다. 첫 읽기의 대상 ID를 유지하면서 문단 삽입/삭제, 행/열 변경과 병합 셀로 이동한 문단의 실제 위치를 따라간다. 각 작업의 기존 값은 해당 단계의 내용과 맞아야 한다. 새로 만든 문단은 별도 읽기 후 선택하며, 이미 삭제한 대상에 대한 후속 작업은 전체 요청을 거부한다. 모든 단계는 메모리에서 검증하고 마지막에 원본의 복구 사본 하나와 최종 파일을 저장한다. 중간 실패는 파일이나 백업 폴더를 바꾸지 않는다.

합성 회귀 20개는 위치 이동, 병합/분리 셀의 문단 추적, 중간 조건 불일치, 삭제 대상 재사용, Save As, 그림과 표 배치의 묶음 저장을 확인한다. 전체 로컬 회귀 **185개**가 통과했다. 분리 패키지의 합성 묶음 **8개, 25작업**과 `testdocs/` 복사본의 **12개, 38작업**을, 매번 다시 읽고 개별 저장한 결과와 비교해 모든 decoded 스트림이 같음을 확인했다.

무저장 계획, 한 번 저장, 원래 바이트 복구를 검사했으며, 원본 세 문서는 불변이다. 한글 화면에서는 행 높이와 셀 아래 정렬, 좌/하 여백을 함께 적용한 합성 결과도 확인했다. 기존 0.2.6의 Windows Python CI는 검사 확대 후 5분 job 시간 초과로 중단돼, 전체 검사에 10분의 유한 실행 시간을 적용했다.

### 혼합 서식 문장에 여러 문단 삽입

후보 **0.2.8**은 부분 삽입, 치환의 새 텍스트에 LF가 있으면 실제 본문/셀 문단을 만든다. 선택 영역 밖 앞뒤 글자의 원래 서식과 문단 속성을 유지하고, 새 글자는 삽입 위치의 서식을 사용한다. 빈 문단과 양 끝 삽입을 지원하며 100개 문단, 100,000 UTF-16 단위를 검사한다. 새 문단의 인스턴스 값, raw UTF-16 run, 셀 문단 수와 마지막 플래그를 확인한다. CR, 탭, 잘못된 surrogate, 문단 수 초과는 저장 전 거부한다.

전체 로컬 회귀 **207개**, 분리 패키지의 텍스트/문단 **38개**와 독립 reader가 통과했다. `testdocs/` 세 복사본의 기존 본문과 셀 다섯 곳에서 새 **25개** 여러 문단 삽입/치환 사례가 무저장 계획, 같은 사본 경로 저장, 재열기, 정확한 바이트 복구와 독립 raw 검사도 통과했다. 세 원본은 불변이며 사본과 기록은 ignored `outputs/improvement-loop-20261011/real-multiline/`에 보관한다. 일반 문단의 범위를 확대한 것이며 숨은 제어가 있는 대상의 자유 편집이나 전체 쪽 배치 인증은 아니다.

실행 패키지는 Node.js 22 이상과 로컬 파일 권한을 사용한다. 엔진 JS, WASM, 압축 해제기와 고지를 포함하며 실행 시 Python, pip, npm 설치나 HWP Easy 인증을 요구하지 않는다. Codex 데스크톱의 번들 Node 경로를 사용할 수 있다. 에이전트가 내부 실행 명령을 수행하므로 사용자가 명령을 입력하는 흐름으로 안내하지 않는다.

## 0.2.24 부동 개체·고정 하단·글상자

선택 개체를 부동 상태로 유지한 재배치, 고정 바닥 영역과 단순 텍스트 꼬리말 위치 보존, 본문 사각형 글상자 부분 편집·빈 상자 입력을 지원 프로필에 추가했다. 쪽 계산 차이는 확실한 충돌과 구분해 불확실 결과로 보고한다. 작업별 조건·10건의 같은 파일 저장/정확한 복구·한컴 30개 파일/43쪽 확인은 [0.2.24 검증](local-release-0.2.24.md), 세부 요청은 [실행기 참조](../plugins/hwp-easy/skills/edit-local-hwp/references/requests.md)를 따른다.

## 0.2.25 공개 양식·진단 보강

공개 12개를 0.2.24 설치본으로 재검증하고 벡터 그룹 이동·셀/중첩 셀 글상자 편집을 확장했다. 새 중첩 표 높이 추정 위험도 차단하려면 계획·편집 요청에 `layout_policy:"reject_new_risk"`를 지정한다. 기본 `report`와 기존 기하학적 검사 `reject_new_overflow`는 유지한다. 위험 거부는 저장·백업 생성 전에 수행하며 무단 글자 축소나 답변 생략으로 우회하지 않는다. WASM 인라인 개체 분류와 중첩 표 페이지 계산의 불확실성도 표시한다. [공개·합성·네이티브 검증과 남은 제한](local-release-0.2.25.md)
