# 구조 설명

HWP Easy는 기존 HWP 처리 엔진을 에이전트가 안전하게 사용하는 데 필요한 대상 지정·검증·저장·연결 계층을 구성합니다. 공통 엔진과 실행 환경별 어댑터를 구분합니다.

## 원격 문서 흐름

```mermaid
flowchart LR
  U[사용자] -->|직접 HWP 업로드| B[인증된 브라우저]
  U -->|읽기·수정 요청| A[ChatGPT / Codex]
  A -->|MCP + OAuth| H[Sites Worker의 사용자별 문서 서비스]
  B --> H
  H --> E[WASM 엔진과 독립 보존 검사]
  H --> D[D1: 소유자·문서·버전·요청 기록]
  H --> R[R2: 버전별 HWP 바이트]
  E -->|검증한 HWP| H
  H -->|조회 결과·보기·다운로드| A
  H -->|고정 버전의 SVG·HWP| B
```

브라우저 업로드와 MCP는 같은 인증 사용자의 원격 문서를 사용합니다. 채팅 첨부가 서버에 자동 전달된다고 가정하지 않습니다. 파일 가져오기는 별도로 허용한 정확한 HTTPS origin에서만 수행합니다.

## 계층별 책임

| 계층 | 구현 | 책임 |
| --- | --- | --- |
| 문서 엔진 | `@rhwp/core` 0.8.6 | HWP 모델 읽기·텍스트 변경·HWP 쓰기·SVG 생성 |
| 공통 어댑터 | `src/one_hwp/*.mjs` | Node와 Worker가 재사용하는 엔진 처리·스타일·글꼴 비교 |
| 독립 검사 | `probes/sites-runtime/guard/` | CFB·레코드·대상 매핑·비대상 바이트와 변경 조건 확인 |
| 원격 엔진 계약 | `probes/sites-runtime/engine/` | 전체/부분 읽기·대상별 편집 제한·사전 계획·입력 작업량 검사 |
| 원격 서비스 | `host/`, `worker/` | MCP와 브라우저 라우팅·입력 검증·파일 전송·사용자 신원 적용 |
| 지속 저장 | `storage/`, `db/`, `drizzle/` | 사용자별 버전·충돌·정확 재시도·복구·명시적 삭제 |
| 로컬 서비스 | `src/one_hwp/native_*.py` | 허용 경로의 로컬 MCP·별도 백업과 기대 버전 저장 |
| 배포 패키지 | `plugins/hwp-easy/` | HTTPS MCP와 OAuth를 연결하는 공개 제출 초안 |

표에서 `host/`·`worker/`·`storage/` 등의 원격 경로는 모두 `probes/sites-runtime/` 아래입니다. 이 디렉터리는 실험 때 정한 이름을 유지하지만 현재 비공개 운영 Worker의 개발 소스도 포함합니다. 변경 위치는 [개발 시작](developer-guide.md)을 따릅니다.

## 저장과 권한

Sites가 신뢰 경계 안에서 제공하는 사용자 ID·이메일 헤더를 확인하고, 사용자 ID에서 사이트별 소유자 키를 생성합니다. 헤더 존재 검사는 독립 OAuth 검증기가 아닙니다. 이 Worker를 별도 호스팅에 그대로 노출하거나 외부 요청의 신원 헤더를 신뢰하면 안 됩니다. 서비스 접근 자격도 사용자 문서 권한으로 취급하지 않습니다.

조회는 해당 사용자의 고정 문서·버전에만 접근합니다. 편집은 기존 값·해시·현재 버전과 요청 ID를 확인하고, 생성·재열기·보존 검사를 통과한 HWP를 새 버전으로 저장합니다. 실패한 묶음을 임의로 나눠 일부만 저장하지 않습니다. 이전 버전을 바꾸지 않으며 복구도 새 버전을 만듭니다. 저장이 원격에서 일어나므로 PC 원본은 자동 변경되지 않습니다.

문서는 사용자가 명시적으로 삭제할 때까지 보관합니다. 연결 해제와 문서 삭제는 별개입니다. [지속 저장 계약](durable-storage.md)과 [원격 문서 계약](remote-documents.md)에 실패·재시도·삭제의 자세한 조건을 기록합니다.

## 구현과 증거의 경계

소유자 전용 배포의 실제 문서 왕복, 헤더를 모의한 로컬 사용자 격리, 다른 실제 OAuth 계정의 격리는 각각 다른 검증입니다. 마지막 항목은 아직 미완료입니다. 내용·구조·바이트 검사도 모든 외부 뷰어의 시각 배치 보존을 인증하지 않습니다.

`one-hwp`·`one-hwp-mcp`는 보존된 Windows COM 경로입니다. 새 엔진이 거부됐을 때 자동 실행하지 않습니다. [이전 문서](legacy/README.md)는 이 경로에만 적용합니다. Dots와 형식 변환은 현재 MVP 범위에 포함하지 않습니다.
