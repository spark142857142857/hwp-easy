# 로컬 HWP Easy 0.2.23 배치 조정 검증

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [이전 검증](local-release-0.2.22.md)

2026년 10월 13일의 공통 Node/WASM 소스·분리 패키지 검증입니다. Codex 실제 설치는 **0.2.20**, Claude Code·Cursor 설치와 공개 ZIP은 **0.2.19**입니다. 이번 변경은 설치·공개 배포와 구분합니다.

## 변경 범위

| 대상 | 추가 동작 | 보존 및 조건 |
| --- | --- | --- |
| 선택한 부동 그림·바깥 그룹 | 글자처럼 취급해 문단이 개체 높이를 확보 | 이미지·크기·자르기·그룹 행렬·텍스트 앵커 순서 보존. 부동 오프셋을 0으로 하고 겹침 허용을 해제. 절대 크기·확인 가능한 세로 용지와 셀 또는 단일 단의 본문 폭 필요 |
| 본문·누름틀이 든 문단·셀 문단 | 글자 크기에 따른 높이와 자동 쪽 이어짐 | 고정/최소/여백 간격을 160%로 전환. 기존 비율은 100–1000% 범위에서 유지. 글꼴별 높이·외톨이줄 보호를 켜고 문단 보호·다음 문단과 함께를 해제 |
| 영향받는 구역 | 매핑한 본문·셀 줄 캐시 무효화 | 후속 문단과 부모 셀의 높이·페이지를 다시 계산하도록 함. 글자·글자 서식·명시적 쪽/단 나눔·번호·개요 수준·최소 행 높이와 불투명 머리말/꼬리말은 유지 |
| 현재 쪽 진단 | 텍스트 줄·부동 개체 교차, 본문 영역 넘침 | 명시적 `layout`의 `scope:"rendered"`. WASM 바운딩 박스 관측이며 32쪽·20,000항목·200,000교차 검사·2,000문제 상한 |
| 단일 그림 조회 | 검증한 가변 길이 개체 설명 보존 | 일반 그림 편집 프로필이 불가능해도 원시 구조를 검증한 대상의 `flow_editable`을 별도 표시. 해당 경우 흐름 조정만 허용 |

요청 형식은 [실행기 참조](../plugins/hwp-easy/skills/edit-local-hwp/references/requests.md)의 `reflow_paragraph`, `reflow_object`를 따릅니다. 같은 파일 저장 전에 기존 텍스트·속성·흐름 조건을 대조하며, 반복한 동일 설정과 빈 캐시는 무저장입니다. 두 작업은 다른 편집과 원자적 배치로 묶을 수 있습니다.

원시 속성은 [한컴 HWP 5.0 revision 1.2](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%98%95%EC%8B%9D_5.0_revision1.2.pdf)의 문단 모양·개체 공통 속성 정의와 고정 엔진의 파서를 대조했습니다. 기존 문단 정의는 그대로 두고 필요한 정의만 추가하며, 현대/이전 줄 간격 슬롯을 함께 갱신하고 개요 수준의 말미 4바이트는 유지합니다.

## 검증

| 검사 | 결과 및 범위 |
| --- | --- |
| 로컬 회귀 | 최종 소스 424개 통과. 전용 흐름/복구/거부 검사 13개 포함 |
| 분리 패키지 | 새 흐름 9건의 계획 무저장, 계획/저장 SHA-256 일치, 같은 파일 저장과 바이트 단위 복구. 기존 그룹·문단 경계·넘침 18건과 독립 판독도 재통과 |
| 독립 Python | OLE 스트림·문단 헤더·줄 간격 두 슬롯·명시적 나눔·개요 꼬리·텍스트/서식 기록·이미지·그룹 행렬 보존 9건 |
| 한컴 자동화 API | 수정 전·후·복구본 27개 파일·42쪽 모두 열기와 이미지 생성. 모든 TEXT가 수정 전후 동일하며 복구 14쪽은 픽셀 동일 |
| 실제 문단 높이 | 60줄 본문 두 프로필에서 제목·끝 문단을 포함한 62줄이 각각 분리된 픽셀 띠로 표시. 두 쪽으로 이어짐 |
| 셀·그룹 호환성 | 긴 누름틀 셀의 높이 증가·두 쪽 이어짐, 그룹/단일 그림의 inline 배치와 주변 글 표시를 쪽 이미지로 확인 |
| computer-use | 0회. 파일 처리·저장·복구·네이티브 열기·렌더링은 실행기와 자동화 API로 수행 |

분리 시험은 임시 폴더의 자체 포함 패키지 실행기만 사용합니다. 제품 실행에 Python·한글·서버는 필요하지 않습니다. 한컴 자동화와 Pillow는 개발자의 선택적 호환성 검증에만 사용합니다. 개인 문서, 기존 클라이언트 설치와 원격 보관본은 변경하지 않았습니다.

재현 명령:

```text
node scripts/package_local_plugin.mjs
node scripts/check-local-reflow.mjs
python scripts/check-local-reflow.py
```

한글이 설치된 Windows에서 합성 결과의 네이티브 호환성을 추가 확인하려면 `render-local-reflow-native.py <결과 폴더>`, Pillow 환경에서 `check-local-reflow-native.py <결과 폴더>`를 실행합니다. Windows·Linux CI에는 분리 실행과 독립 원시 판독을 포함합니다.

## 배치 한계

개체 조정은 **선택 개체를 inline으로 전환**하는 방식입니다. 임의 부동 위치·앞/뒤 겹침·고정 로고/워터마크를 유지하면서 자동으로 최적 배치를 찾는 기능은 아닙니다. 명시적 요청으로 선택한 개체만 전환합니다. 본문보다 큰 개체, 확인하지 못한 다단 본문·가로 용지·세로 셀과 모호한 과거 문단 나눔 플래그는 저장 전에 거부합니다.

부동 그룹을 위/아래 본문 배치로 바꾸기만 한 초기 후보는 한글에서 기준 문단 글을 가려 최종 구현에서 제외했습니다. 최종 방식은 개체를 실제 줄 높이에 포함하며 주변 글과 다음 문단을 보존합니다.

현재 WASM의 페이지 계산·폰트 대체는 한글과 다를 수 있습니다. 이번 60줄 본문에서도 네이티브 두 쪽의 줄 분리를 확인했으나 WASM 진단에는 본문 높이 경고가 남는 경우가 있습니다. 이를 네이티브 넘침이나 손실로 단정하지 않습니다. 기본 가로 기하학 저장 정책과 명시적 쪽 진단은 구분하며 `layout_verified:false`를 유지합니다. 고정 바닥글 회피, 임의 도형 외곽선·미지원 리스트와 모든 문서의 인쇄 배치 인증은 남은 범위입니다.
