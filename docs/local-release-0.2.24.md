# 로컬 HWP Easy 0.2.24 배치·글상자 검증

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [개선·남은 작업](remaining-work.md) · [이전 검증](local-release-0.2.23.md)

2026년 10월 15일의 공통 Node/WASM 소스·분리 패키지 검증이다. 실제 Codex 설치는 **0.2.20**, Claude Code·Cursor 설치와 공개 ZIP은 **0.2.19**를 유지한다. 설치 갱신·공개 게시·포털 제출은 수행하지 않았다.

## 변경 범위

| 작업 | 구현 | 조건과 보존 |
| --- | --- | --- |
| F1 부동 상태 유지 | 선택한 그림·바깥 그룹·지원 글상자의 가까운 빈 위치 탐색 후 재렌더링 | 같은 쪽의 세로 용지·단일 단·절대 크기·위/왼쪽 정렬 본문 개체. 위치 오프셋만 변경하며 부동 플래그·좌표 기준·wrap·여백·크기·이미지·그룹 행렬을 보존 |
| F2 고정 바닥 영역 | 구역의 본문 하단을 줄여 긴 본문·표가 고정 개체 위에서 다음 쪽으로 이어지게 함 | 페이지/용지 기준의 선택 고정 개체 위치는 유지. 단순 텍스트 꼬리말은 첫 문단 앞 간격을 보정해 실제 위치 유지. 기존 문단 정의·꼬리말 글자·글자 서식 보존 |
| F3 배치 진단 | 머리말/꼬리말 글자와 글상자 자체 글자를 구분. 쪽 시작 정보와 렌더링 글자의 소속 불일치 등 표시 | 확실한 관측 문제와 엔진 한계를 분리. 미확정 사례는 `inconclusive`이며 경고가 없다는 이유로 배치를 인증하지 않음 |
| F4 글상자 | 본문의 단순 사각형 글상자 문단 조회·부분 편집, 빈 글상자 입력 | 혼합 서식·한글·비 BMP 문자·문단 안 줄바꿈 지원. 비대상 글자 서식·다른 문단·테두리/채움·도형 구조 보존 |

작업 계약은 [실행기 참조](../plugins/hwp-easy/skills/edit-local-hwp/references/requests.md)의 `reposition_floating_object`, `protect_page_bottom`, `splice_text_box`를 따른다. `read`는 `page_definitions`와 별도 `text_boxes` 대상 목록을 제공한다. 모든 대상은 읽은 파일 해시에 묶이며 묶음 작업은 한 번만 저장한다. 무변경은 저장·복구 사본을 만들지 않는다.

F1은 자동 전체 문서 정리가 아니다. 사용자가 이동을 요청한 개체만 선택한다. 로고·워터마크 같은 의도한 겹침을 자동 판정하거나 옮기지 않는다. 기본 간격은 900 HWP 단위이며 빈 공간·쪽 소속·개체 틀을 확인하지 못하면 저장하지 않는다. 0.2.23의 inline 전환은 별도 동작으로 유지한다.

F2는 해당 구역 전체에 적용되므로 쪽 수가 늘 수 있다. 본문에 놓인 고정 개체에 매쪽 반복 속성을 새로 부여하지 않는다. 문단 기준 개체, 용지 안 제한이 켜진 고정 개체, 제어·그림·필드가 든 꼬리말, 검증하지 못한 용지와 과도한 하단 확보는 거부한다. 글상자 크기 자동 조정·내부 필드·그룹/셀 내부 글상자·임의 하위 그룹 변환은 지원 범위에 포함하지 않는다.

합성 글상자 생성 중 엔진의 신규 text-list 부착 플래그가 한컴에서 거부되는 문제를 발견했다. 한컴 API로 만든 정상 사각형과 비교해 **시험 생성기만** 정상 플래그로 구성했다. 제품은 기존 글상자의 도형 플래그를 바꾸지 않는다. 통과하지 못한 초기 원본을 검증 결과에 포함하지 않았다.

## 엔진 차이와 남은 범위

- 긴 한 문단의 렌더링 글자가 쪽 시작 메타데이터와 다른 쪽에 포함되는 사례를 재현했다. 다른 쪽 소속 글자로 인한 높이 초과를 네이티브 손실로 단정하지 않으며 `PAGINATION_RENDER_MEMBERSHIP_DISAGREEMENT`를 보고한다.
- 명시적 줄바꿈이 많은 문단의 쪽 이어짐을 확정할 수 없으면 `MULTILINE_PARAGRAPH_PAGINATION_UNVERIFIED`를 보고한다.
- 현재 WASM 렌더러는 꼬리말 첫 문단의 앞 간격 보정을 반영하지 않는다. 보정된 꼬리말이 있으면 `FIXED_FOOTER_SPACING_NOT_MODELED`를 보고한다. 네이티브 위치 유지와 WASM 미리보기의 차이를 숨기지 않는다.
- 실제 본문/꼬리말 교차는 계속 보고한다. 진단은 글꼴 대체·정확한 외곽선·의도한 겹침·임의 문서의 인쇄 배치를 인증하지 않으며 `layout_verified:false`를 유지한다.

F1–F4의 이번 대표 프로필은 구현·검증했으나 모든 HWP 구조를 지원한 것은 아니다. 각 후속 범위는 [남은 작업](remaining-work.md)에서 관리한다.

## 재현과 배포

```text
node scripts/package_local_plugin.mjs
node scripts/check-local-placement.mjs
python scripts/check-local-placement.py
```

한컴이 설치된 Windows의 선택적 개발 검사는 `render-local-reflow-native.py <결과 폴더>`, Pillow 환경에서는 `check-local-placement-native.py <결과 폴더>`를 실행한다. 제품 사용자에게 한글·Python·서버 설치를 요구하지 않는다. Windows·Linux CI에 새 검사와 독립 판독을 추가했다. 현재 CI 상태는 아래 실행 기록에서 구분한다.

## 실행·패키지 기록

- 패키지: 25개 파일, ZIP 5,577,182바이트. 새 로컬 marketplace 폴더의 해시·명시적 호출 정책·라이선스 검사 통과. 실제 설치·제출은 수행하지 않음.
- 실행기 SHA-256: `3e4834b153181fd15d95d34ada2edc0225d42738b37e913f26f36a57d222ee4c`.
- ZIP SHA-256: `97f1e82cf713791e0b3d1438b8ac04cc7456e0be6855fb88e40a451145e389d0`.
- Windows·Linux CI: 이번 변경을 푸시한 뒤 결과를 확인한다. 이전 main `c528aea`의 [10개 CI 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/38700816733)은 성공 상태를 재확인했다. 이를 이번 기능의 CI 결과로 대체하지 않는다.
