# 로컬 HWP Easy 0.2.31 검증 기록

[프로젝트 상태](project-status.md) · [지원 기능](supported-features.md) · [남은 작업](remaining-work.md)

2026년 10월 18일. **소스·분리 검증 패키지**의 기록이다. 실제 Codex 설치는 0.2.25, Claude Code·Cursor 설치와 공개 ZIP은 0.2.19를 유지한다. F1 지원 범위를 확장했으며 **전체 F1 완료로 표시하지 않는다**.

## 변경 내용

- **셀 구조:** 후속 행, 여러 평문 문단, 경계를 유일하게 복원하는 가로/세로 병합 셀, 대상 셀의 위/가운데/아래 정렬을 지원한다. 전체 격자의 모든 내부 경계를 알아야 하는 경우와 선택 병합 셀의 네 경계만 증명하면 되는 경우를 구분한다. 앞선 행의 늘어남으로 원점이 달라지는 구조는 거부한다.
- **앵커 이동:** 지원 사각형을 셀↔본문·셀↔셀·다른 구역의 문단으로 옮긴다. 빈 셀·빈 문단에서는 확인된 가상 줄 끝을 실제 텍스트 레코드로 생성한다. 부동 상태·기준 설정·크기·감싸기·내용/서식·표/셀 치수는 유지한다. 선택 하위 구조의 계층 레벨, 호스트 앵커와 서식 위치, 두 오프셋·줄 캐시만 변경한다. 앵커 이동 후 출발·도착 구역의 매핑한 줄 캐시를 모두 정리하고, 상자 내부 캐시는 보존한다. 본문 그림/그룹 이동의 기존 경로도 유지한다.
- **대상 추적:** 텍스트나 구조 해시가 같은 형제를 잘못 선택하지 않도록 원래 레코드로 모든 문단·표·개체·상자 내부 문단을 추적한다. 이동 후의 후속 묶음 편집과 실패 시 전체 무저장도 확인한다.
- **비균등 다단:** 원시 비례 너비/간격과 표시된 단 경계를 대조해 일반 왼쪽→오른쪽 다단의 목적 단을 선택한다. 잘못된 합계·부호·단 방향·경계는 거부한다. 해석은 고정한 [core 파서](https://github.com/edwardkim/rhwp/blob/v0.8.6/src/parser/body_text.rs#L1027)와 실제 한글 배치를 대조했다.
- **장애물·의도한 겹침:** 다른 지원 사각형과 분리된 형제 셀의 확인된 표를 고려한다. 기본값은 겹침 회피다. `overlap_policy:"preserve_existing"`를 명시한 기존 경계 안 배치는 바이트와 백업 수를 바꾸지 않는다. 다른 앵커로 이동하면서 새 겹침을 허용하거나 의도를 자동으로 추측하지 않는다.

공통 Node/WASM 엔진은 하나로 유지한다. 원시 게시 함수는 한 구역뿐 아니라 검증한 여러 구역의 변경을 함께 검사하며, 나머지 스트림·DocInfo·BinData는 정확히 보존한다. 서버나 한글 설치를 제품 실행 조건에 추가하지 않는다.

## 검증 중 발견하고 수정한 문제

`inner answer 😀`가 있는 옆 셀에서 기존 글자 단위 높이 추정은 두 줄을 계산했지만 실제 한글은 단어 경계와 이모지 때문에 세 줄을 사용했다. 처음 후보가 마지막 줄과 겹치는 것을 네이티브 이미지에서 확인했다. 셀 배치가 글자/단어 줄바꿈과 이모지 폭 중 보수적인 높이를 예약하도록 바꿨다. 수정 후 실제 세 번째 줄과 상자가 분리된 것을 픽셀로 확인했다. 폭을 넘는 단어는 새 줄에서 나누어 계산하고, 큰 글꼴이 적용된 빈 문단도 줄 끝의 실제 글자 서식으로 높이를 예약한다. 이 추정도 임의 글꼴의 정확한 조판을 보증하지 않는다.

일반 셀에도 단 기준 오프셋을 셀 내부 폭에 더해 생기는 과도한 넘침 판정이 있었다. 원시/표시 경로를 검증한 경우에는 투영 경계와 글 영역으로 진단하고, 불확실한 프로필의 기존 보호는 유지한다.

## 남은 F1·F3 범위

- **F1:** 가운데/아래 정렬된 조상 셀, 선택 셀 안의 여러 중첩 표·줄이 나뉜/제어가 있는 접두부, 셀 그림/그룹의 자동 재배치, 추가 깊이와 모호한 경로. 구역 간 이동의 모든 HWP 개체를 검증한 것도 아니다. 지원 조건 밖에서는 저장 전에 거부한다.
- **F3:** WASM SVG·썸네일·컨트롤 좌표와 한글의 원점·글꼴·쪽 계산 차이. 중첩 표 뒤 본문으로 옮긴 한 사례에서는 실제 y가 엔진보다 **7px 아래**였으며 실제 목적지의 글/테두리 충돌이 없는 것을 별도로 확인했다. 이 차이를 오차 0 또는 전체 배치 인증으로 기록하지 않는다.

`layout_verified:false`, `native_layout_verified:false`는 유지한다. 지원 셀은 HWP 단·루트 본문 문단 기준 투영과 엔진 표시 불확실성을 반환한다. 폰트/높이는 `font_estimate`이며 엄격 정책은 새 추정 위험도 거부한다. 실제 설치 갱신·새 채팅은 R1에 남긴다.

## 수동 CI

소스 커밋 `f53c030ee3efe9e590f3f7676967f25d47157b70`의 [Windows/Linux CI 10개 작업](https://github.com/spark142857142857/hwp-easy/actions/runs/39120133055)이 **모두 성공**했다. `workflow_dispatch`로 이 기능/저장 변경 단계에서 한 번 실행했다. 자동 push/PR 실행은 계속 비활성이다.

실제 Claude Code·Cursor 설치/계정은 변경하지 않았으며 해당 CI 작업은 공통 소스의 격리된 회귀 검사다. Linux의 엔진/저장·복구 회귀와 Windows에서 별도로 수행한 한글 쪽 이미지 검증은 구분한다. CI 이후 변경은 검증 결과·문서 링크 정리뿐이며 실행기 코드는 같다.
