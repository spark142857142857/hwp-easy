# HWP Easy 공개 플러그인 출시 준비

2026년 10월 10일 사용자가 선택한 목표는 **누구나 ChatGPT·Codex의 디렉터리에서 찾아 설치하는 공개 플러그인**이다. 초대형 배포나 소유자 전용 사이트 업데이트가 완료 조건을 대신하지 않는다. Dots는 계속 제외한다. 전체 플랫폼 백업·재해 복원과 외부 키 보관은 사용자가 후순위로 둔 운영 작업이다.

## 현재 확인한 상태

- 운영 사이트는 버전 51, 사용자 1명만 허용하는 `custom` 접근이다. 기존 소유자 문서와 버전은 공개하지 않았다.
- Sites는 `public` 접근으로 전환할 권한을 제공한다. 이는 URL 접근 대상 설정이며 플러그인 디렉터리 게시와 별도이다.
- 플랫폼이 만든 기존 Sites 플러그인은 비공개 연결이다. 공개 ZIP에는 이 연결의 `.app.json` ID를 재사용하지 않고 실제 HTTPS `/mcp` 주소와 OAuth resource를 선언한다. 기존 연결과 사용자 저장소의 신원·바인딩을 유지한다.
- OpenAI Platform의 현재 조직에서 플러그인 제출 화면까지 로그인했다. 업로드 버튼은 **Complete identity verification**을 표시했다. 검증된 개발자 신원 없이는 업로드할 수 없다. 신원 인증, ZIP 업로드, 심사 신청과 게시는 진행하지 않았다.
- GitHub 저장소는 비공개이다. 그 저장소의 문서·Issues·raw 파일 링크를 공개 홈페이지·지원·심사 첨부 URL로 취급하지 않는다.

공식 공개 경로는 [패키지 준비](https://developers.openai.com/plugins/build/plugins) → [제출 포털의 신원 인증·ZIP 업로드·연결 검사·심사·게시](https://developers.openai.com/plugins/deploy/submission)이다. 공개 패키지의 홈페이지·지원·개인정보·약관 URL은 실제로 접근 가능해야 하며, 게시자 신원과 일치해야 한다. [플러그인 가이드라인](https://developers.openai.com/plugins/plugin-guidelines)의 개인정보와 MCP 요구사항도 따른다.

## 준비한 패키지와 검사

`plugins/hwp-easy/`는 공식 제출 문서가 지원하는 Codex 호환 `.codex-plugin/plugin.json`·`.mcp.json`·SVG 아이콘으로 된 MCP 전용 초안이다. Agent Plugins 1.0.0의 실제 MCP JSON Schema는 OpenAI 문서가 설명하는 서버별 OAuth `extensions`를 추가 속성으로 거부해, 초안을 호환 형식으로 준비했다. 공개 디렉터리는 이 형식도 지원하며 실제 포털 검사는 신원 인증 뒤 수행해야 한다. 개인 스킬·hooks·비공개 등록 App ID·토큰·클라이언트 시크릿·개인 문서를 포함하지 않는다. 실제 `/mcp` URL과 정확한 OAuth resource를 유지하고, 미확인 grant·client ID·scope·token endpoint 인증 방법을 만들지 않는다. 기본 영문 소개와 한국어 번역에는 파일·텍스트 한도, PC 원본과 원격 저장의 차이, 서식·인증 갱신의 제한을 명시했다. `author.name`의 HWP Easy는 프로젝트 초안 표시이며 검증된 법적 게시자 신원이 아니다. 필수 `developerName`과 공개 URL은 확정 전이라 생략했다.

다섯 가지 긍정 시나리오는 기능 조회, 전체 읽기, 무저장 계획, 저장·다운로드, 이전 버전 복구다. 세 가지 부정 시나리오는 다른 사용자 문서 접근, 미지원 형식 변환, 줄바꿈이 든 전체 변경 묶음의 거부다. 이것은 **심사용 시나리오 초안이며 전용 심사 계정으로 실행 완료한 기록이 아니다**. 기존 한 계정의 합성 검증과 혼동하지 않는다. 심사 데이터는 합성 파일만 사용한다.

개발자는 `python scripts/package_public_plugin.py --draft`로 초안 ZIP을 만들 수 있다. 패키징은 정확히 세 파일만 허용하고 시크릿 필드·비공개 App 매핑·headers·hooks·symlink·아이콘 외부 참조를 거부한다. 기본 실행은 필수 제출 메타데이터가 빠져 있으면 거부한다. 구조·ZIP 검사는 포털 스키마 검증이나 공개 연결 인증을 대신하지 않는다. 이 명령을 일반 사용자의 설치 방식으로 안내하지 않는다.

이번 준비에서 패키지 누출 방지 Python 8개, Node 529개와 전체 Worker 회귀 검사가 통과했다. 실제 로컬 compiled workerd에서 익명·부분 신원·과도한 길이·서비스 접근 헤더만 있는 진단을 401로 거부했고, 익명 저장 진단 후 D1/R2가 비어 있음을 확인했다. 정상 합성 신원으로 기존 엔진·저장 진단과 문서 회귀 검사는 계속 통과했다. 이 결과는 모의 헤더를 쓴 로컬 검사이며 실제 OAuth 두 계정이나 운영 배포를 인증하지 않는다. 운영 버전 51·환경 revision 8과 비공개 접근은 유지했다.

## 공개 전에 완료할 항목

| 항목 | 현재 상태 / 완료 근거 |
| --- | --- |
| 검증된 게시자 신원과 표시 이름 | 사용자 신원 인증 필요. 법적 이름·연락처를 임의 작성하거나 계정 화면의 이름을 공개 사용 승인으로 해석하지 않는다. |
| 공개 홈페이지·지원·개인정보·약관 | 안내 초안을 먼저 검토하고 지원 연락처·게시 주체를 결정한 뒤 접근 가능한 실제 URL로 게시한다. 현재 패키지에는 가짜 URL을 넣지 않았다. |
| 익명 진단 실행 제한 | 개발 소스에서 `/`, `/runtime-probe`, `/storage-probe`와 모든 MCP 실행에 완전한 trusted Sites 사용자 신원을 요구하도록 보완했고 위 로컬 검사를 통과했다. 운영 반영과 공개 audience에서의 실제 익명 검사 전에는 출시 완료로 표시하지 않는다. |
| 일반 사용자 설치·인증·권한 철회 | 같은 플랫폼이 공급하는 OAuth를 유지한다. 실제 다른 사용자 계정으로 설치부터 파일 회수까지 검사하고 권한 철회 후 접근을 확인한다. 헤더 모의 검사는 별도다. |
| 실제 두 사용자 격리 | 서로의 문서 ID·버전·다운로드·복구·삭제 접근을 거부하고 본인 문서는 동작해야 한다. 두 실제 OAuth 계정으로 검증한 증거가 필요하다. |
| 심사 자료 | 전용 계정의 합성 데이터로 5+3 시나리오를 실행하고 접근 가능한 녹화 URL을 준비한다. 심사 계정 자격은 공개 ZIP과 Git에 넣지 않고 포털의 별도 보호된 입력에만 제공한다. |
| MCP 연결·도메인 소유 확인 | 포털이 실제 제시한 challenge와 OAuth 등록 방법을 확인한다. 토큰을 추정하거나 기존 연결의 등록 방식을 변경하지 않는다. |
| 인증 자동 갱신 | 지원건 16484855 조사 중. 현재 기능 조회 성공이나 1회 대기 성공으로 영구 해결을 선언하지 않는다. 공개 출시의 신뢰성 검토에 포함한다. |
| 심사와 게시 | 필수 검사와 정책 확인 뒤 신청하고, 승인된 버전을 게시하여 실제 다른 계정의 검색·설치까지 확인한다. |

공개 audience 변경은 위 보호·인증·자료를 준비한 뒤 수행한다. 현재 소유자의 개인 HWP를 공개 예제나 심사 데이터로 쓰지 않는다. 사이트의 공개 전환, 플러그인 심사 승인, 디렉터리 게시, 실제 설치 성공을 각각 기록한다.
